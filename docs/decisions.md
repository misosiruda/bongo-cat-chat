# 결정 기록

기준일: 2026-10-13. 사용자와 합의한 결정, 관찰한 사실, 구현 제안을 구분한다. 아래 결정을 바꾸려면 바뀐 요구사항과 검증 근거를 기록한다.

## D-001. 기존 게임 채팅과 양방향으로 연동한다

**상태: 확정.**

사용자는 별도 채팅망보다 기존 Bongo Cat 채팅과의 양방향 연동이 핵심이라고 답했다. 프로그램을 설치하지 않은 상대의 채팅도 읽고, 프로그램에서 보낸 문장도 상대의 원래 게임에 보여야 한다.

별도 서버에 가입한 사용자끼리만 대화하는 제품으로 바꾸지 않는다. 기존 로비 송수신 경로는 기술 검증을 수행했으며, 제품 UI를 통한 전체 흐름 검증은 남아 있다.

## D-002. 게임 내 자기 말풍선 연동을 제외한다

**상태: 확정. 이전 시험 계획 취소.**

외부 송신은 다른 이용자에게 보이지만 송신자의 게임 안에서는 자기 말풍선이 나타나지 않았다. 분석 결과 게임의 송신 처리와 자기 말풍선 표시가 별도 단계였다.

게임 파일을 수정해 표시 전용 모듈을 연결하는 시험을 준비했으나, 사용자는 메신저 형태의 별도 UI에서만 자신의 메시지가 보이면 충분하다고 결정했다. 따라서 실제 설치·재시작 전에 시험을 취소했다.

영향:

- 메신저 UI가 자기 메시지를 즉시 표시한다.
- 같은 메시지를 다시 송신해 게임 말풍선을 만들려고 하지 않는다.
- 게임 DLL 패치, 프로세스 주입, 게임 내 연결 모듈을 제품에 포함하지 않는다.
- 준비했던 말풍선 모듈은 적용하지 않은 연구 기록으로만 로컬 보관한다.
- Auto Chest Opener의 게임 변경 방식은 이 프로젝트의 구현 방식으로 승계하지 않는다.

## D-003. 별도 프로세스의 Steam 연결을 출발점으로 삼는다

**상태: PoC 경로 채택. 제품 호환성 검증 필요.**

현재 계정과 기존 게임 로비에 대해 별도 Python 프로세스가 수신·송신하는 것을 확인했다. 게임 내부에 코드를 넣지 않는 전송 계층을 먼저 구현한다.

다만 한 PC의 기존 패치 환경에서 확인한 결과다. 순정 설치·다른 PC·실행 순서·장시간 연결 결과가 달라지면 이 결정을 재검토한다. API 호출이 성공했다는 이유로 배포 권한까지 확보한 것으로 해석하지 않는다.

## D-004. 관찰한 게임 포맷과 UTF-8을 유지한다

**상태: 실제 바이트 비교로 확인.**

게임에서 직접 보낸 한글 문장의 UTF-8 JSON 52바이트가 PoC 생성 결과와 일치했다. 인코딩 변경이나 추가 변환을 적용하지 않는다. 확인된 예제의 채널은 `3`, 본문 필드는 `Message`다.

초기 “외계어” 보고의 정확한 원인은 확인하지 못했고, 이후 사용자는 상대방에게 채팅이 잘 전달된다고 확인했다. 원인 미확정 보고를 인코딩 결함 수정 실적으로 기록하지 않는다.

## D-005. 앱이 실제 수신한 대화를 로컬에 보관한다

**상태: 제품 방향 확정. 저장 구현과 세부 정책 미정.**

지나간 대화를 다시 보는 것이 핵심 가치다. 수신한 대화를 앱의 로컬 저장소에 보관하고 조회·검색한다.

앱 실행 전·오프라인 중 대화를 Steam에서 완전히 복원한다고 가정하지 않는다. 여러 기기 동기화와 서버 저장은 확정 범위에 포함하지 않는다. 보관 기간과 삭제·내보내기 정책은 구현 전에 결정한다.

## D-006. 상대방 설치를 요구하지 않는다

**상태: 확정.**

상대방은 기존 게임만 사용해도 된다. 프로그램 고유의 메시지 ID나 상태 정보를 채팅 본문에 붙이지 않는다. 따라서 제품의 전송 확인은 상대방 읽음 확인과 구분해야 한다.

## D-007. 일반 텍스트를 먼저 지원한다

**상태: 첫 제품 기준.**

한글 일반 텍스트로 기존 로비 송신을 확인했다. 이모지 데이터의 자체 왕복 시험은 통과했지만 게임의 글꼴·화면 지원은 검증하지 않았다. 첨부파일, 음성, 이모티콘 호환은 첫 제품 완료 조건에 넣지 않는다.

## D-008. 무료 배포를 목표로 하고 개발자에게 안내한다

**상태: 사용자 의도 확정. 외부 안내·배포 실행 전.**

불특정 이용자에게 무료로 배포하는 것이 목표다. 개발자에게도 기능과 동작 방식을 설명하려는 의도가 있다.

안내 메시지는 아직 보내지 않았으며 승인·협력 관계도 확인되지 않았다. 공개 배포, 소스 공개, 라이선스 선택, 개발자 연락은 서로 다른 결정으로 관리한다. 검증 완료 전에 “공식 허용”, “모든 계정에서 안전”, “무조건 배포 가능”으로 표현하지 않는다.

## D-009. 문서와 로컬 원본 자료를 함께 보관한다

**상태: 반영.**

사용자가 기본 프로젝트 폴더를 변경했고 `bongo-cat-chat` 이름의 저장소를 만들어 문서부터 시작하도록 요청했다.

- 저장소에는 요구사항·검증 결과·설계·결정·개발 계획과 식별정보 없는 증거 요약을 둔다.
- 원본 로그와 PoC 소스 20개는 로컬 `research/private/2026-10-12/`에 복사하고 해시를 비교했다.
- 기존 작업 폴더는 보존한다.
- 로컬 원본 자료, 게임·Steam 바이너리와 분석 도구 DLL은 Git에 포함하지 않는다.
- 초기 저장소는 비공개로 시작한다. 공개 전에는 자료와 라이선스를 다시 검토한다.

## D-010. 접을 수 있는 사이드바와 게임 프로필을 사용한다

**상태: 2026-10-13 사용자 요구사항 반영. 이름·외형 조회 후보 검증, 제품 구현·화면 대조 전.**

사용자는 와이어프레임을 보고 왼쪽 사이드바의 접힘 기능, Bongo Cat에 표기되는 이름과 같은 이름, 게임에 나오는 고양이와 동기화된 프로필을 요청했다.

- 사이드바를 접거나 펼쳐도 선택한 방과 작성 중인 문장을 유지한다. 아이콘만 남기는 접힘 형태는 현재 시안의 제안이다.
- 다른 사용자와 내 계정 모두 게임 표시 이름을 사용한다. 계정 식별자로 사용자를 연결하고 이름은 표시 정보로 취급한다.
- 게임 속 고양이를 프로필로 쓰는 방향을 채택한다. Steam 프로필 사진을 가져오는 것만으로 이 요구사항을 충족하지 않는다.
- 이름 원천, 고양이 외형·장식 데이터, 이미지 표시 방법, 변경 감지를 게임 파일 무수정 조건으로 검증한다. 경로를 확보하지 못하면 미지원 범위와 대안을 별도로 결정한다.
- 와이어프레임은 가상 이름과 고양이 아이콘으로 구성했다. 게임 연결·프로필 동기화 완료로 기록하지 않는다.

후속 실험에서 게임의 친구 별명 우선 규칙, 로비 13명의 이름·모자·스킨 조회, 64개 대응 스프라이트와 정지 이미지 생성 경로를 확인했다. [실제 검증 범위](profile-sync-validation.md)는 시안·제품 구현과 구분한다.

## D-011. 사용자 숨김은 Bongo Cat의 설정만 따른다

**상태: 2026-10-13 사용자 정정으로 확정. 읽기 전용 메모리로 실제 숨김·해제 감지 확인·제품 미구현.**

사용자는 숨김이 채팅 앱에서 조작할 기능이 아니라 Bongo Cat 자체 기능이며, 게임에서 숨긴 사용자는 앱에서도 숨겨져야 한다고 명확히 했다.

- 숨김·해제 조작은 게임에서 한다. 앱은 게임 상태를 읽어 반영한다.
- 앱 자체 숨김 버튼·토글·독립 수동 목록은 제공하지 않는다. 앞선 와이어프레임의 수동 숨김 제안과 대안 후보는 철회한다.
- 숨긴 사용자의 메시지는 기존 기록을 포함해 대화·검색·미리보기에서 감추고 알림·읽지 않은 수에서도 제외한다. 영구 삭제와 숨김 중 저장 정책은 별도 결정한다.
- 상태를 읽는 경로를 찾지 못하면 필수 요구사항 미충족으로 기록한다. 앱 자체 숨김을 대체안으로 구현하거나 동기화 완료로 보고하지 않는다.
- 게임 파일 무수정 원칙은 유지한다. 수정된 시안의 필터링은 예시 데이터로만 동작하며 실제 게임 연동을 입증하지 않는다.

후속 실험은 게임의 실제 정적 캐시를 외부에서 읽었으며 파일 수정·프로세스 주입·메모리 쓰기를 하지 않았다. 같은 이용자의 숨김·해제 전환을 사용자의 실제 조작과 대조했다. 이 후보의 제품 채택과 재시작·업데이트 호환성, 앱 전체 필터 적용은 아직 결정·검증 전이다. 게임 내부 구조에 의존하는 후보를 공식 조회 API로 소개하지 않는다.

## D-012. 차분한 메신저 디자인과 라이트·다크 테마를 제공한다

**상태: 2026-10-13 사용자 방향 선택·테마 요구사항 반영. 제품 구현 전.**

사용자는 초기 와이어프레임보다 세련된 디자인을 요청하고, 차분한 데스크톱 메신저 방향과 라이트·다크 호환을 선택했다.

- 대화 중심의 두 열 배치, 절제된 보라색 강조, 접을 수 있는 사이드바를 사용한다. 작은 창에서는 사이드바를 서랍으로 전환한다.
- 라이트·다크·시스템 선택을 제공한다. 기본값은 시스템이며 직접 선택한 테마는 기억한다.
- 테마 변경은 대화·검색·작성 중인 문장·스크롤을 초기화하지 않는다. 고양이 이미지 색을 반전시키지 않는다.
- [새 디자인 시안](design/README.md)은 가상 이름·대화와 별도 생성한 고양이 그림을 사용한다. 화면은 실제 게임이나 전송 경로에 연결하지 않는다.
- 고양이 그림은 프로필 자리와 테마 대비를 검토하기 위한 예시다. 실제 제품의 게임 외형 동기화 요구사항은 유지한다.
- 정적 HTML·CSS·JavaScript 미리보기를 만든 것으로 제품 프레임워크나 런타임을 확정하지 않는다.

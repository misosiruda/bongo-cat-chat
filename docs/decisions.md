# 결정 기록

## 2026-10-16: 두 PC 공통 배포 요청과 독립 서명 환경

사용자 승인으로 개발 PC에서 실행하는 앱 코드·테스트와 운영 업데이트 키의 사용 환경을 분리한다. 별도 `misosiruda/bongo-cat-chat-release` 저장소에서 키 없는 빌드와 승인 후 독립 서명을 수행하고, 앱 저장소는 승인 기록·서명·출처·파일 해시를 재검증해 기존 Release 위치에 게시한다. 두 PC 어디서든 GitHub UI 또는 요청 스크립트를 사용한다.

기존 Ed25519 키·공개키·manifest와 ZIP 규약은 유지한다. 공개 dev11 manifest의 기존 서명을 재현하여 키 연속성을 검사하며 새 제품 릴리스 게시와 구분한다. 로컬 키 사본 회수는 클라우드 검증과 독립 복구 백업 확인 후 진행한다. 수동 승인과 서명은 코드의 악성 여부, 다른 PC 인수 또는 Windows Authenticode 신뢰를 보증하지 않는다. [두 PC 배포 절차](release-workstations.md)를 따른다.

기준일: 2026-10-13. 사용자와 합의한 결정, 관찰한 사실, 구현 제안을 구분한다. 아래 결정을 바꾸려면 바뀐 요구사항과 검증 근거를 기록한다.

## D-001. 기존 게임 채팅과 양방향으로 연동한다

**상태: 확정.**

사용자는 별도 채팅망보다 기존 Bongo Cat 채팅과의 양방향 연동이 핵심이라고 답했다. 프로그램을 설치하지 않은 상대의 채팅도 읽고, 프로그램에서 보낸 문장도 상대의 원래 게임에 보여야 한다.

별도 서버에 가입한 사용자끼리만 대화하는 제품으로 바꾸지 않는다. 기존 로비 송수신 경로는 기술 검증을 수행했으며, 제품 UI를 통한 전체 흐름 검증은 남아 있다.

## D-002. 게임 내 자기 말풍선 연동을 제외한다

**상태: 확정. 이전 시험 계획 취소.**

외부 송신은 다른 이용자에게 보이지만 송신자의 게임 안에서는 자기 말풍선이 나타나지 않았다. 분석 결과 게임의 송신 처리와 자기 말풍선 표시가 별도 단계였다.

게임 파일을 수정해 표시 전용 모듈을 연결하는 시험을 준비했으나, 사용자는 메신저 형태의 별도 UI에서만 자신의 메시지가 보이면 충분하다고 결정했다. 따라서 실제 설치·재시작 전에 시험을 취소했다.

영향:

- 메신저 UI가 자기 메시지를 즉시 표시한다.
- 같은 메시지를 다시 송신해 게임 말풍선을 만들려고 하지 않는다.
- 게임 DLL 패치, 프로세스 주입, 게임 내 연결 모듈을 제품에 포함하지 않는다.
- 준비했던 말풍선 모듈은 적용하지 않은 연구 기록으로만 로컬 보관한다.
- Auto Chest Opener의 게임 변경 방식은 이 프로젝트의 구현 방식으로 승계하지 않는다.

## D-003. 별도 프로세스의 Steam 연결을 출발점으로 삼는다

**상태: PoC 경로 채택. 제품 호환성 검증 필요.**

현재 계정과 기존 게임 로비에 대해 별도 Python 프로세스가 수신·송신하는 것을 확인했다. 게임 내부에 코드를 넣지 않는 전송 계층을 먼저 구현한다.

다만 한 PC의 기존 패치 환경에서 확인한 결과다. 순정 설치·다른 PC·실행 순서·장시간 연결 결과가 달라지면 이 결정을 재검토한다. API 호출이 성공했다는 이유로 배포 권한까지 확보한 것으로 해석하지 않는다.

## D-004. 관찰한 게임 포맷과 UTF-8을 유지한다

**상태: 실제 바이트 비교로 확인.**

게임에서 직접 보낸 한글 문장의 UTF-8 JSON 52바이트가 PoC 생성 결과와 일치했다. 인코딩 변경이나 추가 변환을 적용하지 않는다. 확인된 예제의 채널은 `3`, 본문 필드는 `Message`다.

초기 “외계어” 보고의 정확한 원인은 확인하지 못했고, 이후 사용자는 상대방에게 채팅이 잘 전달된다고 확인했다. 원인 미확정 보고를 인코딩 결함 수정 실적으로 기록하지 않는다.

## D-005. 앱이 실제 수신한 대화를 로컬에 보관한다

**상태: 제품 방향 확정. 개발판 SQLite 구현, 보관·삭제 정책은 D-013으로 확정.**

지나간 대화를 다시 보는 것이 핵심 가치다. 수신한 대화를 앱의 로컬 저장소에 보관하고 조회·검색한다.

앱 실행 전·오프라인 중 대화를 Steam에서 완전히 복원한다고 가정하지 않는다. 여러 기기 동기화와 서버 저장은 확정 범위에 포함하지 않는다. 30일 보관·직접 삭제를 제공하며 내보내기는 후속 범위다.

## D-006. 상대방 설치를 요구하지 않는다

**상태: 확정.**

상대방은 기존 게임만 사용해도 된다. 프로그램 고유의 메시지 ID나 상태 정보를 채팅 본문에 붙이지 않는다. 따라서 제품의 전송 확인은 상대방 읽음 확인과 구분해야 한다.

## D-007. 일반 텍스트를 먼저 지원한다

**상태: 첫 제품 기준.**

한글 일반 텍스트로 기존 로비 송신을 확인했다. 이모지 데이터의 자체 왕복 시험은 통과했지만 게임의 글꼴·화면 지원은 검증하지 않았다. 첨부파일, 음성, 이모티콘 호환은 첫 제품 완료 조건에 넣지 않는다.

## D-008. 무료 배포를 목표로 하고 개발자에게 안내한다

**상태: 사용자 의도 확정. 외부 안내·배포 실행 전.**

불특정 이용자에게 무료로 배포하는 것이 목표다. 개발자에게도 기능과 동작 방식을 설명하려는 의도가 있다.

안내 메시지는 아직 보내지 않았으며 승인·협력 관계도 확인되지 않았다. 공개 배포, 소스 공개, 라이선스 선택, 개발자 연락은 서로 다른 결정으로 관리한다. 검증 완료 전에 “공식 허용”, “모든 계정에서 안전”, “무조건 배포 가능”으로 표현하지 않는다.

## D-009. 문서와 로컬 원본 자료를 함께 보관한다

**상태: 반영.**

사용자가 기본 프로젝트 폴더를 변경했고 `bongo-cat-chat` 이름의 저장소를 만들어 문서부터 시작하도록 요청했다.

- 저장소에는 요구사항·검증 결과·설계·결정·개발 계획과 식별정보 없는 증거 요약을 둔다.
- 원본 로그와 PoC 소스 20개는 로컬 `research/private/2026-10-12/`에 복사하고 해시를 비교했다.
- 기존 작업 폴더는 보존한다.
- 로컬 원본 자료, 게임·Steam 바이너리와 분석 도구 DLL은 Git에 포함하지 않는다.
- 초기 저장소는 비공개로 시작한다. 공개 전에는 자료와 라이선스를 다시 검토한다.

## D-010. 접을 수 있는 사이드바와 게임 프로필을 사용한다

**상태: 2026-10-13 사용자 요구사항 반영. 개발판 이름·외형 연결, 실제 게임 화면 대조 전.**

사용자는 와이어프레임을 보고 왼쪽 사이드바의 접힘 기능, Bongo Cat에 표기되는 이름과 같은 이름, 게임에 나오는 고양이와 동기화된 프로필을 요청했다.

- 사이드바를 접거나 펼쳐도 선택한 방과 작성 중인 문장을 유지한다. 아이콘만 남기는 접힘 형태는 현재 시안의 제안이다.
- 다른 사용자와 내 계정 모두 게임 표시 이름을 사용한다. 계정 식별자로 사용자를 연결하고 이름은 표시 정보로 취급한다.
- 게임 속 고양이를 프로필로 쓰는 방향을 채택한다. Steam 프로필 사진을 가져오는 것만으로 이 요구사항을 충족하지 않는다.
- 이름 원천, 고양이 외형·장식 데이터, 이미지 표시 방법, 변경 감지를 게임 파일 무수정 조건으로 검증한다. 경로를 확보하지 못하면 미지원 범위와 대안을 별도로 결정한다.
- 와이어프레임은 가상 이름과 고양이 아이콘으로 구성했다. 게임 연결·프로필 동기화 완료로 기록하지 않는다.

후속 실험에서 게임의 친구 별명 우선 규칙, 로비 13명의 이름·모자·스킨 조회, 64개 대응 스프라이트와 정지 이미지 생성 경로를 확인했다. [실제 검증 범위](profile-sync-validation.md)는 시안·제품 구현과 구분한다.

## D-011. 사용자 숨김은 Bongo Cat의 설정만 따른다

**상태: 2026-10-13 사용자 정정으로 확정. 개발판 실험 어댑터 연결과 필터 구현, 배포 호환성은 미검증.**

사용자는 숨김이 채팅 앱에서 조작할 기능이 아니라 Bongo Cat 자체 기능이며, 게임에서 숨긴 사용자는 앱에서도 숨겨져야 한다고 명확히 했다.

- 숨김·해제 조작은 게임에서 한다. 앱은 게임 상태를 읽어 반영한다.
- 앱 자체 숨김 버튼·토글·독립 수동 목록은 제공하지 않는다. 앞선 와이어프레임의 수동 숨김 제안과 대안 후보는 철회한다.
- 숨긴 사용자의 메시지는 기존 기록을 포함해 대화·검색·미리보기에서 감추고 알림·읽지 않은 수에서도 제외한다. 영구 삭제와 숨김 중 저장 정책은 별도 결정한다.
- 상태를 읽는 경로를 찾지 못하면 필수 요구사항 미충족으로 기록한다. 앱 자체 숨김을 대체안으로 구현하거나 동기화 완료로 보고하지 않는다.
- 게임 파일 무수정 원칙은 유지한다. 수정된 시안의 필터링은 예시 데이터로만 동작하며 실제 게임 연동을 입증하지 않는다.

후속 실험은 게임의 실제 정적 캐시를 외부에서 읽었으며 파일 수정·프로세스 주입·메모리 쓰기를 하지 않았다. 같은 이용자의 숨김·해제 전환을 사용자의 실제 조작과 대조했다. D-014에서 개발판 실험 연결을 승인했다. 앱 전체 필터는 오프라인 검사했고 게임 재시작·업데이트와 실제 조작 인수는 남았다. 게임 내부 구조에 의존하는 후보를 공식 조회 API로 소개하지 않는다.

## D-012. 차분한 메신저 디자인과 라이트·다크 테마를 제공한다

**상태: 2026-10-13 사용자 방향 선택·테마 요구사항 반영. 실제 Qt 개발판에 구현.**

사용자는 초기 와이어프레임보다 세련된 디자인을 요청하고, 차분한 데스크톱 메신저 방향과 라이트·다크 호환을 선택했다.

- 대화 중심의 두 열 배치, 절제된 보라색 강조, 접을 수 있는 사이드바를 사용한다. 작은 창에서는 사이드바를 서랍으로 전환한다.
- 라이트·다크·시스템 선택을 제공한다. 기본값은 시스템이며 직접 선택한 테마는 기억한다.
- 테마 변경은 대화·검색·작성 중인 문장·스크롤을 초기화하지 않는다. 고양이 이미지 색을 반전시키지 않는다.
- [새 디자인 시안](design/README.md)은 가상 이름·대화와 별도 생성한 고양이 그림을 사용한다. 화면은 실제 게임이나 전송 경로에 연결하지 않는다.
- 고양이 그림은 프로필 자리와 테마 대비를 검토하기 위한 예시다. 실제 제품의 게임 외형 동기화 요구사항은 유지한다.
- 정적 HTML·CSS·JavaScript 미리보기를 만든 것으로 제품 프레임워크나 런타임을 확정하지 않는다.

## D-013. 30일 보관·직접 삭제, 숨김 중 새 메시지 미저장

**상태: 2026-10-13 사용자 답변으로 확정·개발판 구현.**

- 받은 대화와 초안을 로컬에서 30일 보관한다. 실행 시·실행 중 정리하고 조회에서도 만료 데이터를 제외한다.
- 선택한 로비 또는 현재 계정의 기록을 직접 삭제한다. 내보내기는 후속 작업이다.
- 게임에서 숨긴 동안의 새 상대 메시지는 저장하지 않는다. 이미 저장된 기록은 화면·검색에서 감추고 게임에서 해제하면 다시 조회할 수 있다.
- 숨김 상태 미확인·조회 실패·오래된 표본에서는 상대 대화 노출과 새 저장을 보류한다. 숨김 실패를 아무도 숨기지 않은 상태로 바꾸지 않는다.
- 평문 SQLite로 개발하되 일반 배포 전 암호화·백업 정책은 남긴다. 직접 삭제는 디스크 물리 복구 불가능성을 보장하지 않는다.

## D-014. 숨김 조회는 개발판의 실험 기능으로 연결

**상태: 2026-10-13 사용자 승인. 일반 배포 채택과 분리.**

읽기 전용 게임 메모리 어댑터를 연결한다. 확인된 기능 계약·네이티브 ABI·메타데이터·관리 도메인·PID 생성 시각이 맞지 않으면 상대 대화와 송신을 차단한다. 숨김 사전 조회 실패와 송신 조건의 분리는 D-021을 따른다. 매 게임 프로세스 수명마다 주소를 새로 찾으며 이전 주소를 저장하거나 재사용하지 않는다. 기존 패치 PC에서 구현했다. 2026-10-14 새 빌드의 조회는 추가 확인했으며, 순정 환경·다른 PC·반복 재시작과 새 빌드의 실제 숨김 조작 인수는 남아 있다.

## D-015. 개발판 런타임과 저장소 선택

**상태: 구현 선택. 검증 결과에 따라 재검토 가능.**

## D-016. GitHub Release 자동 다운로드·다음 실행 적용

**상태: 2026-10-13 사용자 답변으로 확정·구현. 2026-10-15 D-023에서 자동 재시작으로 확장.**

새 정식 릴리스를 자동 다운로드하고 다음 앱 실행에 적용한다. 사용 중인 채팅을 강제로 종료하지 않는다. 현재 GitHub 저장소를 공개하는 배포 방향을 선택했고 2026-10-14 실제 공개 전환을 완료했다. 첫 릴리스 게시·소스 라이선스와 일반 배포 조건은 별도 단계다.

고정 공개키의 Ed25519 서명과 ZIP 해시를 검사하고 별도 버전 폴더의 오프라인 화면 검사 후 활성 포인터를 변경한다. 실패 때 기존 선택을 유지하고 시작 직후 실패는 이전 버전으로 되돌린다. 대화 데이터는 설치 폴더 밖에 보존한다. 규약은 [자동 업데이트](automatic-updates.md), 증거는 [검증 기록](update-validation.md)에 둔다.

## D-017. 일반 이용자는 한국어 Windows 설치 파일을 사용

**상태: 2026-10-14 사용자 요구에 따라 구현.**

명령어와 개발 도구 설치를 요구하지 않는 단일 `Setup.exe`를 만든다. NSIS 3.13의 한국어 Modern UI와 현재 사용자 설치를 선택했다. 기존 PyInstaller 묶음·업데이트 실행기를 그대로 포함하면서 기본 Windows 제거 목록과 시작 메뉴를 제공하고, 별도 런타임 다운로드나 관리자 권한이 필요하지 않다. 내부 복사·복구 엔진은 Windows 기본 PowerShell을 숨겨 실행한다. 사용자가 스크립트를 입력할 필요는 없다.

설치 시 실행 잠금을 공유하고 새 파일 준비 후 마지막에 활성 버전을 바꾼다. 같은 버전 재설치와 dev1 이전 구조 전환을 지원하며 이전보다 낮은 버전은 거부한다. 교체 실패 때 기존 파일을 복구한다. 제거는 알려진 앱 구성원만 삭제하고 기록·설정과 설치 폴더의 별도 파일을 보존한다. Windows 코드 서명·다른 PC 호환성·첫 공개 릴리스는 별도 검증 및 배포 단계다.

## D-018. 게임 변경을 감지하면 대응 앱 업데이트를 확인

**상태: 2026-10-14 사용자 요청에 따라 개발판 구현.**

미지원 게임 파일 조합이 감지되면 앱 업데이트를 즉시 확인하고, 서명된 정식 Release가 있으면 자동 다운로드해 다음 실행에 적용한다. 같은 오류의 연결 재시도는 중복 다운로드 요청으로 이어지지 않는다. 지원 조합은 검수한 앱에 포함하며, 공개 빌드 번호만으로 지원을 허용하거나 게임을 자동 패치하지 않는다.

기존 패치 환경과 업데이트 후 사용자가 패치를 재적용한 환경의 파일 조합을 각각 보관한다. 후자의 정적 분석·실제 읽기 검사와 남은 인수는 [게임 업데이트 대응](game-update-compatibility.md)에 기록한다. 이 결정을 순정 환경 검증이나 미래의 모든 게임 업데이트 지원 약속으로 확대하지 않는다.

## D-019. 게임의 관련 기능이 유지되는 업데이트는 자동으로 허용

**상태: 2026-10-14 사용자 정정에 따라 dev6 구현.**

게임 업데이트마다 전체 DLL 해시를 등록하는 방식은 무관한 변경도 차단한다. Auto Chest Opener는 설치 조건이 아니며, 사용자가 게임을 재패치하는 절차를 요구하지 않는다. D-018의 관리 DLL 전체 해시 허용 목록을 기능 계약으로 대체한다.

채팅 채널·JSON 송수신, 숨김 캐시·조회 의미, 현재 로비 필드·기록 경로, 이름·스킨/모자 키의 관련 코드와 참조하는 내부 함수·필드를 비교한다. 메타데이터 토큰·주소·MVID·파일 해시는 판정에서 제외하며, 다중 채널 수신 함수는 채팅 채널의 분기와 도달 코드만 확인한다. 검사기는 게임 DLL을 실행하거나 변경하지 않는다. 현재 낮은 수준의 Mono 구조·Steam 호출 ABI는 확인된 네이티브 파일로 계속 제한한다. 이는 임의의 미래 엔진까지 호환된다고 추정하지 않기 위한 범위다.

관련 코드가 달라지거나 해석할 수 없으면 상대 대화·저장·송신을 보류하고 대응 앱 업데이트를 확인한다. 대응 릴리스는 자동 다운로드·다음 실행 적용 정책을 따른다. 실행 중 파일 변경도 재검사하며 기존 프로세스 주소·검사 결과를 새 연결에 재사용하지 않는다. 검사 통과를 실제 송수신·순정 설치 인수와 동일시하지 않는다.

## D-021. 로비 연결과 숨김 동기화를 분리한다

**상태: 2026-10-14 사용자 승인·소스 구현. 설치본 배포와 구분.**

아래 최초 설계의 Steam 친구 게임 정보와 로비를 대조하는 조건은 2026-10-15 D-024에서 변경했다. 초기 방 표시와 숨김 동기화를 분리하는 정책은 유지한다.

최초 연결 지연 분석 후 사용자가 Steam 연결·로비 표시를 먼저 진행하고 숨김 확인을 뒤따르게 하는 변경을 승인했다.

- 호환성 검사 후 Steam을 먼저 초기화한다. Steam이 보고하는 게임·로비·자기 참여를 확인하면 방과 초안 입력을 먼저 제공한다. 이 단계는 실제 게임 로비 검증 완료나 송신 허용을 뜻하지 않는다.
- 게임 메모리 주소 탐색은 작업자 안의 별도 스레드에서 수행한다. 탐색 중에도 상태 갱신과 콜백 비우기를 계속한다. 미확인 메시지를 나중에 표시하려고 본문이나 콜백 번호를 보관하지 않는다.
- 게임의 현재 로비를 독립적으로 다시 읽어 Steam의 보고와 대조한 뒤 송신을 허용한다. 공통 Mono 메타데이터·관리 도메인 검증은 유지하며 숨김 목록의 조회 완료는 송신 선행 조건에서 제외한다.
- 숨김 사전을 읽은 경우 확인된 비숨김 사용자만 대화·검색·프로필·신규 저장에 허용한다. 누락된 사용자는 계속 감춘다. 사전 조회 실패 시 모든 상대를 감추지만 검증된 로비 연결과 내 메시지 처리는 유지한다.
- 연결 상태가 2.5초 이상 갱신되지 않으면 송신과 신규 수신 처리를 모두 보류한다. 계정·프로세스·로비가 달라지면 이전 요청을 폐기한다. 숨김 동기화 완료만으로 연결 구간이나 초안을 바꾸지 않는다.
- 탐색 실패는 Steam을 유지한 채 15초 후 재시도한다. 게임 종료·파일 변경·지원 조건 실패는 기존처럼 전체 연결을 보류한다. 주소를 디스크에 저장하거나 다음 프로세스에서 재사용하지 않는다.
- 대용량 패턴 검색은 앱에 포함한 `MemoryScan.exe`에서 수행한다. 입력·결과는 로컬 비공개 파이프만 사용하고 읽기 권한·탐색 예산·정렬·후보 중복 제한을 유지한다. 게임 메타데이터·루트·숨김 값 검증은 Python 어댑터가 계속 담당한다.

후속 측정에서 33초의 실제 채팅 준비 지연도 확인했다. 이를 줄이기 위해 해시로 제한된 Mono의 로드된 어셈블리 목록 → 타입 캐시 → 도메인별 vtable 경로를 우선 사용한다. 전체 메모리 검색을 생략해도 동일한 필드·정적 루트·도메인·게임 로비 대조를 통과해야 한다. 목록의 크기·순환·중복·읽기 전후 변경을 검사하고, 읽는 함수 코드는 실행하지 않는다. 로드된 접근자 코드가 지원 구조와 다르면 연결을 보류한다. 초기화 중인 목록 등으로 직접 조회가 실패하면 기존 제한된 검색을 사용하므로 모든 상태에서 1초를 보장하지 않는다. 고양이 이미지 준비는 검증 완료 상태를 보낸 뒤 시작한다. [직접 조회 측정](product-validation.md#2026-10-14-mono-타입-목록-직접-조회로-초기화-단축)은 앞선 33초 결과와 구분한다.

## D-022. 고양이 클릭 울음을 대화에서 제외한다

## 2026-10-14: SignPath 후보의 고지와 업데이트 통신 선택

MIT 결정을 유지하고 Qt/PySide/Chromium 대응 소스와 네이티브 고지를 동봉한다. 설치 중 개인정보 전문을 보여주고 GitHub 자동·수동 업데이트 통신을 끌 수 있게 한다. 기존 사용자에게는 저장된 선택을 유지하며 처음 선택 기록이 없으면 기존 자동 업데이트 기본값을 유지한다. Steam 채팅 사용 여부와는 별개다. 앱 설정에서도 통신 선택과 오프라인 고지를 제공한다.

GitHub Windows 실행기의 소스 검증·테스트·미서명 앱/설치 파일 빌드를 신청 근거로 사용한다. 이 결과는 재단 심사·코드 서명·Windows 신뢰 경고 해소를 대신하지 않는다. 기존 공개 자산은 교체하지 않으며, 후보에서 새 바이너리를 공개할 때는 검증한 대응 소스 묶음도 함께 게시한다.

## 2026-10-15: 원작 고양이와 말풍선으로 앱 아이콘을 통일한다

사용자가 요청한 원작 Bongo Cat 아이콘에 말풍선을 더하는 방향을 채택한다. 기울어진 하얀 고양이·분홍 발바닥과 메신저의 보라색 말풍선을 결합하고 투명 배경으로 만든다. 앱 내부 로고, Qt 창, Windows 실행 파일·설치·제거 프로그램, 파비콘에 동일한 마스터에서 내보낸 파일을 사용한다. 게임 원본 실행 파일은 수정하지 않으며 참조 아이콘 추출본은 Git에 포함하지 않는다. [출처·생성·내보내기](design/app-icon.md)와 [검증 범위](product-validation.md#2026-10-15-앱-아이콘과-파비콘)를 별도로 기록한다.

## D-023. 업데이트 준비 후 앱을 자동으로 재시작한다

**상태: 2026-10-15 사용자 요청·소스 구현. 공개 배포와 구분.**

새 버전을 자동으로 내려받은 뒤 앱이 스스로 재시작해 적용하도록 D-016을 확장한다. 준비 완료 안내 후 30초를 기다리고 한글 조합·방 전환·전송 중에는 재시작을 보류한다. 마지막 입력 후 최소 5초를 기다리며 최신 초안 저장에 성공하고 전송 결과가 정리돼야 종료한다. 저장 오류·미저장 기록이 있으면 현재 창을 유지한다.

앱의 정상 종료·DB 잠금 해제 후 실행기의 기존 복사본 인계와 서명·해시·오프라인 후보 검사를 사용한다. 이전 실행기로 시작한 앱, 개발 소스·일반 오프라인·화면/연결 진단 실행에서는 자동 재시작하지 않는다. 명시적 `--update-smoke-dir` 설치본 진단만 게임 작업자 없이 실제 업데이트와 재시작을 허용하며 별도 데이터 폴더를 요구한다. 업데이트 통신 선택을 끄면 예약된 자동 재시작도 취소한다. 대화 기록과 실행 옵션은 유지하며 게임·Steam을 종료하거나 메시지를 재송신하지 않는다. 재시작 중 수신하지 못한 대화는 복원한다고 약속하지 않는다. [동작과 호환성](automatic-updates.md), [검증 범위](update-validation.md)를 따른다.

## D-024. 여러 Steam 게임을 실행해도 Bongo Cat의 로비를 직접 확인한다

**상태: 2026-10-15 복수 게임 실행 시 로비 탐색 실패 제보·소스 수정. 설치본 배포와 구분.**

기존 작업자는 `GetFriendGamePlayed`가 Bongo Cat을 보고해야 로비를 인정하고 메모리 탐색을 시작했다. Steam이 다른 게임을 보고하면 실제 Bongo Cat 로비를 확인할 경로까지 막혔다. 이 API는 친구의 게임 정보 조회이며 실행 중인 모든 게임을 열거하는 API가 아니다. [Steamworks 공식 설명](https://partner.steamgames.com/doc/api/ISteamFriends#GetFriendGamePlayed)을 근거로 이를 Bongo Cat 실행 여부의 필수 조건으로 사용하지 않는다.

- 지원 조건과 프로세스 수명을 확인한 `BongoCat.exe`의 메모리 탐색을 Steam 초기화 후 시작한다. 친구 게임 정보가 없거나 다른 게임을 가리켜도 탐색·실패 후 재시도를 계속한다.
- `LobbyData.Current`를 읽은 뒤에는 그 값이 로비의 기준이다. Bongo Cat App ID로 초기화한 Steam 계정과 해당 로비의 자기 참여를 확인하며, 다른 게임의 로비를 목적지로 사용하지 않는다.
- 친구 게임 정보는 메모리 탐색 전 Bongo Cat 로비·초안 표시를 앞당기는 보조 정보로만 사용한다. 로비 없음·메모리 읽기 실패를 이 정보로 덮지 않는다. 확인 중에는 송수신을 허용하지 않는다.
- 다른 게임을 실행·종료해 친구 게임 정보가 바뀌어도 실제 Bongo Cat 로비가 같으면 연결 구간과 초안을 유지한다. Bongo Cat 로비·계정·프로세스 변경, 자기 참여 해제, 파일 호환성 실패에 대한 차단과 송신 직전 확인은 유지한다.
- 숨김 미확인 상대의 본문·저장 차단, 전환 시 콜백 비우기, 읽기 전용 실행, 자동 재전송 금지를 유지한다. Bongo Cat 자체가 여러 개 실행되는 경우에는 기존처럼 대상을 모호하다고 판정한다.

합성 회귀 검사와 실제 읽기 전용 연결 검사는 [제품 검증 기록](product-validation.md#2026-10-15-복수-steam-게임-실행-시-로비-탐색-수정)에 구분한다. 후속으로 사용자가 스파이더맨 리마스터를 실행한 상태에서 수정 전 실패와 수정 후 로비 발견·30초 연결 유지를 확인했다. 추가 실행/종료 전환, 로비 이동·송신 시험은 포함하지 않는다.

## D-025. 현재 로비 상대의 Steam 프로필을 외부 Steam 창으로 연다

**상태: 2026-10-16 이슈 #23에 따라 소스 구현. 게임 미실행 상태의 합성 검사와 실제 Steam 표시 인수를 구분.**

- 참여자 목록과 현재 로비 메시지의 상대 이름·아바타에 `Steam 프로필 열기`를 제공한다. 친구 추가는 외부 Steam 창에서 사용자가 직접 진행하며 앱이 친구 요청을 보내지 않는다.
- ID는 전체 경로에서 문자열로 유지한다. 네이티브에서 공백·부호·선행 0이 없는 양의 ASCII 십진수 문자열과 uint64 범위를 검사하고 `steam://url/SteamIDPage/<SteamID64>`만 조립한다. 범용 URL 열기 권한과 렌더러 외부 탐색은 허용하지 않는다.
- 클릭 당시 계정·로비·generation이 현재 context와 일치하고 연결 표본이 2.5초 미만이며 로비 검증·대상 비숨김·현재 프로필이 확인돼야 한다. 작업자는 1초 프로필 캐시와 별개로 매 상태 발행 시 현재 참여자·비숨김 집합과 교집합을 취한다. 자기 자신과 보관 로비에는 액션을 제공하지 않는다.
- 전원 숨김 동기화 완료나 채팅 송신 가능 여부는 요구하지 않는다. 읽기 전용·부분 확인에서도 선택한 상대가 허용되면 열 수 있다. 종료·업데이트 재시작 중에는 거절한다. 이미 확인한 표본 직후의 실제 퇴장까지 원자적으로 차단한다고 약속하지 않는다.
- 사용자 동작 한 번에 OS 전달 한 번을 요청한다. 진행 중 연타·더블클릭과 네이티브 재진입을 차단하고 자동 재시도하지 않는다. `QDesktopServices.openUrl(QUrl(uri))`의 실패·예외는 별도 오류로 바꾸며 저장 오류나 전송 차단을 유발하지 않는다.
- 메시지 내용이 같아도 권한·context·화면 로비 변경을 렌더링에 반영한다. 참여자 갱신에서 같은 대상의 키보드 포커스를 복원하고 대상이 사라지면 닫기 버튼으로 이동한다. 초안·검색·스크롤·선택 방은 프로필 동작으로 변경하지 않는다.

이슈에 기록된 진단 코드의 실제 URI 검증을 새 제품 버튼의 통합 인수로 대신하지 않는다. 이번 작업 PC에서는 사용자 요청으로 Bongo Cat을 실행하지 않는다. [오프라인 검증과 남은 인수](product-validation.md#2026-10-16-이슈-23-steam-프로필-열기)를 따른다. 설치본 교체·릴리스 게시·친구 관계 변경은 이번 범위에 포함하지 않는다.
## D-026. 새 상대 수신에 비활성 앱 알림과 기기별 두 설정을 연결한다

**상태: 2026-10-16 이슈 #24의 세 기능을 후속 소스에 구현. 배포·실제 로비 인수와 구분.**

작업 표시줄 깜빡임·알림 센터에 남는 Windows 토스트·독립 ON/OFF를 제품 수신에 연결한다. 상세 기본값·일반 문구·5초 간격·정리 정책은 이슈의 제안 기준을 구현 선택으로 채택한 것이며 별도 사용자 합의로 소개하지 않는다. 같은 시점의 이슈 #23 작업이 사용하는 D-025/FR-16과 번호를 중복하지 않는다.

- 필터 이후 새 상대 수신만 `AcceptedIncoming`으로 반환한다. 자기 에코·중복·울음·미확인·숨김·이전 연결·기록 조회는 제외하고 부분 숨김 확인·읽기 전용·새 미저장 수신은 허용한다.
- Qt 앱 활성 상태면 억제하고 포커스를 가져오지 않는다. 수신 큐를 추가하지 않으며 첫 토스트 즉시·5초 뒤의 새 수신부터 다시 제출한다. 저장·표시는 전부 유지한다.
- 기기별 bool 두 키는 기본 ON이고 명시적 OFF를 유지한다. 저장 성공 뒤 확정하며 실패는 이전 값으로 복구한다. OS 알림 오류를 저장 오류로 취급하지 않는다.
- Windows에는 고정 제목·안내만 남기고 자기 그룹만 정리한다. 고정 AUMID와 안정적인 런처를 설치·업데이트·제거에 사용하며 이전 기본 바로가기는 소유 확인 후 보완한다.
- 게임 실행·기존 실사용 데이터·Windows 알림 설정을 변경하지 않고 합성 검사한다. 앱 종료 중 수신·트레이 상주·클릭 활성화·공개 릴리스는 추가하지 않는다.

정확한 정책과 실패·만료·롤백 범위는 [알림 안내](notifications.md), 실행 근거와 남은 인수는 [제품 검증 기록](product-validation.md#2026-10-16-이슈-24-제품-알림-연결)을 따른다.

## D-027. 아이템 미착용을 정상적인 기본 외형으로 표시한다

**상태: 2026-10-20 이슈 #32에 따라 소스 수정. 실제 게임 실행 없이 검증.**

로비 슬롯의 명시적인 `-1`은 아이템 미착용이다. 스킨은 설치 리소스의 `CatLeft`·`CatRight`를 사용하는 기본 캐릭터로, 모자는 레이어 생략으로 처리한다. 기본 캐릭터에 착용한 모자도 유지한다. 슬롯 누락·파싱 실패·알 수 없는 아이템·정의 조회 실패를 기본 외형으로 치환하지 않는다.

게임 빌드 `25936063`의 미착용 기록·기본 스프라이트 참조를 파일 읽기로 확인했고, 합성 외형 전환과 Qt 화면 갱신을 검사했다. 게임 실행·Steam 초기화·실제 이용자의 착용 변경은 수행하지 않았다. [검증 기록](product-validation.md#2026-10-20-이슈-32-기본-아바타)과 [dev13 안내](releases/0.1.0.dev13.md)를 따른다.

## 변경 내용

제품 버전 두 곳을 `1.0.0`으로 맞췄다. 창·HTML 제목·연결 안내·길이 제한 안내·한국어/영어 번역·설치기·CLI의 개발판 전제 문구를 정리했다. 50 UTF-16 단위 제한과 기존 기능·자동화 기본값·보호 정책은 유지한다. 내부 `development` 상태와 `development_limit_50` 코드, 과거 릴리스 기록과 호환성 fixture는 보존한다.

Windows 제거 등록 정보는 현재 사용자에게 이미 존재하는 항목만 처리하며 설치 위치와 제거 프로그램 경로를 모두 확인한다. 활성 슬롯 실행 파일이 있고 설치 소유가 일치할 때만 `DisplayVersion`을 갱신한다. 다른 설치본·없는 키·접근 실패는 변경하지 않으며 등록 오류가 앱을 막지 않는다. 새 실행기는 시작 전과 종료·복귀 후 동기화한다.

첫 dev34 → 1.0.0은 이전 실행기가 적용하므로 새 앱에서도 보고한다. 이전 실행기의 45초 초기 실패 복귀 구간에는 후보 버전을 먼저 기록하지 않는다. 정상 종료하거나 앱 실행이 45초를 지난 뒤 반영하며 이 구간의 Windows 표시 지연은 의도한 동작이다. 초기 실패는 이전 표시를 유지한다.

현행 사용 문서와 한국어/영어 개인정보 안내에 저장된 상자 자동 시작 선택을 반영했다. [게시용 안내 초안](releases/1.0.0.md)을 준비했고 README 이미지 6장을 같은 가상 대화·일러스트와 실제 제품 HTML로 다시 캡처했다. `tools/capture_readme.py`로 재생성할 수 있다. 스크린샷은 실제 계정·게임 화면이나 소비 시험의 증거가 아니다.

## 설치와 dev34 전환 확인

별도 시험 폴더·가상 데이터·시험용 제거 등록 항목에서 **offline**으로 수행했다. 사용 중인 설치의 제거 등록 정보와 업데이트 통신 선택은 전후 동일함을 확인했다.

1. 시험용 Setup.exe로 신규 설치 후 실제 동결 실행기를 실행했다. marker·Windows `DisplayVersion`·보고서가 `1.0.0`으로 일치했다. 시험 설치를 제거해도 시험용 업데이트 통신 OFF 선택은 남았다.
2. 공개 dev34 ZIP의 **기존 공개키 Ed25519 서명·해시**를 검증하고 별도 슬롯에 풀었다. dev34 동결 실행기로 오프라인 시작과 버전을 확인했다.
3. 기준 커밋의 dev34 `bootstrap.py`를 그대로 불러와 실제 1.0.0 후보 ZIP 적용과 새 동결 앱 실행을 검사했다. 시험 manifest에는 메모리에서 만든 일회용 키를 사용했다. **공개 dev34 동결 실행기의 운영 서명 패키지 다운로드 인수는 아니다.** 운영 공개키·앱 설정·개인키는 변경하거나 사용하지 않았다.
4. probe 실패 시 활성 버전·Windows 표시는 dev34를 유지했다. 성공 시 실제 새 앱이 실행되고 marker·Windows 표시·보고서가 1.0.0으로 일치했다. 가상 대화·초안·언어·테마·실제 `auto_chest` 설정의 `start_on_launch` 선택을 보존했다. 시험 업데이트 통신 선택도 OFF를 유지했다.
5. probe 이후 EXE 격리를 시험 폴더에서 재현했다. 이전 실행기 로직은 dev34로 복귀하고 Windows 표시도 dev34를 유지했다. 설치된 새 동결 실행기로 이전 dev34 슬롯을 실행하는 경로도 통과했다.
6. 회귀 검사에서 45초 이전 정상/비정상 종료·장기 실행 보고 시점·다른 설치 위치·잘못된 제거 경로·누락 키·접근 거절·소스 실행도 확인했다.

## 산출물과 남은 단계

### 자동 업데이트 첫 실행의 실행기 호환

2026-11-16 후속 요구는 기존 사용자도 Setup.exe 재설치 없이 무인 복구를 쓰는 것이다. dev34의 `apply_pending`은 이미 실행기 파일을 교체한다. 남는 것은 디스크의 구형 실행기가 아니라 첫 앱을 기다리는 이전 도우미 프로세스다. 앞선 재설치 필요 안내는 이 둘을 혼동한 설명으로 정정했다.

새 앱의 진입점은 설치·활성 버전·실행 파일·데이터 위치 검증을 마친 뒤, 현재 설치의 이전 실행기/도우미가 부모이고 복구 토큰이 없는 경우 UI·작업자·DB를 열기 전에 현재 버전의 세션 제어를 맡는다. 기존 도우미는 설치 잠금을 유지한다. 실제 UI 자식에는 새 복구 토큰이 전달되므로 다시 중첩되지 않고 복구 종료 코드 23은 새 제어부에서 처리한다. 다음 일반 실행은 디스크의 새 실행기를 직접 사용한다. 첫 세션에만 제어 프로세스 하나가 추가로 유지되는 방식이다. 소스·오프라인·읽기 전용·진단 실행과 재시도 금지 상태는 제외한다.

- 공개 기준 `22d91a2`의 dev34 실행기 소스를 검사 fixture로 보존했다. 시험 서명을 검증하는 기존 적용 함수→새 진입점→새 세션 제어를 연결해 정상 종료, 초기 오류/실행 파일 접근 실패의 복귀, 프로필 점유, 다음 업데이트 코드, 복구 요청 처리와 잠금·가상 데이터 보존을 검사했다.
- 복구·업데이트·등록 정보·실제 오프라인 Qt 화면·번역 관련 **178개 통과**(44.76초). 그 뒤 실행 파일 접근 실패 사례 1개를 추가한 최종 핵심 검사 `pytest -q tests/test_launcher_compat.py tests/test_install_metadata.py tests/test_updates.py`는 **98개 통과**(2.41초). 두 결과는 겹치므로 합산하지 않는다. UI 검사에는 기존 Chromium shared-image 진단이 남았지만 실패는 없었다.
- 공개 dev34 ZIP의 운영 공개키 서명·파일 해시를 확인하고 그 안의 실제 동결 실행기를 별도 시험 도우미로 실행했다. 현재 진입점·호환 제어·복구 루프를 포함한 동결 가상 앱을 첫 앱으로 연결했다. Setup.exe 실행 없이 첫 UI의 복구 지원, 모의 재시작 1회, 두 번째 UI의 새 토큰과 잔여 합성 예산 5회(9회 중 4회 완료), 가상 기록 보존을 확인했다. UI와 게임 함수만 모의 구현이며 실제 Steam·게임·운영 등록 정보는 접근하지 않았다. 실제 제품 UI와 패키지의 동결 검사는 최종 CI에서 별도로 확인한다.
- 초기 시험 실행 파일의 Python 진입점 import와 빌드 데이터 상대 경로를 보완한 뒤 위 실행 검사가 통과했다. 실패한 시험 폴더·로그도 보존한다. 단위 검사의 환경 dict를 참조로 기록한 오류도 복사본 기록으로 수정했다. 이들은 제품 동작 실패와 구분한다.

이번 변경은 새 업데이트 채널·서명 키·데이터 변환·설치 파일 재실행을 추가하지 않는다. 첫 실행의 Windows 버전 표시는 초기 실패 복귀 구간 동안 조기 갱신하지 않는다. 실패 시 기존 버전 선택 복귀와 업데이트 재시도 금지 정책을 유지한다. 최종 소스의 전체 검사·Windows 빌드·설치기·패키지 검사는 PR #70의 필수 CI에서 확인하며 정확한 head와 결과는 PR 본문에 남긴다. 이번 증거는 `artifacts/launcher-compat-1.0.0/`에 보존한다. 실제 서버 장애→게임 재시작→소비 재개 종단 인수와 배포는 수행하지 않는다.

### 무인 복구 통합

2026-11-16 후속 사용자 지시에 따라 기존 미커밋 무인 복구(D-042)를 1.0.0 범위에 포함했다. 원본 24개 파일은 변경하지 않고 작업 브랜치에 복사했다. 실행기 import, 번역, 결정 기록과 Qt 검사 충돌을 조정하면서 dev34의 복복 알림·화면 종료 순서 보완과 1.0.0의 설치 버전 갱신을 유지했다. 개인 세션·합성 ledger·실제 로비 자료는 가져오지 않았다.

- 기본 OFF, 2분 장애 기준, 원래 계정·로비·작업 조건, 합성 잔여 횟수, 소비 결과 미확인 차단, 상대 상자 중복 요청 보호를 통합했다. 기존 기록의 201개 검사는 과거 무인 복구 소스의 근거이며 이번 통합의 통과 결과로 재사용하지 않는다.
- 이 단계에서는 첫 실행의 이전 도우미와 디스크의 새 실행기를 구분하지 못해 Setup.exe 재설치가 필요하다고 안내했다. 후속 실행기 호환 보완에서 이 설명을 정정하고 재설치 조건을 제거했다. 이 단계의 검증은 `c55b20c` 기준이며 후속 호환 변경의 근거로 재사용하지 않는다.
- `pytest -q tests/test_game_recovery.py tests/test_updates.py tests/test_auto_merge.py tests/test_auto_chest.py tests/test_connection_recovery.py tests/test_install_metadata.py tests/test_desktop.py tests/test_localization.py`: **280개 통과**, 79.05초, 생략 없음.

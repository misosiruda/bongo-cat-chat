# 1.0.0 전환 구현과 로컬 후보 검증

2026-11-16, [#69](https://github.com/misosiruda/bongo-cat-chat/issues/69). 문서·구현·로컬 검증을 진행했고 **배포·태그 생성·원격 게시·실제 게임 소비 시험은 수행하지 않았다.** 착수 시 공개 최신판은 `v0.1.0.dev34`였다. 이 기록은 1.0.0 공개 완료를 의미하지 않는다.

- 릴리스 도구 기준: `600a2d45ebbdbf0d0df15829c0c07900a14a537a`. 작업 공간은 `C:\Project\bongo-cat-chat-release-v1`, 브랜치는 `chore/stable-release-copy`다.

## 변경 내용

제품 버전 두 곳을 `1.0.0`으로 맞췄다. 창·HTML 제목·연결 안내·길이 제한 안내·한국어/영어 번역·설치기·CLI의 개발판 전제 문구를 정리했다. 50 UTF-16 단위 제한과 기존 기능·자동화 기본값·보호 정책은 유지한다. 내부 `development` 상태와 `development_limit_50` 코드, 과거 릴리스 기록과 호환성 fixture는 보존한다.

Windows 제거 등록 정보는 현재 사용자에게 이미 존재하는 항목만 처리하며 설치 위치와 제거 프로그램 경로를 모두 확인한다. 활성 슬롯 실행 파일이 있고 설치 소유가 일치할 때만 `DisplayVersion`을 갱신한다. 다른 설치본·없는 키·접근 실패는 변경하지 않으며 등록 오류가 앱을 막지 않는다. 새 실행기는 시작 전과 종료·복귀 후 동기화한다.

첫 dev34 → 1.0.0은 이전 실행기가 적용하므로 새 앱에서도 보고한다. 이전 실행기의 45초 초기 실패 복귀 구간에는 후보 버전을 먼저 기록하지 않는다. 정상 종료하거나 앱 실행이 45초를 지난 뒤 반영하며 이 구간의 Windows 표시 지연은 의도한 동작이다. 초기 실패는 이전 표시를 유지한다.

현행 사용 문서와 한국어/영어 개인정보 안내에 저장된 상자 자동 시작 선택을 반영했다. [게시용 안내 초안](releases/1.0.0.md)을 준비했고 README 이미지 6장을 같은 가상 대화·일러스트와 실제 제품 HTML로 다시 캡처했다. `tools/capture_readme.py`로 재생성할 수 있다. 스크린샷은 실제 계정·게임 화면이나 소비 시험의 증거가 아니다.

## 설치와 dev34 전환 확인

별도 시험 폴더·가상 데이터·시험용 제거 등록 항목에서 **offline**으로 수행했다. 사용 중인 설치의 제거 등록 정보와 업데이트 통신 선택은 전후 동일함을 확인했다.

1. 시험용 Setup.exe로 신규 설치 후 실제 동결 실행기를 실행했다. marker·Windows `DisplayVersion`·보고서가 `1.0.0`으로 일치했다. 시험 설치를 제거해도 시험용 업데이트 통신 OFF 선택은 남았다.
2. 공개 dev34 ZIP의 **기존 공개키 Ed25519 서명·해시**를 검증하고 별도 슬롯에 풀었다. dev34 동결 실행기로 오프라인 시작과 버전을 확인했다.
3. 기준 커밋의 dev34 `bootstrap.py`를 그대로 불러와 실제 1.0.0 후보 ZIP 적용과 새 동결 앱 실행을 검사했다. 시험 manifest에는 메모리에서 만든 일회용 키를 사용했다. **공개 dev34 동결 실행기의 운영 서명 패키지 다운로드 인수는 아니다.** 운영 공개키·앱 설정·개인키는 변경하거나 사용하지 않았다.
4. probe 실패 시 활성 버전·Windows 표시는 dev34를 유지했다. 성공 시 실제 새 앱이 실행되고 marker·Windows 표시·보고서가 1.0.0으로 일치했다. 가상 대화·초안·언어·테마·실제 `auto_chest` 설정의 `start_on_launch` 선택을 보존했다. 시험 업데이트 통신 선택도 OFF를 유지했다.
5. probe 이후 EXE 격리를 시험 폴더에서 재현했다. 이전 실행기 로직은 dev34로 복귀하고 Windows 표시도 dev34를 유지했다. 설치된 새 동결 실행기로 이전 dev34 슬롯을 실행하는 경로도 통과했다.
6. 회귀 검사에서 45초 이전 정상/비정상 종료·장기 실행 보고 시점·다른 설치 위치·잘못된 제거 경로·누락 키·접근 거절·소스 실행도 확인했다.

## 산출물과 남은 단계

로컬 증거는 `artifacts/release-1.0.0/`에 보존한다. `test-results.xml`, `full-tests.log`, `install-upgrade-result.json`, `verify_install_upgrade.py`, 각 browser 로그를 포함한다. 패키지 증거는 `dist/release-1.0.0/evidence/bundle-validation.json`이다. 시험 등록 항목과 시험 바로가기는 정리하고 후보·가상 DB·실패/복귀 증거는 후속 검토를 위해 남긴다.

`dist/candidate-1.0.0/`에 Setup.exe·업데이트 ZIP·manifest·대응 소스 ZIP·고지를 준비했다. **운영 Ed25519 서명·승인 영수증이 없는 로컬 후보**다. 서명·승인은 후속 지시에 따라 기존 별도 릴리스 저장소에서 수행해야 한다. Windows Authenticode는 기존처럼 미서명이다.

남은 순서는 별도 게시 도구 검토·원격 반영 → 앱 변경 검토·필수 원격 CI → 사용자 배포 지시 후 승인 후보 빌드·서명 → 게시 dry-run → 게시 승인·공개 → 한국어/영어 본문 반영과 공개 자산/최신 업데이트 경로 확인이다. 초안 안내는 실제 게시 시 제거한다. 로컬 증거를 정확한 원격 후보의 필수 검사 대신 쓰지 않는다.

실제 게임 메시지 송신·합성·상자 개봉·포인트 소비, 실행 중 게임/설치 변경, 게임 종료·재시작·로비 이동, 다른 PC·순정 게임·장시간 인수는 수행하지 않았다. #69의 공개 게시·공개 경로 확인 항목은 남아 있다.

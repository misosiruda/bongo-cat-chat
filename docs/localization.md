# 한국어·영어 지원

2026-10-23 사용자 요청으로 앱 한·영 UI와 영문 README를 추가한 후속 소스다. 커뮤니티 소개와 사용 안내를 위한 준비이며 공개 설치본 배포·커뮤니티 게시와 구분한다.

## 사용자 동작

**설정 → 언어 / Language**에서 `시스템 설정`, `한국어`, `English`를 선택한다. 시스템 설정은 Windows의 표시 언어 목록 첫 항목이 한국어이면 한국어, 그 외에는 영어를 선택한다. OS 표시 언어 변경은 다음 실행 또는 시스템 설정 재선택 시 반영한다.

언어는 기기별 SQLite settings의 `language`에 `system`, `ko`, `en` 중 하나로 저장한다. 저장 성공 후 화면과 Qt 창 제목에 적용하고 다음 실행에도 유지한다. 저장 실패 시 이전 값과 표시 언어를 유지한다. 기존 설정 행이 없거나 지원하지 않는 값이면 시스템 설정을 사용한다. 시작 시 읽기 실패에는 저장 오류를 표시하면서 시스템 언어로 앱을 열고 기존 설정을 덮어쓰지 않는다. DB 스키마와 기존 기록은 변환하지 않는다.

새로고침으로 저장소를 복구할 때 언어 설정도 다시 읽는다. 읽기가 계속 실패하면 저장 오류를 유지하고, 복구되면 저장된 명시적 언어를 다시 적용해 창 제목과 다음 view를 갱신한다.

## 번역 범위

- 앱의 사이드바·검색·참여자·설정·접근성 레이블·입력 안내.
- 연결 확인·숨김 확인·오프라인·읽기 전용·미지원 게임·작업자 종료 안내.
- 전송 중·Steam 접수·실패·결과 불명, 저장 실패와 설정 저장 상태.
- 업데이트 진행·검증 실패·롤백·자동 재시작 안내.
- 날짜·시간 표시: 선택 언어에 맞춘 `ko-KR` 또는 `en-US`, 시간대는 실행 환경의 로컬 시각.
- Qt 창 제목, 시작 오류 안내, Windows 새 메시지 토스트와 개인정보 안내 창.
- [영문 README](../README.en.md)와 [영문 개인정보 안내](privacy-policy.en.md). 대응 소스·배포 라이선스 전문은 기존 영어 고지를 사용한다.

대화 본문·초안·검색어·이용자 이름·로비 이름·게임 울음 문자열은 번역하지 않는다. 앱 문구와 같은 단어라도 사용자 데이터는 원문으로 유지한다. 언어 변경 시 선택 대화·검색·초안·메시지 스크롤 위치를 유지하며 메시지를 보내거나 재전송하지 않는다.

새로 조회한 이름이 없으면 빈 값을 저장하고 UI에서 현재 언어의 임시 이름을 붙인다. 기존 DB에 이미 저장된 한국어 기본 이름은 실제 이용자/로비 이름과 확실하게 구분할 수 없어 자동 치환하지 않는다. DB를 열기 전의 시작 오류는 Windows 표시 언어를 사용한다. 경량 실행기의 설치 확인 오류는 한·영 병기로 안내한다.

**설치 마법사는 기존 한국어를 유지한다.** 영문 README에 설치 버튼의 의미를 설명한다. 전체 설계 이력·과거 검증 기록을 일괄 번역하지 않으며 영문 README에서 한국어 문서임을 표시해 연결한다. 공개 설치본·새 버전 번호·서명·실제 로비 인수는 이 변경으로 완료되지 않는다.

## 구현

`src/bongo_chat/ui/translations.json`은 한국어 원문을 키로 하는 영어 번역표다. `localization.py`가 로컬 파일을 읽고 OS 표시 언어를 판정한다. Qt bridge는 선택 언어와 저장된 선호를 반환하며 렌더러가 다른 언어를 요청했을 때만 번역표를 전달한다. 외부 번역 API·네트워크 요청·브라우저 로컬 저장소는 사용하지 않는다.

`app.js`는 시작 시 앱 HTML의 정적 문구만 수집한다. 사용자 메시지를 생성한 뒤 DOM 전체를 검색해 치환하지 않는다. 동적 앱 문구는 `t()`를 사용하고 변수는 이름 있는 자리표시자로 전달한다. 날짜·시각, 상태와 동적 접근성 레이블은 다시 렌더링하며 기존 스크롤 앵커를 복원한다. 이름과 본문은 계속 `textContent`로 다룬다.

개인정보 영어 문서는 배포 고지 생성 시 `PRIVACY.en.md`로 동봉한다. 영어 모드의 개인정보 버튼이 해당 파일을 연다. 소스 실행에서도 영어 안내를 열 수 있고, 배포본에서 고지가 누락됐으면 기존 `legal_unavailable` 오류로 처리한다.

## 검증

게임 실행·Steam 초기화·실사용 로비 송신 없이 다음 검증을 실행한다.

```powershell
.venv/Scripts/python.exe -X utf8 -m pytest tests/test_localization.py tests/test_core.py tests/test_windows_notifications.py -q
.venv/Scripts/python.exe -X utf8 -m pytest -q
.venv/Scripts/python.exe -X utf8 tests/browser_localization_check.py --browser "C:\Program Files\Google\Chrome\Application\chrome.exe" --output "<저장소 밖의 검증 출력 폴더>"
```

- 번역표 누락·비어 있는 번역·변수 이름 불일치 검사.
- 시스템 언어, 명시적 선택, Controller 재생성·화면 재로드 후 유지.
- 한국어 → 영어 → 한국어 전환, 설정 저장 실패·잘못된 언어 값.
- 앱 문구와 같은 사용자 이름·본문·초안 원문 유지, 검색 유지.
- 실제 Qt bridge/SQLite/렌더러와 영어 Windows 토스트 XML 생성. OS 알림 제출은 mock이며 실제 배너 표시는 별도다.
- 설치된 Chrome의 Playwright 합성 화면: 언어 전환·저장 실패·연결/업데이트 상태, 1240×840·960×540·400×500에서 라이트·다크 설정창 6개 조합. 닫기 버튼·하단 삭제 확인 접근, 수평 넘침, 콘솔 오류와 읽던 메시지 앵커를 확인한다.

실행 결과는 [제품 검증 기록](product-validation.md)의 2026-10-23 한·영 UI 항목에 기록한다. 브라우저 검사는 설치된 Chrome과 기존 Playwright 의존성을 사용했다. 합성 화면 증거는 실제 게임·설치 파일의 동작 증거가 아니다.

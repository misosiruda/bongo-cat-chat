# 새 메시지 알림

**2026-10-28 후속 변경:** 아래의 게임 숨김 기반 제외 정책은 앱의 [Steam ID 차단 목록](chat-blocking.md)으로 대체한다. 게임에서 숨긴 고양이도 허용하며 앱에서 차단한 상대만 알림·반응에서 제외한다. 과거 검증 결과는 당시 정책의 이력이다.

이슈 [#24](https://github.com/misosiruda/bongo-cat-chat/issues/24)의 후속 소스 기능이다. 게시된 `0.1.0.dev11` 설치본에 포함됐다는 뜻은 아니다. 앞선 [독립 기술 검증](notification-validation.md)과 제품 통합 검사를 구분한다.

## 동작과 설정

설정의 **새 메시지 알림**에서 **작업 표시줄 깜빡임**과 **Windows 알림**을 각각 선택한다. 설정 키가 없는 신규·기존 프로필은 둘 다 켜진다. 저장한 OFF는 다음 실행에도 유지한다. 저장 중에는 해당 항목을 잠시 비활성화하고, 실패하면 마지막 저장값으로 되돌린 뒤 설정창에 설명한다.

시작 시 설정 조회에 실패하면 키 미존재로 간주하지 않고 두 알림을 보류한다. 새로고침으로 저장소 복구가 성공하면 두 값을 한 번에 다시 읽는다. 일부 조회만 성공한 값을 섞거나, 복구하면서 저장된 OFF를 기본 ON으로 바꾸지 않는다.

앱이 실행 중이고 다른 프로그램을 사용하거나 창을 최소화했을 때 새 상대 메시지를 알린다. 설정·참여자·고지 창을 포함해 Qt 앱이 활성 상태면 두 알림 모두 생략한다. 메시지 수신으로 창을 앞으로 가져오지 않으며, 창 닫기를 트레이 숨김으로 바꾸지 않는다. 앱 종료 중 수신, Windows 자동 실행, 빠른 답장·클릭 활성화는 추가하지 않는다.

작업 표시줄 주의 표시는 앱 복귀, 해당 옵션 OFF, 연결·숨김 권한 상실, 종료·업데이트 인계 때 해제한다. Qt `QApplication.alert(window, 0)`로 시작하고 Windows `FlashWindowEx(FLASHW_STOP)`으로 중지한다. 중지 API의 반환값을 성공 여부로 해석하지 않는다.

Windows 토스트는 최초 유효 수신에 즉시 제출한다. 그 뒤 **5초 미만**의 수신은 추가 토스트를 생략한다. 5초 이후 새로 들어온 메시지부터 다시 제출하며, 같은 tag/group의 한 항목으로 교체한다. 별도 대기 큐나 타이머 재발송이 없어 앱 복귀·OFF→ON·재연결 뒤 과거 알림이 재생되지 않는다. 채팅 저장·표시는 생략하지 않는다. 앱 복귀 또는 권한 상실 뒤에는 다음 새 수신부터 새 주기로 시작한다.

Windows 설정에서 알림을 끄거나 방해 금지·전체 화면 정책을 사용하면 배너·소리가 제한될 수 있다. 앱은 OS 설정을 변경하지 않는다. API 제출을 사용자 열람이나 배너 표시 완료로 설명하지 않는다.

## 수신·오류 경계

`ChatService.receive()`는 수락한 새 상대 메시지만 본문 없는 `AcceptedIncoming`으로 반환한다. `Controller.poll()`이 이를 같은 GUI 스레드에서 처리한다. 현재 계정·로비·generation, 2.5초 미만의 연결 표본, 검증된 로비, 상대별 숨김 허용을 확인한다. 숨김·미확인 상대, 자기 메시지·자기 에코, 중복 receipt, 클릭 울음, 이전 연결은 알림을 만들지 않는다. 작업자는 현재 참여자 밖의 발신자를 본문 복사 전에 거른다.

전원 숨김 확인 완료나 송신 가능 상태는 요구하지 않는다. 일부만 확인된 경우 허용된 상대와 읽기 전용 수신에도 같은 정책을 적용한다. 저장 실패로 메모리에만 표시하는 새 상대 메시지도 한 번 알리며 DB 재조회·검색·기록 페이지·테마·재렌더링은 수신으로 취급하지 않는다.

두 bool 키 `notification_flash`, `notification_toast`는 기존 SQLite settings에만 추가한다. 문자열·숫자·null·미등록 키는 브리지에서 거절한다. OS 발송·등록·정리 실패는 별도 상태로 설정창에 표시하며 `storage_error`나 송신 실패로 바꾸지 않는다. 토스트 발송/등록 오류 뒤에는 자동 재시도를 멈추고 옵션 OFF→ON 또는 앱 재실행 뒤의 새 메시지에서 다시 시도한다. OS 알림 제한 상태는 5초 간격의 새 수신에서만 확인한다. 정리 오류는 폴링마다 재시도하지 않는다.

새 AUMID의 첫 제출 전에는 Windows 설정 행이 없어 `ToastNotifier.Setting`이 `0x80070490`을 반환하는 경우를 실제 합성 시험에서 확인했다. 이 오류만 첫 `Show`를 허용하며, Windows가 발송 과정에서 OS 정책을 적용하도록 한다. 설정 레지스트리를 만들거나 정책을 켜지 않는다. 그 밖의 조회 오류는 정상 발송으로 처리하지 않는다.

## 개인정보·수명

토스트 내용은 제목 **Bongo Cat Chat**, 본문 **새 메시지가 도착했어요.**로 고정한다. 발신자·대화 본문·Steam ID·로비 정보를 Windows XML·tag·group·실행 인자에 넣지 않는다. 네트워크나 서버 푸시를 사용하지 않는다.

앱 복귀, Windows 알림 OFF, 연결/허용 경계 변경, 종료·업데이트 인계 시 자기 `incoming` 그룹만 제거한다. 다른 앱의 알림과 Windows 전체 기록은 지우지 않는다. 정리 실패나 비정상 종료에 대비해 만료는 1일로 설정한다. 기록 삭제 기능은 별도 로컬 DB 정책이며, 토스트에는 삭제한 대화 내용이 처음부터 들어가지 않는다.

이전 프로세스의 비정상 종료로 남은 안내도 정리하도록, 알림을 사용할 수 있는 제품 실행의 최초 상태 동기화에서 자기 그룹 제거를 한 번 시도한다. 첫 동기화 전에 옵션 OFF나 종료가 발생해도 같은 정리를 수행한다. 실패해도 같은 시도를 100ms 폴링마다 반복하지 않으며 새 수신·저장은 계속 처리한다.

## 설치·업데이트·제거

- 제품 AUMID는 버전과 무관한 **`BongoCatChat.Desktop`**이다. 시험용 AUMID나 Python/PowerShell의 ID를 사용하지 않는다.
- 설치기는 `IShellLinkW`와 `IPropertyStore`로 시작 메뉴 바로가기에 `System.AppUserModel.ID`를 기록한다. 아이콘·대상은 버전 슬롯 밖의 안정적인 `BongoCatChat.exe`다. 바로가기는 준비 후 교체하고, 다른 대상·다른 앱 ID 소유의 바로가기는 덮어쓰지 않는다.
- 자동 업데이트로 이전 설치에서 넘어오면 첫 토스트 전에 기존 기본 바로가기의 정확한 런처 경로·소유 ID를 검사하고 누락된 AUMID만 보완한다. 이미 같은 ID면 변경하지 않는다. 바로가기가 없거나 사용자 지정 이름이면 앱이 새로 만들지 않으며 Windows 알림 불가를 설명한다. 재설치로 기본 바로가기를 복원할 수 있다. 작업 표시줄 옵션은 독립적으로 동작한다.
- 버전 슬롯 변경과 롤백은 바로가기 대상·AUMID를 바꾸지 않는다. 제거기는 자기 런처·앱 ID를 확인한 바로가기와 자기 알림 그룹만 정리하며 기존 대화·설정은 보존한다. 새 설정 키는 이전 소스에서 무시할 수 있는 추가 값이며 DB schema를 변경하지 않는다.
- 토스트는 직접 Python/WinRT 바인딩을 사용한다. 메시지마다 PowerShell을 실행하지 않고 Qt 트레이 배너도 함께 발송하지 않는다. Python 3.13 x64 wheel 5개를 `3.2.1`로 고정한다: runtime, Foundation, Foundation.Collections, Data.Xml.Dom, UI.Notifications. 모두 MIT 메타데이터를 확인했다. wheel에 라이선스 전문이 없어 같은 태그의 원문을 commit/SHA-256으로 고정한 `PyWinRT-3.2.1-LICENSE.txt`로 보완한다. PyInstaller는 `--collect-all winrt`로 namespace·네이티브 확장을 수집하며 기존 배포 고지 수집기가 이 전문을 포함한다.

Microsoft의 [데스크톱 AUMID 등록](https://learn.microsoft.com/en-us/windows/win32/shell/enable-desktop-toast-with-appusermodelid), [PyWinRT 문서](https://pywinrt.readthedocs.io/en/latest/), [Qt alert](https://doc.qt.io/qtforpython-6/PySide6/QtWidgets/QApplication.html)를 따른다.

## 검증 범위

제품 정책·실제 QWebChannel·설정 DB·설치 엔진·브라우저·동결 패키지 검사는 [제품 검증 기록](product-validation.md#2026-10-16-이슈-24-제품-알림-연결)에 기록한다. 모든 새 시험은 게임 실행·Steam 작업자·실사용 로비 송신 없이 합성 데이터로 수행한다. 실제 로비 자연 수신, 육안 배너/깜빡임, 다른 PC·Windows 10·방해 금지는 별도 인수다.

# 아이템 자동 합성 — 내부 함수 연결 개발판

관련 이슈: [#43](https://github.com/misosiruda/bongo-cat-chat/issues/43)

2026-10-30 노트북 후속 수정: dev19 설치본이 동일 build에서 Auto Chest 파일 해시 차이로 연결을 거부한 원인을 확인했다. 현재 소스는 다른 11개 게임 파일 해시를 유지하면서 확인된 Auto Chest 해시 2개만 허용한다. 파일 조합 불일치·누락·읽기 실패 안내도 구분한다. 공개 dev19 자체는 변경하지 않았다. [노트북 실패 재현·호환성 근거·로컬 검증](item-auto-merge-laptop-validation.md)을 참고한다.

2026-10-29 사용자가 이 기능에 한해 내부 연결 모듈의 개발·설치를 허용했다. 실행 중인 게임에 연결해 **합성 화면이 닫힌 상태에서 원본 중복 선택과 합성 함수를 호출했고, 두 그룹에서 각각 1회씩 성공을 확인했다.** 첫 요청 완료 후 다음 요청을 보내 요청당 1회, 이번 확인 전체 2회 제한을 지켰다. 이후 연결 처리기를 해제했다. 게임 파일·기존 Auto Chest·로비는 변경하지 않았다.

2026-10-30에는 사용자의 후속 요청에 따라 **앱 내 연결과 로컬 개발 실행 파일까지 완성했다.** 패널의 `게임에 연결` 버튼을 사용하므로 세션 경로를 입력할 필요가 없다. 추가 실제 합성 시험은 금지됐으며 이번 작업의 실제 소비는 0회다. 기존 시험 모듈의 2회 ledger는 그대로 보존했다. 공개 설치본 반영·출시는 별도다.

## UI와 사용 흐름

- 사이드바의 계정·설정 위 **아이템 자동 합성**에서 패널을 연다.
- **게임에 연결**을 누른다. 호환되는 게임 파일·프로세스를 확인한 뒤 연결하며 재료 선택이나 합성은 실행하지 않는다. 같은 게임 수명에서는 기존 세션을 재사용한다.
- 앱에서 **캐릭터·모자·봉고 / 이모티콘·UI 테마**를 선택한다. 게임 탭을 열거나 전면에 유지할 필요가 없다. 게임은 실행 중이어야 하며 수동 합성 화면은 닫혀 있어야 한다.
- 즐겨찾기 포함·이벤트 아이템 제외는 게임의 현재 값을 조회한다. 앱에 별도 보호 옵션을 저장하거나 게임 옵션을 바꾸지 않는다.
- 가능 횟수는 현재 그룹만 표시한다. 미확인은 `확인 필요`, 확인된 소진은 `0회`다. 다른 그룹이나 품질의 재료를 합쳐 계산하지 않는다.
- **최대값으로 설정**은 최신 관측의 횟수를 입력할 뿐 합성을 시작하지 않는다. 양의 정수를 직접 입력할 수도 있다. 그룹을 바꾸면 이전 상한을 비운다.
- **자동 합성 시작**을 명시적으로 눌러 실행한다. 매회 원본 중복 선택으로 재료 10개를 선택하고, 합성 1회의 결과를 확인한 뒤 다음 1회를 요청한다.
- 패널을 닫아도 실행은 유지한다. 사이드바·대화 상단·패널의 중지는 새 요청을 막는다. 이미 접수된 교환의 취소를 약속하지 않는다.
- 미확인 결과는 성공으로 세거나 자동 재시도하지 않는다. 자동 업데이트 재시작도 보류한다. 사용자의 결과 확인은 미확인 건을 성공으로 바꾸지 않는다.
- 앱을 다시 열어도 자동 연결·자동 시작·자동 재개하지 않는다. 수동 게임 재실행 후에는 연결 버튼으로 새 게임 수명에 연결한다. 게임 파일이 다르거나 기존 모듈 상태가 불명확하면 안내 후 거부한다.

## 연결과 보호

```text
Qt 패널 → AutoMerge → BridgeAdapter 작업 스레드 → 접근 제한된 파일 IPC
       → 게임 Unity 메인 스레드 → 원본 SlotDuplicates / TryExchange
       ← 요청에 연결된 결과 콜백 ← 게임의 기존 교환 처리
```

`merge_connection.py`는 명시적인 연결 버튼을 비동기로 처리하고, `merge_install.py`는 검증된 자체 모듈만 연결한다. 게임 파일 수정·게임 재시작·기존 Auto Chest 변경은 하지 않는다. `merge_bridge.py`는 단일 작성자 파일 IPC를 처리한다. 경로·토큰·계정·아이템 ID·설치 인수는 renderer에 전달하지 않는다. offline/read-only 모드에서는 연결할 수 없다. `--merge-bridge-session`은 과거 개발 시험 경로를 위한 선택 사항이다.

`tools/merge_bridge/Bridge.cs`는 고정된 조회·그룹 변경·중복 선택·합성·중지·해제 명령만 처리한다. 임의 코드나 메서드 호출 명령은 없다. 프로세스 생성 시각·epoch·토큰을 검사하고 요청 UUID를 중복 실행하지 않는다. 소비 전에 ledger에 예산 사용을 기록하며 미확인 요청도 사용한 것으로 취급한다. 세션 디렉터리는 현재 사용자와 SYSTEM만 접근한다.

일반 UI용 `interactive` 모드의 최초 허용량은 0이다. `begin` 명령은 명시적 시작 시 그룹·보호 옵션·유휴 상태·상한을 검증하고 실행 ID와 허용량을 기록한다. 선택·합성은 같은 실행 ID 안에서만 허용한다. 누적 소비 횟수를 보존하고 실행 상한을 넘길 수 없다. 중지는 새 요청을 차단하고 실행 허용을 해제한다. 요청 순번을 단조 증가시켜 512개 응답 캐시를 넘긴 뒤에도 과거 명령을 재실행하지 않는다. 오래된 시험 모드의 0~2회 예산과는 별도다.

처리기는 관리 코드의 `BeforeRenderHelper` 콜백 목록에 연결한다. Unity 메인 스레드와 SynchronizationContext를 확인한 후 게임 API를 호출한다. 설치 작업 스레드는 관리 코드 로딩·파일·리플렉션만 수행한다. 현지 게임 빌드의 파일 해시와 Mono export prologue를 검증하며 다른 빌드 지원을 자동 인정하지 않는다.

원본 선택 직전에만 분류 인덱스를 그룹에 맞게 지정하고 finally에서 복원한다. 실제 탭 열기·포커스 변경은 없다. 기존 수동 선택·진행 중 교환을 거부하며, 원본 규칙에 맞는 선택과 종류별 1개 보존·총 10개·교환 1회를 재검사한다. 옵션·그룹·선택 fingerprint 변경도 차단한다.

성공은 새로 생성된 정확히 하나의 교환 handle과 원본 ExchangeRoutine 콜백·선택 재료의 일치를 확인한 뒤 집계한다. 래퍼는 원본 콜백을 한 번 실행하고 결과를 기록한다. 성공 결과와 교환 종료를 모두 관찰해야 완료다. 빈 슬롯만으로 추정하지 않는다.

가능 횟수는 원본 `GetDuplicateItems(true)`, 교환 가능 여부, 10개짜리 레시피를 사용해 현재 그룹의 품질별 여분을 합산한 뒤 각 품질에서 10으로 나눈 정수 합이다. 선택 배치의 `_possibleExchanges`와 다르다. 아직 받지 않은 보상을 미리 포함하지 않고 결과 이후 다시 계산한다.

## 로컬 앱 빌드와 사용

```powershell
.\packaging\build.ps1 -Python <Python-3.13-python.exe> -AllowUnsigned -OutputRoot dist/item-auto-merge-local
```

dev19 배포 빌드는 게임 파일 없이 자체 Bridge.cs와 메타데이터 검사 도구 MergePrepare.exe·Mono.Cecil·지원 해시 계약을 포함한다. 첫 연결 시 Windows .NET Framework C# 도구로 검증된 로컬 게임 메타데이터를 참조해 자체 모듈을 컴파일한다. 지원 파일 12개의 해시·소스·준비 도구 해시를 검증하며, 컴파일 후 제거된 런타임 API 참조를 검사한 뒤에만 로드한다. 게임 DLL은 배포하지 않는다. .NET 도구 누락·준비 실패는 UI에서 안내한다. PowerShell 7은 사용자 연결에 필요하지 않다. 같은 게임 수명·동일 소스의 기존 세션만 재사용한다.

이 작업의 실행 파일은 `dist/item-auto-merge-local/BongoCatChat/versions/0.1.0.dev18/BongoCatChatApp/BongoCatChatApp.exe`다. 기존 공개 설치본을 교체하지 않았고 새 릴리스로 게시하지 않았다. 로컬 개발 파일이며 Windows 서명은 없다.

세션은 `%USERPROFILE%\.bongo-cat-chat\merge-bridge\<PID>-<생성시각>`에 보관한다. 앱과 게임에서 같은 경로를 볼 수 있고, 현재 사용자와 SYSTEM만 허용하는 ACL로 디렉터리를 생성한다. 설치 시도 표시가 있으면 자동 재설치하지 않는다. 정상 기존 세션은 파일 해시·생성 시각·snapshot을 재검증해 재사용한다. 이전 모듈이 확실히 해제된 상태만 새 모듈 연결을 허용하며 활성·미확인 모듈은 거부한다.

## 과거 개발 시험 도구

현재 지원 계약은 Windows x64, 조사한 build 25936063 + 기존 Auto Chest 조합만 허용한다. 게임 바이너리와 개인 IPC 파일은 커밋·배포하지 않는다. 아래 도구는 과거 시험용이며 일반 사용은 앱의 연결 버튼으로 진행한다. **현재 후속 작업에서는 실제 소비 시험을 추가하지 않는다.**

```powershell
.\tools\merge_bridge\build.ps1
python tools/merge_bridge/install.py --install --test-budget 0
python -m bongo_chat --merge-bridge-session <출력된 세션 경로>
python tools/merge_bridge/client.py --session <세션 경로> read
python tools/merge_bridge/client.py --session <세션 경로> shutdown
```

빌드는 .NET Framework C# 컴파일러와 로컬 Mono.Cecil, 설치 도구는 개발 환경의 pefile·psutil·PowerShell 7을 사용한다. 게임을 재시작하거나 설치 게임 DLL을 고치지 않는다. 검증한 자체 DLL 내용을 Mono에 로드한다. 불명확한 설치를 자동 재시도하거나 완료되지 않은 원격 스레드의 메모리를 해제하지 않는다.

이 PC의 게임은 AppData에 만든 세션 경로를 찾지 못했다. 공유 작업 폴더 `research/private/merge-bridge-session/`로 옮긴 뒤 초기화·IPC가 작동했다. MSIX 경로 가상화 가능성이 있으나 그 원인을 확정하지 않았다. 배포용 저장 위치는 별도로 검증해야 한다.

shutdown은 처리기를 제거한다. 미확인·진행 중 교환이 있으면 거부한다. 관리 어셈블리는 게임 종료 때까지 메모리에 남을 수 있다. 같은 게임 수명에서 재연결해 소비 예산을 초기화하지 않는다. 세션·ledger·시도 기록을 보존하고 게임 종료·기존 자동화 변경은 별도 범위다.

## 실제 검증

| 항목 | 결과 |
| --- | --- |
| 최초 조회 | 캐릭터·모자·봉고 180회 / 이모티콘·UI 테마 193회 |
| 보호 설정 | 즐겨찾기 포함 꺼짐, 이벤트 제외 켜짐 |
| 이모티콘·UI 테마 | 10개 선택 → 1회 요청 → 해당 콜백 성공·교환 종료, 이후 가능 192회 |
| 캐릭터·모자·봉고 | 첫 요청 완료 후 10개 선택 → 1회 요청 → 해당 콜백 성공·교환 종료, 이후 가능 180회 |
| 최종 상태 | 요청 2회, 확인된 완료 2회, 선택 재료 0개, 대기 교환 0개, 처리기 해제 |
| 화면 상태 | 모든 명령 관측에서 수동 합성 화면 닫힘 |

가능 횟수는 새 재고를 품질별로 계산한 값이며 완료 수의 단순 차감과 구분한다. 두 번째 그룹의 총 가능 횟수가 그대로인 세부 재고 변동 원인은 추적하지 않았다. 보상 종류·개별 아이템 수량의 독립 전후 대조나 실제 팝업의 육안 확인은 아니다. 성공 판정은 연결된 원본 교환 콜백과 종료 상태를 근거로 한다.

실제 호출 DLL SHA-256은 `649648CB66F75EF236352B95E5C74D165F29DC9298227D66E8843CB565DA0CFC`다. 이후 소스에 요청의 기대 그룹·옵션 검사, 일시적인 snapshot 파일 공유 충돌 복구를 보강했다. 후속 소스는 합성 자료·컴파일·별도 런타임으로 검사하며 실제 소비 예산을 재사용하지 않는다.

집중 Python/Qt 검사 83개, C# 가짜 게임의 25개 확인, 기존 기능 회귀 145개가 통과했다. Python 검사에는 native bootstrap 정상·실패 경로 8개, 파일 IPC 작업자에서 단일 합성 두 번 후 시험 예산으로 중단하는 검사가 포함된다. 후속 연결 작업자·UI·번역 변경 뒤 해당 29개 검사를 다시 통과했다(앞선 결과와 합산하지 않음). 같은 Mono 런타임의 별도 프로세스에서도 모듈 로딩·Install이 통과했다. Qt offscreen GPU 진단은 페이지 JavaScript 오류와 구분한다.

별도 Playwright/Chrome에서 1240×840 및 400×500, 그룹 선택에 따른 상한 초기화·최대값 입력·접힌 사이드바 중지·한영 전환·초안 보존을 확인했다. 스크린샷도 확인했으며 가로 넘침과 페이지 콘솔 오류는 없었다. 이 화면의 수량과 이용자는 합성 자료다. 마지막 읽기 전용 확인에서 게임 관련 12개 파일 해시는 모두 그대로였고, 게임은 실행 중이며 종료 snapshot의 generation 540·소비 ledger 2·완료 2·선택 0·대기 0이 유지됐다.

## dev19 출하 준비 보완

배포 환경에 게임 파일을 올리지 않기 위해 연결 시 로컬 메타데이터 참조 컴파일로 전환했다. 이 준비 경로는 게임 파일을 읽기만 하고 자체 DLL만 생성한다. 실제 설치 파일 집합으로 컴파일·참조 검사 후 별도 Mono 프로세스의 Install이 성공했다. 실행 중인 실제 게임의 기존 모듈·ledger를 바꾸거나 추가 소비를 요청하지 않았다. CI에서는 모의 C# 게임으로 실행 상한·중지·순번 재전송 방지를 검사한다. 새 게임 수명에서 dev19 연결의 실제 인수는 기존 연결 검증과 구분한다.

PR #44 검수에서 준비 실패 후 재연결을 막는 잔여 폴더를 보완했다. 새로 만든 폴더에서 컴파일·메타데이터 재검사가 실패하고 자체 DLL 외 파일이 없을 때만 자체 파일과 빈 폴더를 정리한다. 연결 시도·설정·ledger 또는 알 수 없는 파일이 있으면 그대로 보존한다. 관련 준비·연결·bootstrap 회귀 22개를 통과했고 실제 게임 연결이나 소비를 추가하지 않았다.

## 표시 동작

발신자의 현재 닉네임도 고양이 아래 이름표에 함께 표시한다. 글자 크기는 11px, 이름표는 최대 너비 112px·높이 22px의 한 줄이며 긴 이름은 말줄임표로 표시한다. 글자 수를 기준으로 자르지 않아 한글·영문 이름에도 같은 화면 상한이 적용된다. 닉네임은 텍스트로 표시하고 별도 툴팁·클릭 동작 없이 반응과 함께 사라진다.

게임에서 받은 클릭 울음과 이모티콘 아이템을 현재 로비의 대화 영역 아래에서 위로 띄운다. 발신자의 현재 스킨·모자를 합성한 고양이와 울음 말풍선 또는 실제 아이템 아이콘이 함께 움직이고 최대 2.2초 안에 사라진다. 상한에 도달하면 오래된 반응은 더 일찍 제거될 수 있다. 고양이는 기존 프로필과 같은 정지 외형이며 게임의 봉고 장식·동작 전체를 복제하지 않는다.

같은 발신자의 반복 입력도 별개 파티클이다. 횟수 배지나 `×N`으로 합치지 않는다. 반응은 메시지 목록·SQLite·검색·미저장 기록·새 메시지 표시·작업 표시줄 깜빡임·Windows 토스트로 전달하지 않는다. 기존 클릭 울음 기록의 숨김 정책도 유지한다. 정확히 같은 울음 문구를 직접 입력한 경우와 자동 클릭 울음은 게임 패킷만으로 구분할 수 없다.

대화 스크롤 바깥의 겹침 레이어에 표시하며 입력·클릭을 가로채지 않는다. 대화 영역 너비에 따라 동시에 8~24개까지 표시한다. 상한은 `min(24, max(8, floor(너비 / 70) * 2))`로 계산하며, 390px에서는 10개, 600px에서는 16개다. 유효한 새 반응이 도착했을 때 가득 차 있으면 가장 먼저 표시한 파티클과 그 정리 타이머를 제거한 뒤 새 반응을 즉시 추가한다. 창을 줄이면 다음 화면 조회에서 오래된 것부터 줄인 상한에 맞춘다. 사용자별 제한이나 재생 대기열은 만들지 않는다. 움직임 줄이기 설정에서는 아래쪽에서 짧게 나타났다 사라진다. 검색·보관 로비·숨겨진 창에서는 반응을 재생하지 않는다.

dev14의 4~12개 상한과 새 입력 폐기 정책은 연속 입력 중 기존 파티클이 사라질 때까지 표시가 끊기는 원인이었다. 후속 소스는 상한을 두 배로 늘리고 최신 입력을 우선한다. 화면 조회 주기 600ms는 유지하므로 같은 조회에서 받은 반응은 함께 나타날 수 있다.

## 반응 효과 ON/OFF

2026-10-23 후속 소스는 **설정 → 고양이 반응 효과 → 이모티콘·야옹 효과 표시**를 제공한다. 이 설정은 고양이와 함께 올라오는 이모티콘·클릭 울음 전체에 적용하며 기본값은 ON이다. 이 기기의 기존 SQLite `settings` 테이블에 bool `reactions_enabled`로 저장하고 앱을 다시 실행해도 유지한다. DB 스키마 변경이나 별도 마이그레이션은 없다.

- OFF를 선택하면 화면의 파티클과 정리 타이머를 즉시 제거한다. 저장에 성공하면 서비스의 대기 반응도 비우고 이후 반응을 폐기한다.
- ON으로 다시 바꾼 시각보다 먼저 수신한 반응은 자원 준비·프로세스 간 전달이 늦어져도 표시하지 않는다. 설정 변경 전의 늦은 화면 조회 응답도 무시한다.
- 저장 중에는 중복 조작을 막고 저장 성공 후 값을 확정한다. 실패하면 이전 설정과 체크 상태를 유지하고 오류를 표시한다. 시작 시 설정을 읽지 못하면 OFF 상태로 보류하며 저장소 복구 시 다시 읽는다. 키가 없는 기존 사용자만 기본 ON을 적용한다.
- 일반 대화 수신·저장, 메시지 알림, 초안·검색·스크롤과 게임의 반응 동작은 이 설정으로 변경하지 않는다. 아이템 송신이나 파일 업로드를 추가하는 기능이 아니다.

이 옵션은 앱 화면의 표시 설정이다. 게임 작업자의 패킷 수신·자원 준비를 중지하거나 게임에서 사용한 아이템을 취소하지 않는다. 공개 설치본 반영은 별도 배포 단계다.

## 확인한 게임 계약

설치 게임 빌드 `25936063`을 파일 읽기와 Steam 아이템 정의 조회로 확인했다. 게임 어셈블리를 실행하거나 수정하지 않았다.

- `SteamMultiplayer.SendEmote`는 아이템 정의 번호를 십진수 문자열로 바꿔 `Channel=6`, `Message`에 담는다. `OnLobbyChatMsg`의 대응 분기는 번호를 파싱해 `OnEmoteReceived`로 전달한다. 일반 문장과 클릭 울음은 `Channel=3`이다.
- `EmoteSpawner.SpawnMultiplayerEmote`는 해당 번호의 `SteamItemRuntime.Icon`을 표시한다. 런타임 생성자는 아이템 이름에서 ASCII 공백을 지우고 `Icon`을 붙여 스프라이트를 찾는다.
- 앱은 Steam 정의의 `tags`에서 `itemslot:emote` 또는 `itemslot:consumable`을 확인하고 `name`으로 같은 아이콘 이름을 구성한다. 실제 조회 표본은 `927`의 반짝임, `903`의 로켓, `456`의 새우, `457`의 화난 얼굴이었다. 숫자만 일치하는 모자나 상자는 표시하지 않는다.
- 설치된 `sharedassets0.assets`와 `resources.assets`에서 UnityPy로 PNG를 메모리에 만든다. 아이콘·게임 DLL을 앱에 복제해 배포하거나 원격 아이콘 URL을 불러오지 않는다. 알 수 없거나 중복된 이미지 이름, 지원 범위를 벗어난 이미지, 외형 조회 실패에는 대체 그림을 꾸며내지 않고 해당 반응을 생략한다.
- `feature-contract.json`에 다섯 번째 `reactions` 계약을 추가했다. 채널 6의 분기·패킷·아이템 번호·아이콘 연결 코드가 달라지면 기존 호환성 정책에 따라 연결을 보류한다. 네 개의 기존 계약 해시는 유지된다.

## 수신과 수명

콜백 소유 기간 안에 패킷을 복사한 뒤 `decode_event`에서 메시지와 반응을 분리한다. 현재 계정·로비·generation, 참여자 및 비숨김 집합의 기존 수신 경계를 그대로 거친다. 새 연결·숨김 해제 직후의 이전 콜백을 새 반응으로 재생하지 않는다.

`ReactionAssets`는 최대 24개까지 비동기 이미지 준비를 기다리되 수신 후 1.2초가 지나면 폐기한다. 목록이 가득 차면 가장 오래된 대기 항목을 제거하고 최신 입력을 보관한다. 매번 현재 프로필·숨김·연결을 다시 검사한다. 이미지 준비 지연으로 첫 반응이 생략될 수 있으며, 준비된 뒤 지난 반응을 재생하지 않는다. 별도의 반응 송신·아이템 사용 또는 소비 API는 없다.

`ChatService`의 메모리 전용 목록도 최신 24개를 유지한다. 중복·유효하지 않은 반응은 기존 항목을 교체하지 않는다. UI의 정규 조회가 한 번만 소비하며 전달 직전에도 유효기간과 숨김 상태를 확인한다. 로비 변경 때 폐기한다. 화면에서는 식별자 중복을 제거하고 `animationend` 또는 2.4초 정리 타이머로 요소를 제거한다. 숨김·퇴장·연결 단절·검색·방 이동·창 숨김은 표시 중인 요소도 제거한다.

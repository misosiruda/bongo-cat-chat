## 1단계: 설치 환경과 연결 수명주기 검증

목적은 기존 패치 환경에서 성공한 PoC가 일반 이용자의 환경에서도 성립하는지 확인하는 것이다. 기존 사용자 게임을 임의로 복구하거나 패치를 제거하지 않는다. 별도 순정 설치 환경 또는 사용자가 정한 시험 환경을 준비한다.

검증 항목:

- 순정 Bongo Cat, Steam 로그인, 실제 참여 로비에서 별도 프로그램이 초기화되는지 확인한다.
- 다른 계정·PC와 송수신을 비교한다. 게임만 설치한 상대의 화면에 같은 본문이 표시되는지 기록한다.
- Steam → 게임 → 앱, Steam → 앱 → 게임 등 시작 순서에 따른 상태를 기록한다.
- 앱 종료가 게임의 로비 참여를 해제하지 않는지 확인한다.
- 게임 종료, Steam 종료·재시작, 네트워크 단절과 복구, 로비 이동을 각각 확인한다.
- 계정 변경을 탐지하고 이전 계정의 연결·초안·기록이 잘못 연결되지 않도록 조건을 정한다.
- 확보한 읽기 전용 숨김 메모리 조회 후보의 제품 채택 여부와 순정 설치·재시작·업데이트 호환성을 확인한다. 게임 내부 구조에 의존하는 후보이며 공개 Steam 숨김 API를 확보한 것은 아니다.
- 숨김 전·후·해제 후를 비교하고 원시 수신, 게임 표시, 앱의 표시·저장 정책을 구분한다.
- 게임과 동일한 표시 이름을 얻는 경로와 현재 고양이 외형을 읽어 이미지로 보여주는 경로를 각각 확인한다. 스킨·장식의 데이터 조회와 썸네일 표시는 별도 검증하며, 이름·외형 변경 및 로비 이동 후 지연 응답을 시험한다.
- 시험 시간을 명시해 연속 수신을 관찰한다. 확인한 시간을 넘어 장기 안정성을 주장하지 않는다.

완료 조건은 시험 환경·게임 빌드·절차·관찰 결과가 남아 있고, 지원할 실행 조건과 지원하지 않는 조건을 설명할 수 있는 것이다. 실패한 환경은 결과에 포함한다. 순정 환경에서 경로가 성립하지 않으면 UI 개발 전에 원인과 대안을 검토한다.

로비 변경·사용자 숨김을 포함한 총 23개 시나리오는 [엣지 케이스 문서](edge-cases.md)를 기준으로 한다. 게임 숨김 자동 반영은 필수 조건이며, 경로를 확보하지 못하면 미충족으로 남긴다. 앱 자체 숨김 버튼·수동 목록을 만들거나 그것으로 자동 연동을 대체하지 않는다.

## 2단계: 제품용 전송 계층

PoC의 성공 경로를 [아키텍처 제안](architecture.md)의 연결·수신·송신 인터페이스로 정리한다. 런타임과 UI 프레임워크를 이 단계의 결과로 결정한다.

- 초기화·종료와 콜백 처리를 명시적으로 관리한다.
- 현재 계정과 로비가 확인된 경우에만 보내기를 허용한다.
- 수신 이벤트의 크기·타입·채널·발신자를 검사하고 채팅만 전달한다.
- 콜백 안에서 본문을 복사하고 앱 자체 수신 ID를 부여한다. Steam의 `m_iChatID`를 콜백 밖에 저장·전달하지 않는다.
- 관찰한 UTF-8 JSON 형식을 유지하고 게임의 실제 길이 제한을 추가 확인한다.
- 송신 직전에 로비를 다시 확인한다. 준비 시점과 달라졌으면 자동 송신하지 않는다.
- API 거부와 결과 불명을 구분하고, 결과 불명에 자동 재전송하지 않는다.
- 종료 시 앱 자신의 자원을 해제한다. 실제 게임이 참여한 로비를 나가는 동작을 종료 처리에 넣지 않는다.

완료 조건은 UI 없이도 명시적인 상태와 이벤트를 제공하고, 장애 시 보내기를 차단하며, 게임 파일 변경 없이 실행·종료되는 것이다. 의존 파일의 출처와 사용 방법도 기록한다.

## 3단계: 메시지 상태와 로컬 저장

- 자기 메시지를 즉시 추가하고, 실제 송신 결과와 자체 수신을 같은 항목에 반영한다.
- 같은 문장을 두 번 보낸 경우 두 메시지를 보존한다.
- 수신 콜백 중복과 실제 반복 발언을 구별하는 키를 검증한다.
- 계정·로비·연결 구간을 기준으로 기록을 분리한다.
- 앱 재시작 후 저장한 메시지를 읽고 검색한다.
- 저장 실패와 전송 실패를 별도로 표시한다.
- 기록 범위, 보관 기간, 삭제·내보내기 기본값을 결정한 뒤 반영한다.

완료 조건은 저장된 기록을 재시작 후 확인할 수 있고, 누락·중복·다른 방으로의 혼입을 시험한 결과가 남는 것이다. 수신하지 못한 구간을 완전한 대화 기록처럼 표시하지 않는다.

## 4단계: 메신저 UI

[제품 요구사항](product-spec.md)의 첫 화면 범위를 구현한다.

- 현재 계정·로비·연결 상태와 대화 목록을 표시한다.
- 사이드바 접기·펼치기를 구현하고 선택한 방·검색어·초안과 접힘 선호를 유지한다.
- 게임 표시 이름과 고양이 프로필을 표시한다. 조회 실패 때 임시 표시를 제공하고, 이전 계정·로비의 늦은 결과를 적용하지 않는다.
- Bongo Cat에서 설정한 사용자 숨김·해제를 자동 반영한다. 앱에는 해당 설정을 바꾸는 UI를 두지 않는다.
- 다른 이용자의 메시지와 자기 메시지를 구분한다.
- 한글 조합 중 Enter 입력, 줄바꿈, 붙여넣기를 시험하고 전송 키 동작을 정한다.
- 과거 기록 스크롤, 검색, 새 메시지 도착 시 스크롤 유지 동작을 구현한다.
- 보내기 대기·접수·실패·결과 불명을 설명한다. 읽음 확인으로 표시하지 않는다.
- 현재 방이 바뀌면 초안을 보존하되 새 방으로 자동 송신하지 않는다.
- 화면 읽기 순서, 키보드 이동, 배율 변경과 창 크기 변경을 점검한다.

완료 조건은 사용자가 게임 입력창을 거치지 않고 프로그램에서 읽고 보낼 수 있으며, 프로그램을 설치하지 않은 상대와의 실제 교환이 확인되는 것이다. 자기 메시지는 이 UI에 보이면 충분하다.

## 5단계: 배포 준비

2026-10-14 저장소 공개 전환과 [첫 개발판 릴리스](https://github.com/misosiruda/bongo-cat-chat/releases/tag/v0.1.0.dev6) 게시를 완료했다. 한국어 Windows 설치 파일·시작 메뉴·제거 목록·기존 설치 교체를 구현했으며 검사 범위는 [설치 검증 기록](installer-validation.md)에 구분한다. 공개 다운로드·다음 실행 적용의 결과는 [업데이트 검증](update-validation.md)에 기록한다.

- 지원 Windows·Steam·게임 조건과 설치·종료·삭제 방법을 문서화한다.
- 개발 도구가 없는 PC에서 설치 및 실행을 확인한다.
- 설치·실행·종료·삭제 전후 게임 파일이 변경되지 않았는지 검증한다.
- 프로그램 버전과 검증한 게임 빌드를 함께 표시한다.
- 외부 의존 파일 이용 조건, 이름·아이콘 사용, 공개 소스 라이선스를 결정한다.
- 개발자에게 전달할 설명 자료와 질문을 확정한다. 현재는 발송 전이다.
- [배포·개인정보 검토](distribution-and-privacy.md)의 미결 항목을 정리한다.

완료 조건은 패키지 자체의 동작과 배포 조건이 각각 확인되는 것이다. 문서 완성, 로컬 빌드, API 호출 성공만으로 일반 배포 완료로 처리하지 않는다.

| T-08 | 잘못된 UTF-8·JSON·알 수 없는 채널 | 안전하게 건너뛰고 나머지 수신 지속 | 잘못된 입력·다른 채널·콜백 복사 오프라인 검사 |

## 검증 자료를 만드는 방법

오프라인 검사는 식별정보 없는 [기준 데이터](evidence/2026-10-12-validation.json)의 한글 문장과 원본 바이트를 사용할 수 있다. 파서·길이 검증·메시지 상태 전이는 외부 송신 없이 시험한다. 제품 테스트 실행 결과는 원본 PoC·시안 검사와 구분해 기록한다.

온라인 시험은 범위가 정해진 시험 로비부터 진행한다. 실제 이용자 로비 송신은 해당 시험에 대한 사용자 요청에 따라 대상·본문·횟수를 제한한다. 이 문서 작성은 추가 송신이나 게임 재시작을 포함하지 않는다.

결과에는 날짜, 앱 버전·게임 빌드, 계정·PC 수, 실행 절차, 기대 결과와 관찰 결과를 남긴다. 상대 화면 확인, 사용자 보고, 자체 수신은 증거 유형을 구분한다. 공개 가능한 결과에는 다른 이용자의 원문과 계정·로비 식별정보를 넣지 않는다.

# Bongo Cat Chat 0.1.0.dev30

**상자·합성에 필요한 게임 파일을 연결 전에 확인하고, 파일 복구가 필요한 오류를 정확히 안내해요.** #58 제보자는 게임 재설치 후 연결이 해결됐다고 확인했어요. dev30은 같은 종류의 의존성 문제를 먼저 검사하고 사용자 조치를 구분해요. 특정 DLL의 누락이 제보 PC에서 직접 확인됐다는 뜻은 아니에요.

**[Windows 설치 파일 다운로드](https://github.com/misosiruda/bongo-cat-chat/releases/download/v0.1.0.dev30/BongoCatChat-0.1.0.dev30-windows-x64-Setup.exe)** · [English installation guide](#english)

## 처음 설치할 때

- **Windows 10/11 64비트(x64), Steam, Bongo Cat**이 필요해요. Python·개발 도구·관리자 권한은 필요하지 않아요.
- 다운로드할 파일은 **`BongoCatChat-0.1.0.dev30-windows-x64-Setup.exe`** 하나예요. `Source code` ZIP은 소스이고, `bongo-cat-chat-windows-x64.zip`은 앱 업데이트용이에요.

1. 실행 중인 Bongo Cat Chat이 있으면 종료하고 Setup.exe를 실행해요.
2. **다음 → 개인정보 처리 안내 확인 → 다음**으로 진행해요.
3. **GitHub 업데이트 확인 및 다운로드 허용** 여부를 선택해요. 해제해도 Steam 채팅과 수동 버그 제보는 사용할 수 있어요.
4. 설치 위치를 확인하고 **설치 → 마침**을 눌러요. 기본 위치는 `%LOCALAPPDATA%\Programs\BongoCatChat`이에요.
5. Steam에 로그인하고 Bongo Cat을 실행해 **게임 안에서 로비에 참여**해요. 시작 메뉴에서 **Bongo Cat Chat**을 실행해요.
6. 앱의 연결 상태와 로비를 확인하고 채팅해요. **Enter**로 전송하고 **Shift + Enter**로 줄을 바꿔요.

앱 언어는 **설정 → 언어 / Settings → Language**에서 한국어·English를 선택할 수 있어요. 설치 마법사는 한국어로 표시돼요. 상자 자동 개봉과 아이템 자동 합성은 선택 기능이며 채팅을 쓰기 위한 필수 설정이 아니에요.

## 기존 설치를 업데이트할 때

**설정 → 앱 업데이트 → 업데이트 확인**을 누르고 준비 완료 안내에 따라 앱을 다시 시작해요. GitHub 업데이트 통신을 꺼 뒀다면 켜거나, 앱을 종료하고 위 Setup.exe를 **기존 설치 폴더에** 실행해요. 먼저 제거할 필요 없이 대화·초안·설정·별명을 보존해요. 적용 후 설정에 **v0.1.0.dev30**이 표시되는지 확인해요.

자동화 진행 중이거나 결과를 기다리는 동안, 버그 제보 창을 열어 둔 동안에는 자동 업데이트 재시작을 보류해요. 저장한 **앱 실행 시 자동 개봉 시작** 설정은 유지되며, 켜 둔 경우 앱을 다시 열면 저장된 시작 동작이 적용될 수 있어요.

dev29에서 정상 연결 중이었다면 dev30 업데이트만을 위해 게임을 재설치할 필요는 없어요. 파일 누락·지원 파일 불일치·구성 요소 로드 실패 안내가 나오면 다음 순서로 진행해요.

1. **오류가 남아 있는 앱을 닫기 전에 버그 제보**로 진단을 전달해요.
2. 진행 중인 개봉·합성 결과를 확인하고 게임과 앱을 종료해요.
3. **Steam 라이브러리 → Bongo Cat 우클릭 → 속성 → 설치된 파일 → 게임 파일 무결성 확인**을 실행해요.
4. 복구가 끝나면 게임과 앱을 다시 열어 연결해요. 문제가 계속되면 게임 재설치를 시도해요.

파일 읽기 권한 오류는 게임 폴더의 읽기 권한을 먼저 확인해요. 지원 파일 불일치는 손상뿐 아니라 미지원 게임 버전일 수도 있으므로 앱 업데이트도 확인해요. 무결성 확인·재설치는 기존 모드나 도우미의 패치에 영향을 줄 수 있어요. 사용자가 진행하는 복구이며 앱이 게임 파일이나 기존 도우미 설정을 자동으로 바꾸지 않아요.

## 버그를 제보할 때

1. 오류가 나타난 뒤 앱을 종료하기 전에 **상자 자동 개봉 / 아이템 자동 합성 → 버그 제보**, 또는 **설정 → 문제 해결 → 버그 제보**를 눌러요.
2. **수집한 진단 보기**를 펼쳐 전송할 내용을 확인해요. 미리보기를 여는 것만으로 전송하지 않아요.
3. **GitHub에서 제보하기**를 눌러요. 기본 브라우저에 제목·진단 본문이 채워진 GitHub 이슈 작성 화면이 열리고, 이때 진단이 GitHub에 전달돼요.
4. GitHub에서 로그인하고 문제가 생긴 상황을 덧붙인 뒤 **등록(Submit new issue)**을 눌러요. 브라우저를 연 것만으로 접수가 완료되지는 않아요.

GitHub 계정이 없거나 브라우저를 열지 못하면 **진단 복사**로 같은 내용을 개발자에게 전달할 수 있어요. GitHub에 등록한 제보는 공개되므로 직접 덧붙이는 내용에도 개인 정보를 넣지 마세요.

진단에는 앱·Windows·Python 버전, 알려진 연결 상태·오류, 이번 앱 실행 중 최근 연결 실패 3회의 단계·초기화 결과와 확인 가능한 오류 번호가 들어가요. 초기화 세부 단계, 허용 목록에 있는 예외 종류 최대 3개와 고정된 실패 분류도 포함해요. 임의 예외 메시지는 제외해요. 확인된 게임 build 번호가 현재 상태에 있으면 함께 담아요. `attach_not_confirmed_no_retry`의 `status`·`stage`·`managed_exception` 등도 확인 가능한 범위에서 자동으로 담아요. 대화·초안·이름·Steam/로비 ID·파일 경로·프로세스 ID·연결 토큰·원본 로그·스택·소비 기록은 제외해요.

제보 버튼은 게임에 다시 연결하거나 상자·합성을 시작하지 않아요. 이전 앱 실행에서 사라진 상세 진단은 복원하지 못하므로, 업데이트 뒤 오류가 다시 발생하면 앱을 종료하기 전에 제보해 주세요. 연결 폴더나 `session.json`을 따로 찾거나 공유할 필요가 없어요. 기록이나 ledger를 삭제해 연결 제한을 해제하지 마세요.

## 변경 내용과 확인 범위

- 기본 게임 파일 `System.Numerics.dll`의 누락·읽기 실패·지원 파일 불일치를 게임 프로세스를 열기 전에 차단해요.
- 실행 중 타입 로드 실패는 `bridge_dependency_load_failed`로 구분하고 무결성 확인·필요시 재설치를 안내해요. 이 오류만으로 특정 파일이 없다고 단정하지 않아요.
- 기존 실패 기록과 미확인 결과를 보존하고, 실패한 모듈을 다시 로드하거나 소비 명령을 재전송하지 않아요.
- 합성 연결과 게임 파일 복사본에서 누락·변조·복원, 기록 보존, 한·영 상자/합성 안내를 검사했어요.
- 제보자의 재설치 후 복구는 사용자 확인이고, 격리 시험에서 특정 DLL을 제외해 같은 오류를 재현한 결과와 구분해요.
- 실제 상자 개봉·합성·포인트 소비, 실행 중 게임/기존 설치 변경, 실제 GitHub 제보 등록은 검사에서 수행하지 않았어요.

## English

**dev30 checks a required game dependency before connecting and provides specific repair guidance.** The user confirmed that reinstalling Bongo Cat resolved the connection reported in #58. This does not prove which file was missing or damaged on that PC.

**[Download BongoCatChat-0.1.0.dev30-windows-x64-Setup.exe](https://github.com/misosiruda/bongo-cat-chat/releases/download/v0.1.0.dev30/BongoCatChat-0.1.0.dev30-windows-x64-Setup.exe)**

### First installation

You need **Windows 10/11 x64, Steam and Bongo Cat**. Python, developer tools and administrator privileges are not required. Download only the Setup.exe above; the source ZIP is source code, and `bongo-cat-chat-windows-x64.zip` is for the app updater.

1. Close any running Bongo Cat Chat and launch Setup.exe.
2. The installer is in Korean. Choose **다음 (Next)**, read the privacy notice, then choose **다음 (Next)**.
3. Choose whether to allow **GitHub 업데이트 확인 및 다운로드 허용 (GitHub update checks and downloads)**. Chat and manual bug reporting still work if you turn this off.
4. Confirm the install folder and choose **설치 (Install) → 마침 (Finish)**. The default is `%LOCALAPPDATA%\Programs\BongoCatChat`.
5. Sign in to Steam, launch Bongo Cat and **join a lobby in the game**. Open **Bongo Cat Chat** from the Start menu.
6. Check the connection and lobby, then chat. **Enter** sends; **Shift + Enter** inserts a line break. Choose English in **설정 → 언어 / Settings → Language** if needed.

Automatic chest opening and item merging are optional and are not required for chat.

### Updating an existing installation

Use **Settings → App updates → Check for updates**, then follow the app restart prompt. If GitHub update access is disabled, enable it or close the app and run Setup.exe into the **existing install folder**. Uninstalling first is unnecessary. History, drafts, preferences and nicknames are preserved. Confirm **v0.1.0.dev30** in Settings.

Active automation, pending/unverified results and an open bug report window postpone automatic update restart. Saved **Start automatic chest opening when the app launches** consent is preserved and may start the configured automation when the app relaunches.

A healthy dev29 connection does not require reinstalling the game just to update to dev30. If the app reports a missing or incompatible dependency, or a component load failure:

1. **Report the bug before closing the app**, while diagnostics are still available.
2. Check pending chest/merge results, then close the game and app.
3. In **Steam Library → right-click Bongo Cat → Properties → Installed Files → Verify integrity of game files**, run the repair check.
4. Reopen the game and app after repair. If the issue persists, try reinstalling the game.

For a read-access error, check access to the game folder first. An incompatible file can also mean an unsupported game update, so check for an app update. Verification or reinstallation may affect existing mod/helper patches. These are user actions; the app does not repair game files or change the existing helper automatically.

### Reporting a bug

1. After the error, before closing the app, choose **Report a bug** in the chest/merge panel or **Settings → Troubleshooting → Report a bug**.
2. Expand **View collected diagnostics** to review the content. Previewing alone does not send it.
3. Choose **Report on GitHub**. Your default browser opens a draft with its title and diagnostics filled in; diagnostics are sent to GitHub at this point.
4. Sign in, add what happened and choose **Submit new issue**. Opening the browser does not finish submission.

Without a GitHub account, or if the browser cannot open, choose **Copy diagnostics** and share the report with the developer. Submitted issues are public; do not add personal information.

The report contains app/Windows/Python versions, known connection states/errors and allowlisted initialization results from the last three failed connections during this app session. A known game build is included when available. This includes `status`, `stage`, `managed_exception`, a known initialization step, up to three allowlisted exception types and fixed failure classifications when available. Arbitrary exception messages are excluded. Known type/assembly load failures are reported as `bridge_dependency_load_failed`; other initialization exceptions remain `bridge_initialization_failed`. Chat, drafts, names, Steam/lobby IDs, paths, process IDs, connection tokens, raw logs, stacks and consumption records are excluded.

The report button does not reconnect, open chests or merge items. Diagnostics lost from an earlier app session cannot be reconstructed. Report a recurring error before closing the updated app. You do not need to find or share the connection folder or `session.json`. Do not delete records or ledgers to bypass connection guards.

Validation uses synthetic connections and offline Qt tests. No real items/chests/points were consumed, no running game or existing user installation was changed, and no live GitHub issue was submitted. The user confirmed recovery after a game reinstall; the exact changed file on that PC remains unconfirmed. The isolated reproduction and dependency preflight checks are documented separately. [Validation](https://github.com/misosiruda/bongo-cat-chat/blob/v0.1.0.dev30/docs/product-validation.md)

This development installer is **not Windows Authenticode-signed**. Download it from the official GitHub release. Automatic updates verify separate Ed25519 signatures. Received messages are kept locally for 30 days by default; uninstalling preserves records and settings.

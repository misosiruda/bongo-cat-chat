# 상자·합성 기능 호환성

2026-11-05, dev26 개발 소스는 상자·합성의 공통 설치 검사를 기능 계약으로 전환한다. 이전 전체 게임 파일 프로필과 `ChestRuntime`의 별도 Assembly-CSharp 해시 목록은 사용하지 않는다. 게임 build 26431657에서 Assembly-CSharp와 System.Core의 전체 해시가 달라 연결 전에 차단되던 문제를 다룬다.

## 검사 범위

2026-11-09 dev30부터 JSON 읽기에 필요한 `System.Numerics.dll`도 필수 의존성으로 검사한다. 누락·읽기 실패·지원 파일 불일치를 연결 전 차단하고, 실행 중 타입 로드 실패에는 파일 복구 안내를 제공한다. 사용자 재설치로 해결된 #58과 격리 재현의 증거·한계는 [의존성 검사 기록](issue-58-dependencies.md)을 따른다.

단일 원본은 `tools/merge_bridge/local-contract.json`이다. 빌드할 때 이 계약에서 읽기 전용 검사기의 입력과 무결성 해시를 생성한다. 제품 연결·개발용 컴파일·개발용 설치는 같은 검증 함수를 사용한다.

- **합성:** ItemExchange, AutoExchanger, SteamItemRuntime, 교환 규칙·슬롯, 보호 옵션, 선택·원본 교환·결과 콜백을 포함한다. 연결 모듈이 직접 사용하는 LINQ와 HashSet도 명시한다.
- **상자:** Shop, ShopItem, ChestExchanger, 다른 참여자 상자 버튼과 활성 상태를 포함한다. 차감·보상·재시도 코드와 관련 콜백을 함께 검사한다.
- **인벤토리:** CatInventory의 준비·조회·갱신 및 관련 경로를 검사한다.

선택한 타입의 필드·중첩 타입·메서드 전체와 Assembly-CSharp/System.Core 안의 호출 의존성을 정규화한다. 생성된 콜백·상태 머신, 생성자의 가상 메서드, 정적 초기화, 인터페이스·제네릭 제약, 지역 변수와 예외 처리 영역도 포함한다. 메타데이터 토큰·RVA·MVID·파일 배치만 달라진 것은 기능 변경으로 취급하지 않는다. 미지원 참조나 읽기 실패는 통과시키지 않는다. 검사기는 게임 어셈블리를 실행하지 않는다.

Mono·Steam 네이티브, Unity와 검증 범위 밖 관리 의존성은 파일 해시를 유지한다. 기존 BongoAutoChest는 검토한 파일 또는 부재만 허용한다. 검사기가 실제로 참조하는 외부 어셈블리가 계약에 빠졌으면 거부한다. 무관한 게임 변경을 허용하는 범위이며 모든 런타임·모드 업데이트를 자동 승인하는 것은 아니다. 오래된 전체 파일 프로필이 있었다는 이유만으로 확인하지 않은 기능 지문을 승인하지 않는다.

## 검사와 실제 연결의 일치

검사 전후, 컴파일 전후, 연결 직전에 실제 입력 해시를 대조한다. 이 해시는 해당 연결을 검증한 파일에 묶는 값이며 별도의 지원 목록이 아니다. 검사한 관리 어셈블리의 MVID를 세션에 넣고 연결 모듈에서 현재 로드된 어셈블리와 대조한다. 디스크만 갱신되고 게임은 이전 모듈을 쓰는 경우를 차단한다. 게임의 경량 런타임에 남아 있는 `Assembly.GetModules()`/`ModuleVersionId` API로 구현하며 컴파일 후 모든 참조를 실제 설치 메타데이터에서 해석한다.

연결만으로 소비 권한이 생기지 않는다. 처음 허용량 0, 사용자 시작·저장한 상자 자동 시작 설정, 기존 도우미 전환 확인, 계정·프로세스 수명, 결과 미확인 보호, 중복 소비 재전송 금지는 유지한다. 이미 로드된 구버전 연결 모듈을 교체하지 않는다.

## 소비 없는 검증

- 현재 설치의 세 기능 지문이 계약과 일치하고 연결 모듈 컴파일·경량 런타임 참조 확인이 통과했다. 모듈을 게임에 로드하지 않았다.
- 이전에 확인한 순정 Assembly-CSharp 백업을 **현재 의존성**과 조합해 읽었을 때 세 기능 지문이 현재와 같았다. 예전 System.Core 원본은 없어 이전 설치 전체의 동일성을 주장하지 않는다.
- 선택된 그래프는 700·892·938개 메서드이며 PawPass는 포함되지 않는다. [식별정보 없는 정적 근거](evidence/2026-11-05-automation-feature-compatibility.json)를 참고한다.
- 독립 합성 DLL에서 무관한 코드·메타데이터 변경을 허용하고, 보호 필드·결과 콜백·가상 반복자·정적 초기화·예외 처리 변경과 미검증 의존성을 차단한다.
- 모의 게임/IPC는 기존 복구·중지·미확인 결과·단일 소비 보호를 검사한다. 모의 아이템 수치는 실제 게임 소비가 아니다.

실제 개봉·합성·포인트 소비 시험, 게임 재시작·파일 변경, 실행 중 모듈 교체는 0회다. 실제 최소화·장시간 연결 유지와 다른 PC의 인수는 별도다.

## 2026-11-10 build 26538670 지원

dev30 계약으로 현재 설치를 읽기 전용 검사해 `unsupported_automation_features`를 재현했다. 네이티브·관리 의존성 검사는 통과했으며 상자 지문만 달랐다. dev31은 기존 프로필을 보존하고 검토한 새 상자·합성·인벤토리 조합을 별도 프로필로 추가한다. 검사 알고리즘과 보호 범위를 축소하지 않는다.

이전 로컬 IL 기록과 현재 메타데이터를 비교했다. 선택 그래프에서 자동 생성 이름의 번호 이동을 분석용으로 정규화하면 새 `Shop.get_ShowChestSetting`, `Shop.get_CanGetShownChest`와 기존 `Shop.get_ShowChest` 변경이 확인된다. 일반 상자도 `ShowCosmeticChest` 설정을 사용하는 표시 정책 변경이다. 선택 기록에 이 필드와 두 접근자의 메서드·시그니처 기록이 추가됐고 제거된 기록은 없다. 이 이름 정규화는 분석에만 사용하며 제품 검사기는 원래의 엄격한 지문을 유지한다.

합성·인벤토리는 제품 검사기의 전체 기능 지문이 기존과 일치한다. 상자의 원본 구매·차감·결과 처리 및 연결 모듈이 사용하는 필드·메서드는 비교한 IL에서 유지됐다. 연결 모듈은 기존과 같이 준비 상태·앱의 사용자 선택·아이템 활성 상태·구매 가능 여부를 검사한다. 게임의 새 표시 설정을 자동 소비 권한으로 취급하지 않는다.

이전 자료는 IL·선택 키 기록이므로 과거 바이너리 전체나 모든 메타데이터의 의미 동등성을 증명하지 않는다. 현재 메타데이터를 사용한 실제 검사·컴파일·참조 해석과 모의 보호 검증을 별도로 수행한다. [정적 검사 근거](evidence/2026-11-10-automation-compatibility.json)에 결과를 기록한다. 실행 중 게임·사용 설치본 변경, 모듈 로드, 실제 소비 시험은 수행하지 않는다.

로컬 검증은 자동화 연결·상자·합성 테스트 245개와 기능 검사기·패키징·배포 테스트 60개가 통과했다. 기존/신규 프로필 허용, 알 수 없는 기능 변경 거부, 다른 프로필의 의존성 조합을 빌려 통과하지 못하는 회귀 검사를 포함한다. 최초 기능 검사기 21개는 컴파일 셸이 로드한 Mono.Cecil 파일 잠금으로 준비 실패했고, 그 셸 종료 후 별도 프로세스에서 모두 통과했다. 변경이 지원 프로필·버전에 한정되어 관련 소비자와 패키징을 선택했으며, 로컬 전체 스위트와 원격 CI는 실행하지 않았다.

# 상자 자동 개봉 통합

dev26부터 상자·합성·인벤토리 공통 기능 계약으로 연결 호환성을 검사한다. 상자 내부의 별도 전체 DLL 해시 제한은 제거했다. 연결·시작·기존 도우미 전환·결과 미확인 보호는 유지한다. [호환성 검사와 소비 없는 검증](automation-feature-compatibility.md)을 참고한다.

2026-11-05 / `0.1.0.dev25` 소스. 앱 실행 시 자동 시작과 연결 끊김 예방·자동 복구를 포함한다. 공개 상태는 최신 릴리스에서 확인한다. 이전 상자/합성 연결을 사용했다면 업데이트 후 게임을 직접 한 번 재실행해 새 모듈을 적용한다. 실제 게임 개봉 인수는 미수행이다. 사용자는 내/다른 사람 상자·대기 시간·단축키를 기존 앱에 흡수하는 방향을 승인했다. 개발 과정에서는 실제 개봉·포인트 소비·게임 재시작·기존 설치 변경을 수행하지 않는다.

## 사용 흐름

1. 사이드바의 **상자 자동 개봉**을 연다.
2. **내 상자 자동 개봉**(기본 ON), **다른 사람의 상자도 개봉**(기본 OFF), 최소·최대 대기 시간을 선택하고 **설정 저장**을 누른다. 1~300초 범위이며 최소가 최대보다 크면 저장하지 않는다. 다른 사람 상자는 내 포인트를 소비한다.
3. 다음 실행에도 자동으로 사용하려면 **앱 실행 시 자동 개봉 시작**을 켜고 **설정 저장**한다. 기본 OFF다. 저장 직후에는 시작하지 않으며 다음 앱 실행에서 게임 연결이 준비되면 한 번 연결·시작한다.
4. 수동으로 시작하려면 **게임에 연결**한다. 자동 합성과 같은 자체 연결 모듈을 사용한다. 자동 시작을 선택하지 않았다면 연결·설정 저장만으로 상자를 열지 않는다.
5. 기존 Auto Chest가 감지되면 **기존 도우미의 자동 개봉을 이번 게임 실행 동안 중지하고 전환**을 확인한다. 기존 개봉이 진행 중이면 전환하지 않는다. 공유 게임 연결이 바뀌면 전환 체크를 해제하며 자동 합성 패널에서 재연결한 경우에도 새 확인이 필요하다.
6. **자동 개봉 시작**을 누른다. 패널을 닫아도 실행하며 패널·사이드바의 **중지**는 새 요청을 막는다. 이미 게임이 접수한 요청의 취소는 보장하지 않는다.
7. 시작한 세션에서는 **Ctrl+Alt+F9**로 일시 정지·재개한다. 중지·재연결 이후에는 시작 버튼을 다시 눌러야 한다. 앱 재실행 시에는 저장한 자동 시작 설정을 따른다. 단축키가 새 실행을 허가하지 않는다.

내 일반/감정표현 상자를 우선한다. 발견 후 대기와 개봉 간 대기는 같은 무작위 범위를 사용하며 겹쳐 진행한다. 원본 도우미의 대기 모델과 같다. 준비 상태 하나당 요청은 한 번이며 실제 not-ready 관측 후 새 ready 구간에서만 다시 요청한다. 다른 사람 상자는 현재 로비·다른 계정·현재 참가자·게임 숨김·활성 버튼·보이는 상자를 재검사한다. 준비 상태가 불명확하면 요청하지 않는다.

## 실행·결과 처리

`Controller → AutoChest → MergeConnection → BridgeAdapter → 고정 파일 IPC → Unity 메인 스레드 ChestRuntime` 경로다. 저장된 설정에는 실행 상태인 enabled/armed 플래그가 없으며 별도의 `start_on_launch` 동의만 저장한다. 기존 4개 설정은 자동 시작 OFF로 읽는다. 옵션과 상자·대기 설정은 하나의 SQLite 값으로 함께 저장하고 저장 실패 시 이전 설정을 유지한다. 자동 시작은 앱 수명당 한 번만 시도하며 연결 실패·오래된/미확인 상태·동시 합성·수동 재연결·중지·종료 시 취소한다. 오프라인·읽기 전용 실행에서는 자동 연결하지 않는다. 기존 도우미가 있으면 이번 게임의 확인과 수동 시작을 기다린다. 중지는 자동 시작 대기도 취소하지만 다음 앱 실행을 위한 저장 설정은 유지한다. 시작 시 설정 전체를 검증하고 적용한다. 실행 중 설정 변경은 거부한다. 재연결은 이전 실행의 lease를 인계하지 않으며 기존 armed 상태에는 stop만 보낸다.

내 상자는 원본 `ChestExchanger.OpenChest(Action<int>)`를 호출하고 요청에 연결된 래퍼에서 원본 `ShopItem.Callback(itemId, true)`를 한 번 실행한 뒤 완료/실패를 기록한다. 원본 `Buy`의 입력 준비에 해당하는 대기 플래그·로딩 표시를 연동하지만 게임 DLL·콜백 본문은 패치하지 않는다. 게임의 토큰·비용·보상·원본 재시도 규칙은 그대로다. 화면 변화·포인트 변화·빈 슬롯을 완료로 추정하지 않는다. 콜백을 받지 못하거나 처리에 실패하면 미확인 상태로 멈추며 같은 게임 수명에서 재시작하지 않는다. 늦은 콜백을 받더라도 미확인 상태를 자동 해제하지 않는다. 결과를 게임에서 확인한 뒤 게임과 앱을 모두 직접 다시 실행해 새 세션으로 복구한다.

다른 사람 상자는 원본 `OpenChestForMember.OnClicked()`를 사용한다. `_hasClicked`가 설정됐을 때 **요청**으로만 센다. 상대방 보상 수령 확인으로 표시하지 않는다. 버튼 reset은 실제 준비 해제를 관측한 뒤에만 수행한다.

앱이 시작한 실행에만 0.75초 간격 heartbeat를 보내며 게임 측 lease는 3초다. stop이 전달되지 못해도 마지막 heartbeat 이후 최대 3초의 lease가 만료되면 새 요청을 보류한다. 11월 5일 소스에서는 동일 앱·게임·계정의 실행이 유지되는 일시적인 통신 장애에 한해 신선한 heartbeat로 계속 진행한다. 사용자 중지·앱 종료·대상 변경·결과 미확인은 자동 재개하지 않는다. 중지 중에도 접수된 요청의 결과는 유지한다. 진행·대기·미확인은 자동 업데이트 재시작을 막는다. 자동 합성과 자동 개봉은 한 번에 하나만 실행한다.

## 연결 상태 오류 복구

dev23 작업 당시 실제 세션 읽기 전용 20초 관측에서는 99개의 신선한 snapshot이 계속 갱신됐지만 `bridge_observation_failed`가 남아 ready=false였다. 이는 모듈 종료나 snapshot 만료와 다르다. 모의 게임에서 인벤토리 FetchingItems를 잠깐 켰다 정상으로 되돌려도 오류가 남는 경로를 재현했다. dev23은 정상 RequireGame 검증 후 해당 일시 조회 오류만 해제했으며, 명령 실패·미확인 결과·중지된 자동화는 자동 재개하지 않았다. 이 관측만으로 모든 끊김 원인을 확정하지 않는다. 후속 자동 복구와 예방 변경은 아래에 구분한다.

### 2026-11-05 연결 자동 복구

후속 사용자 지시로 위 dev23의 **일시 장애 뒤 수동 재시작** 정책을 변경한다. 이미 시작한 실행은 인벤토리 갱신 중에는 `인벤토리 갱신 대기 중`, 통신 장애에는 `연결 복구 대기 중`으로 표시한다. 복구 후 동일 게임·계정을 재검증하고 기존 설정으로 계속 실행한다. 사용자 중지·앱 종료·결과 미확인·기존 도우미 재활성화는 자동 재개하지 않는다.

인벤토리 조회가 불가능해도 모듈은 신선한 연결 상태와 상자 상태를 발행한다. heartbeat는 인벤토리 검사를 요구하지 않는다. 3초 lease가 만료되면 새 요청을 보류하고, 같은 앱이 소유한 실행 ID의 heartbeat가 돌아오면 진행한다. 일시 정지 설정은 보존하며 heartbeat 자체는 시작·사용자 중지를 되돌리지 않는다. 새 앱이나 수동 재연결은 이전 실행을 인계하지 않는다. 결과 대기 30초 제한은 조회 장애 중에도 유지한다.

통신 응답이 유실된 시작은 실행 ID가 일치하는 신선한 상태로만 확인한다. 이미 처리됐을 수 있는 명령은 재전송하지 않으며, 전송되지 않았거나 게임이 처리 전 보류했다고 명시한 요청만 재시도한다. 복구 대기 중 중지는 heartbeat와 미전송 시작을 취소한다. 실행 중 게임에 모듈을 교체하지 않았으므로 현재 설치본에는 아직 적용되지 않았다.

### 2026-11-05 연결 끊김 예방

복구와 별도로 연결을 불안정하게 만드는 네 경로를 변경했다.

- 첫 렌더 콜백에서 Unity 메인 스레드 컨텍스트를 확보한 뒤 주기 작업을 그 컨텍스트에 게시한다. 화면 렌더링이 계속되어야만 상태를 발행하던 구조를 없앴다. 타이머에서는 게임 API를 호출하지 않고 대기/진행 중 작업도 하나만 둔다.
- 0.75초 주기 heartbeat를 명령/응답과 별개의 파일로 전달한다. 이 신호는 RPC 응답을 기다리지 않으며 인벤토리/상태 조회 실패 중에도 동일 실행의 lease를 유지할 수 있다. 게임은 계정·세션·실행 ID, 증가하는 순번과 1.5초 이내 발행 시각을 확인하고 실제 신호 경과 시간을 lease에서 차감한다. 오래된 파일을 반복해서 읽어 lease를 연장하지 않는다.
- 양쪽 상태 파일 읽기에 삭제 공유를 허용하고 반복 가능한 상태·응답·heartbeat 파일 교체에 Windows `ReplaceFileW`를 사용한다. 열린 파일의 원래 내용은 유지하면서 다음 독자는 새 내용을 읽는다. 소비 명령·허가·ledger의 기존 발행 방식과 미확인 결과 보호는 유지한다.
- 상자가 실행·결과 대기·미확인 상태라 합성이 차단된 동안에는 합성 가능 수량의 전체 중복 아이템 조회를 생략한다. 개봉 전에 필요한 게임 상태 확인은 유지한다.

최초 연결에는 여전히 메인 스레드의 첫 렌더 콜백이 필요하다. 게임 메인 루프 전체 정지·PC 절전·게임 종료를 이 구조로 방지할 수는 없다. 렌더 없는 모의 루프와 파일 공유 검사는 통과했으며, 실제 최소화·장시간 실행 인수는 남아 있다. 근거와 최종 회귀 결과는 [제품 검증](product-validation.md)에 기록한다.

## 기존 도우미와 설치 전환

원본 소스는 로컬 `bongo-cat-auto-chest`의 MIT 코드와 동작을 참고했다. 원본 저장소의 미커밋 변경은 보존한다. 소스 출처·저작권은 `Bridge.cs`에 표시한다. 설치 마법사와 DLL 패치/복원 코드를 복사하지 않는다.

전환은 유휴 상태·기존 `OwnRequests` 0을 확인하고 검토한 기존 처리기의 런타임 `Faulted=true`, `Enabled=false`로 바꾼다. 이 상태는 게임 종료까지 유지하며 INI의 enabled 값을 가져와 자동 시작하지 않는다. 이후 기존 처리기의 재활성화를 감지하면 새 자동화를 멈춘다. 앱 중지/종료 시 기존 처리기를 자동으로 다시 켜지 않는다. 게임 재실행에는 기존 패치가 다시 동작할 수 있으며 다음 시작에 전환 상태를 다시 확인한다.

순정 파일 조합은 Auto Chest DLL 없이도 모듈을 컴파일할 수 있다. 기존 패치를 영구 제거하려면 사용자가 게임을 종료하고 원래 도우미의 원본 복원 또는 Steam 파일 무결성 확인을 사용한다. 앱이 게임을 종료하거나 패치를 복원하지 않는다. 영구 복원 뒤 실제 순정 설치 인수는 남아 있다.

## 호환성 근거

이번 PC의 현재 관리 DLL SHA-256은 `6756b1e864340170e8f312da1d935f9b644d442974c1434bbd0d7eb4a1ab8a2c`, 기존 helper는 `56b777433abcd863be74cce99c6d14e7aa5691a4feeae4303c8450a6da14a9e8`이다. 기록된 원본 백업 `3ae33d93def6346f715256d2b65192097632059252eed969c2641f63b946d4dd`과 모든 메서드 선언/IL을 비교했으며 차이는 기존 패치가 추가한 `MainCat.Update`·`ShopItem.Callback` 두 메서드뿐이었다. 배포사 원본 서명 검증은 아니다.

현재 게임의 `ItemExchange`·`SteamItemRuntime`·`AutoExchanger` 전체 타입 선언/IL은 이전 검토본 `25dbce06…` 원본 백업과 동일했다. 현재 상자 타입·원본 exchanger·준비 상태·가격 경로·비용/원격 요청을 정적으로 확인했다. 새 전체 파일 조합을 기존 자동 합성 프로필과 분리해 추가했다. 상자 runtime은 검토한 현재 patched/original 관리 DLL 두 해시만 지원한다. 이전 프로필의 자동 합성 지원을 상자 지원으로 확대하지 않는다.

계약 schema 5는 여전히 13개 경로의 전체 조합을 비교한다. 검토한 원본 관리 DLL 조합에서만 `BongoAutoChest.dll`의 명시적 `null`(파일 없음) 또는 이번에 검토한 helper 해시를 허용한다. 다른 필수 파일 누락·다른 helper·구신 임의 조합은 거부한다. 배포 준비·검증 도구도 같은 계약을 사용한다.

## 검증과 남은 인수

- 현재 설치 메타데이터만 참조한 C# 컴파일과 stripped runtime 멤버 참조 검사를 통과했다. 모듈을 실제 게임에 로드하지 않았다.
- C# 모의 게임에서 발견 대기·단일 요청·중복 콜백·실패·새 준비 구간·중지 중 결과 유지·단축키·lease 만료·단축키 재시작 금지·숨김 제외·원격 요청/재준비·기존 도우미 전환·기존 미처리 요청 차단·재활성화 중단·미확인 시간 초과를 검사한다.
- Python은 설정 형식·저장 실패·손상 설정·집계 데이터 제한·미확인/오래된 상태·자동 재연결 금지·heartbeat·종료 stop·순정 프로필을 검사한다. 실제 Qt renderer는 저장→연결→전환→시작→패널 닫기→사이드바 중지·영어 전환을 모의 IPC로 검사한다.
- 실제 개봉·포인트 전후·보상·다른 사람 화면·실제 단축키/최소화·실제 기존 도우미 전환·다른 PC·순정 신규 설치·장시간 실행은 미검증이다. 원본 게임의 내부 재시도까지 앱 요청 1회와 동일한 네트워크 시도 횟수로 보장하지 않는다.
- 게임 바이너리·디컴파일 원문·다른 이용자 식별자·개인 로그는 커밋/배포하지 않는다. 이번 소스 변경의 로컬 검증 수치는 `product-validation.md`에 기록한다.

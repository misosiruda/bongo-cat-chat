# 로비 입·퇴장 안내

2026-10-28 사용자 요청에 따른 후속 소스 구현이다. 카카오톡처럼 Bongo Cat 로비의 다른 참가자가 들어오거나 나가면 대화 사이에 가운데 정렬된 안내를 표시한다. 카카오톡 서비스와 연동하는 기능은 아니다. 공개 설치본 반영과 실제 게임 인수는 별도다.

## 표시와 기록

- 한국어: `OO님이 들어왔습니다.` / `OO님이 나갔습니다.`
- 영어: `OO joined the lobby.` / `OO left the lobby.`
- 안내에는 확인 당시 이름과 확인 시각을 표시한다. 이름은 번역하거나 HTML로 실행하지 않는다. 이후 이름이 바뀌어도 저장된 안내의 이름은 유지한다.
- 일반 말풍선·아바타·프로필 버튼·전송 상태는 붙이지 않는다. 로비로 채팅을 전송하지 않는다.
- 대화와 같은 순번으로 로컬에 30일 보관하고 이전 기록 조회·설정의 기록 삭제를 적용한다. 검색은 일반 대화 본문만 대상으로 한다.
- Windows 토스트·작업 표시줄 깜빡임·새 메시지 배지를 발생시키지 않는다. 맨 아래에서는 새 안내를 따라가고 과거 대화를 읽는 중에는 위치를 유지한다.
- 저장 실패 시 현재 연결에서만 미저장 안내를 표시한다. 미저장 목록은 기존 대화와 함께 최대 200개이며 자동 재저장하지 않는다.

## 감지 기준

`LiveConnection.snapshot()`의 검증된 실제 구성원 목록을 이전 표본과 비교한다. 프로필 캐시의 등장·삭제를 입·퇴장으로 사용하지 않는다. 원래의 상태 조회 주기를 유지하며 별도 Steam 콜백·게임 메모리 쓰기·로비 이동 API를 추가하지 않는다. 구성원 목록은 작업자와 서비스 사이의 내부 IPC에만 추가하고 UI 응답에는 노출하지 않는다.

1. 첫 연결, 계정·로비·연결 구간 변경, 연결 검증 또는 숨김 조회 실패, 2.5초 이상 상태 공백 이후의 첫 정상 표본은 기준으로만 삼는다. 기존 참가자의 입장이나 끊긴 동안의 퇴장을 생성하지 않는다. 자기 자신도 안내 대상에서 제외한다.
2. 연속된 정상 표본에서 새 구성원이 나타나면 입장 후보로 잡는다. 현재 비숨김과 이름을 모두 확인했을 때 한 번 기록한다. 새 참가자의 프로필/숨김 조회가 늦으면 최대 5초 기다린다. 숨김으로 확인되거나 퇴장하거나 시간이 만료되면 후보를 버린다.
3. 구성원이 사라지면 직전 정상 표본에서 확인한 이름을 사용한다. 현재 숨김 조회에서도 해당 참가자가 비숨김으로 확인돼야 퇴장을 기록한다. 현재 정보가 없으면 추정하지 않는다.
4. 숨김/해제, 프로필 조회 지연, 이름 변경만으로는 입·퇴장 안내를 만들지 않는다. 같은 이름도 계정 문자열로 구별한다. 계속 같은 구성원 목록이 들어오면 중복 생성하지 않는다.
5. 조회 시에도 기존 숨김 허용 목록을 적용한다. 숨김 또는 미확인 상대의 기존 안내는 감추고 비숨김 확인 후 다시 표시한다. 연결 검증이 없으면 상대 기록 표시를 보류한다.

이는 상태 표본 사이의 변화를 기록하는 기능이다. 조회 사이에 들어왔다가 나간 짧은 방문이나 연결 공백 동안의 활동은 놓칠 수 있다. 표본 간 동시 변화의 실제 선후 관계, 정확한 게임 입·퇴장 시각, 퇴장 이유(자발적 퇴장·연결 끊김·강퇴)는 판별하지 않는다. 앱 실행 전의 활동도 복원하지 않는다.

## 저장 형식과 호환성

`messages.kind`에 `chat`, `member_joined`, `member_left`를 저장한다. 안내 본문은 빈 문자열이고 이름·대상·시각·연결 구간을 별도 필드로 보관한다. 화면에서 현재 언어로 문구를 구성한다. `kind`를 검사해 안내를 일반 대화 검색·새 메시지 계산에서 제외한다. 수신 receipt와 송신 대기열에는 넣지 않는다.

SQLite `user_version`은 1에서 2로 변경한다. 최초 열기에서 `kind TEXT NOT NULL DEFAULT 'chat'` 및 허용값 CHECK를 추가하고 버전을 같은 트랜잭션으로 올린다. 기존 대화·ID·순번·receipt·초안·설정은 유지한다. 인덱스와 30일 정리·삭제 정책은 기존 것을 사용한다.

**기존 schema 1 전용 앱은 변경된 DB를 열지 못한다.** 구버전은 지원하지 않는 버전을 거절하므로 입·퇴장 안내를 상대방이 쓴 메시지로 오인해 표시하지 않는다. 공개 배포 전에는 업데이트의 자동 롤백 경로와 DB 백업/복구 정책을 함께 검토해야 한다. 코드만 구버전으로 교체하는 것으로는 schema 2 DB를 사용할 수 없다. 이전 백업 복원은 그 이후 기록을 잃을 수 있으므로 자동 다운그레이드나 실제 사용자 DB 변환을 이번 작업에서 수행하지 않았다.

## 검증 범위

- `tests/test_presence.py`: 기준 표본, 입·퇴장 중복 방지와 순서, 계정/로비/구간 변경, 연결·숨김 실패와 지연, 숨김/해제/동명이인/이름 변경, 읽기 전용, 미저장 표시, 검색·미읽음 제외, 30일 정리·삭제·페이지 조회, DB 재열기 및 v1 마이그레이션.
- `tests/test_presence_desktop.py`: 실제 Qt WebEngine·QWebChannel·임시 SQLite를 사용해 가운데 안내, HTML 문구 안전성, 한·영 즉시 전환, 재열기, 스크롤·초안·검색·숨김 정책과 알림 호출 없음 확인.
- Playwright/Edge: 실제 제품 HTML/CSS/JS를 로컬 테스트 서버에서 열고 가상 구성원으로 입장 → 일반 대화 → 퇴장 확인. 1240×840, 480×800의 밝은/어두운 테마, 긴 이름 줄바꿈, 화면 식별·비어 있지 않음·오류 오버레이 없음·초안·언어·검색·스크롤을 확인했다. 앱 콘솔 오류/경고는 0개다. Browser 플러그인이 제공되지 않아 저장소의 기존 Playwright 경로를 사용했다.

실제 Bongo Cat·Steam 초기화, 사용자 DB 열기, 로비 메시지 전송, 설치본 교체, 공개 배포는 수행하지 않았다. 자연 발생 입·퇴장과 순정 게임·다른 PC·장시간 실행 인수는 남아 있다. 실행한 전체 회귀 결과는 [제품 검증 기록](product-validation.md#2026-10-28-로비-입퇴장-안내)에 구분한다.

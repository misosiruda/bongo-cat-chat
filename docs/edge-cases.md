# 엣지 케이스와 제품 동작 기준

**2026-10-28 변경:** 아래 게임 숨김 자동 반영·미확인 숨김 보류 항목은 과거 정책이다. 현재 소스는 게임 숨김과 독립적인 [Steam ID 채팅 차단](chat-blocking.md)을 사용한다. 기존 30일 기록 보관·로비 경계·게임 무수정 원칙은 유지한다.

작성일: 2026-10-13. 로비 변경과 사용자 숨김의 인수 기준이다. **Windows 개발판에 추적·필터·저장을 구현했으며 아래 실제 운영 시나리오가 모두 검증된 것은 아니다.** 최신 결정은 [D-013~015](decisions.md), 증거는 [제품 검증](product-validation.md)에 둔다. 숨김 중 미저장·실패 시 차단·30일 보관·직접 삭제는 확정했으며 다른 미결 항목은 제안이다.

## 우선 확인할 두 가지

| 사용자 질문 | 현재 답 | 제품에 필요한 동작 |
| --- | --- | --- |
| 게임에서 로비를 바꾸면 앱도 따라오는가? | 게임 로비 조회·구간 전환·송신 재확인 구현 및 오프라인 검사. 실제 로비 이동은 미검증. | 현재 로비 변경을 감지해 대화 대상을 갱신하고, 전환 중 보내기를 제한해야 함 |
| 게임에서 숨긴 사용자의 채팅도 앱에서 숨겨지는가? | 실험 읽기 어댑터 연결, 기록·검색·새 저장 필터의 오프라인 검사. 게임 재시작·제품 UI와 실제 숨김 조작 대조는 미검증. | 게임에서 설정한 숨김·해제를 자동으로 반영해야 함. 앱에 독립적인 숨김 조작을 두지 않음 |

두 번째 항목에는 [읽기 전용 메모리 조회 후보](profile-sync-validation.md)를 확보했다. 현재 빌드에 대한 실험이며 제품 채택·재시작·업데이트 검증은 남아 있다. 채팅 수신만으로 게임의 숨김·필터를 상속한다고 가정하지 않으며 앱 자체 숨김으로 대체하지 않는다.

## 읽기 전용 분석에서 확인한 사실

분석한 설치 빌드는 `25723683`이며 기존 Auto Chest Opener 패치가 있는 환경이다. 게임 DLL을 데이터로 읽었고, 게임 실행 코드를 호출하거나 파일·로비·설정을 변경하지 않았다. [분석 근거 요약](evidence/2026-10-13-static-review.json)에 메서드 이름과 분석 범위를 기록했다.

- `PlayerDataCache`의 정적 사전에 사용자별 `IsHidden` 값이 있다. `SetIsHidden`은 이 캐시를 갱신한다.
- `LobbyMemberInstance.IsHidden`은 사용자의 ID로 캐시를 조회하며, 설정 시 캐릭터 오브젝트의 활성 상태를 바꾼다.
- `CatSpeech.ShowSpeech`는 해당 게임 오브젝트가 비활성 상태이면 말풍선을 표시하지 않는다.
- 확인한 숨김 처리 경로에서 숨김 목록을 외부 파일이나 Steam 로비 데이터로 내보내는 호출은 찾지 못했다. 게임 전체에 가능한 연동 경로가 없다는 증명은 아니다.
- `PlayerDataCache.Awake`는 캐시를 비운다. 이것만으로 로비 이동·재접속 때의 최종 동작이나 영구 저장 여부를 단정하지 않는다.
- `CatSpeech.ShowMultiplayerSpeech`는 전체 채팅 끄기(`MuteChats`)와 언어 필터(`ChatLanguageFilter`)를 표시 전에 적용한다.
- `LobbyMemberInstance.Start`에는 기존 개별 숨김 값과 자동 고양이 숨김(`AutoHideCats`)을 함께 참조하는 경로가 있다. 개별 숨김·자동 숨김·전체 채팅 끄기를 같은 설정으로 간주하면 안 된다.
- 기존 채팅 PoC의 수신 파서는 UTF-8 JSON의 채널과 본문만 읽는다. 후속 숨김 조회 실험은 별도 어댑터이며 채팅 제품에 아직 통합하지 않았다.

따라서 **현재 PoC를 그대로 UI에 연결하면 게임에서 숨기거나 필터링한 내용이 앱에 나타날 가능성이 있다.** 정적 분석에 따른 판단이며, 사용자를 실제로 숨긴 상태의 수신 실험은 아직 하지 않았다.

## 로비 변경 정책 제안

기본 동작은 자동 추적이다. 새로고침 버튼은 연결 정보를 다시 확인하는 보조 동작으로 두며, 누를 때마다 게임의 로비를 나갔다 다시 들어가게 만들지 않는다.

1. 현재 계정·로비 상태를 재검사한다. 이벤트와 주기적 조회를 함께 검토하되, 이벤트가 별도 프로세스에도 전달되는지는 실제로 확인한다.
2. 로비가 바뀌었거나 불확실하면 보내기를 중지하고 이전 연결 구간을 종료한다.
3. 새 로비와 참여 상태를 확인한 뒤 그 방의 수신을 표시한다. 이전 방의 기록은 이전 방에 남긴다.
4. 이전 방에서 작성한 초안은 방과 함께 보존한다. 새 방 입력창에 자동으로 옮겨 보내지 않는다.
5. 늦게 도착한 이전 방 메시지는 새 방의 목록·알림·읽지 않은 수에 섞지 않는다.
6. 송신 요청에는 최초 대상 로비와 연결 구간을 고정한다. 변경 감지 후 아직 API를 호출하지 않은 요청은 취소하고, 이미 호출한 요청은 원래 대상의 결과로 남긴다.

게임과 앱은 별도 프로세스이므로 최종 확인 직후 게임이 이동하는 경합을 완전히 없앤다고 약속하지 않는다. 핵심은 **새 로비로 자동 재지정하지 않는 것**, 전환 중 송신 상태를 설명하는 것, 중복 전송하지 않는 것이다.

Steam 문서는 로비 참여·퇴장 관련 상태 이벤트와 로비 ID를 제공한다. 다만 `GetFriendGamePlayed`의 공식 설명은 친구 정보 조회이며, PoC에서 현재 계정으로 성공한 사용 방식의 모든 조건을 보장하는 설명은 아니다. [ISteamFriends](https://partner.steamgames.com/doc/api/ISteamFriends#GetFriendGamePlayed), [ISteamMatchmaking](https://partner.steamgames.com/doc/api/ISteamMatchmaking#LobbyChatUpdate_t)

## 숨김 처리 요구사항과 미결 사항

게임의 개별 사용자 숨김·해제를 자동으로 반영하는 것은 필수 요구사항이다. 설정의 기준은 Bongo Cat이며, 앱에는 별도 숨김 조작을 두지 않는다. 자동 동기화 수단을 확보하기 전에는 지원 완료로 표시하지 않는다.

| 쟁점 | 확정 요구사항 또는 결정 필요 사항 |
| --- | --- |
| 식별 기준 | 닉네임 대신 계정 식별자로 적용. 닉네임 변경·동명이인 때문에 다른 사람이 숨겨지면 안 됨 |
| 새 메시지 노출 | 게임에서 숨긴 사용자는 대화 목록, 검색 결과, 미리보기, 알림, 읽지 않은 수에서 함께 제외 |
| 이미 저장한 메시지 | 기존 기록도 표시에서 숨김. 숨김은 영구 삭제를 의미하지 않으며 삭제 정책은 별도 결정 |
| 숨김 중 저장 | 사용자 결정: 새 상대 메시지는 저장하지 않음. 기존 기록은 삭제가 아닌 표시 제외이며 해제 후 다시 조회 가능 |
| 숨김 해제 | Bongo Cat의 해제를 자동 반영. 숨김 중 보관하지 않은 대화를 복원한다고 약속하지 않음. 해제 시 과거 알림을 몰아서 띄우지 않는 안 |
| 방 이동·재접속 | 숨김의 적용 범위와 수명을 확인. 게임에서 해제된 상태를 앱이 계속 유지하거나 반대로 풀어 버리지 않도록 시험 |
| 상태를 읽을 수 없을 때 | D-021: 숨김 조회만 실패하면 상대 대화 노출·신규 저장을 보류하고 검증된 로비의 송신은 유지. 로비 자체 미확인·연결 표본 만료·호환성 실패는 송신도 차단 |
| 앱 자체 숨김 | 제공하지 않음. 이전 수동 숨김 대안 제안 철회. 게임 자동 반영 경로 미확보를 앱 조작으로 대체하지 않음 |
| 전체 채팅 끄기·자동 고양이 숨김 | 게임 말풍선만 끄고 앱에서는 읽으려는 사용도 가능하므로 개별 숨김과 분리해 정책 결정 |
| 욕설·언어 필터 | 게임과 앱에서 내용이 달라질 수 있음. 동일 필터 적용 가능성과 표시·저장 정책을 확인 |

우선 게임 개발자에게 읽기 전용 상태 조회 또는 공식 연동 경로가 있는지 확인할 수 있다. 게임 DLL 패치나 프로세스 주입을 다시 제품 범위에 넣은 것은 아니다. 자동 동기화가 어려우면 필수 요구사항이 미충족임을 명시한다. 범위를 바꾸려면 별도 사용자 결정이 필요하며 임의로 앱 자체 숨김을 도입하지 않는다.

## Steam 프로필 열기의 경계

이슈 #23의 소스는 참여자·메시지 액션에 동일한 ID/context 검증을 적용한다. 숨김·미확인·프로필에서 사라진 상대·자기 자신·보관 로비·2.5초 이상 오래된 연결·종료/재시작은 차단한다. 프로필 캐시가 다음 1초 갱신을 기다리는 중에도 매 상태 발행 시 참여자와 교집합을 취한다. 읽기 전용과 일부 미확인 참여자가 있는 경우 선택한 상대만 허용되면 열 수 있다.

같은 이름, 늦은 UI 이벤트, 진행 중 중복, OS 실패, 포커스·초안·검색·스크롤 보존은 합성 검사로 확인한다. 실시간 표본 직후 퇴장하는 경합, 실제 Steam 미등록/로그인 만료/다른 PC의 화면 결과는 합성 검사로 완료 처리하지 않는다. 이번 작업에서는 사용자 요청으로 게임을 실행하지 않으며 [제품 검증 기록](product-validation.md#2026-10-16-이슈-23-steam-프로필-열기)에 실제 검사와 남은 인수를 구분한다.

## 메시지 번호에 관한 설계 수정

공식 문서상 `LobbyChatMsg_t.m_iChatID`는 해당 콜백 범위에서만 유효하며 저장하면 안 된다. 따라서 이 값을 DB의 영구 메시지 ID나 재접속 후 중복 제거 키로 사용하는 안은 제외한다. 콜백을 해제하기 전에 본문을 복사하고, 앱이 생성한 수신 ID를 같은 내부 처리의 재시도에 재사용한다. 서로 다른 외부 콜백이 같은 발언인지 완벽하게 식별할 수 있다고 약속하지 않는다. ## 다음 검증 순서

1. **로비 추적:** 테스트용 두 로비에서 이동·퇴장·빠른 재입장을 수행하고 외부 프로그램의 관찰값을 비교한다. 먼저 송신 없이 상태 변화와 지연만 확인한다.
2. **숨김 연동 가능성:** 실제 숨김·해제 감지를 확인한 읽기 전용 메모리 조회 후보의 제품 채택·재시작·업데이트 호환성을 검증한다. 공식·지원 조회 경로는 확보하지 못했다.
3. **숨김 전후 수신:** 시험에 참여하는 상대와 숨김 전·숨김 중·해제 후를 비교한다. 원시 수신 여부, 게임 표시, 앱 정책 적용 결과를 따로 기록한다.
4. **정책 결정:** 숨김 중 저장·영구 삭제·조회 실패 시 처리, 전체 채팅 끄기와 자동 숨김, 언어 필터의 적용 범위를 정한다. 기존 기록을 화면에서 숨기는 기준은 게임 설정을 따른다.
5. **제품 구현:** 연결 구간·표시 정책·메시지 상태를 정의한 뒤 UI와 저장 기능을 구현한다.

최초 정적 검토에서는 게임 로비 이동·숨김 설정 변경·채팅 송신을 하지 않았다. 후속 [관찰 시험](profile-sync-validation.md)에서는 사용자가 직접 숨김·해제를 조작했고 외부 프로그램이 그 전환을 감지했다. 로비 이동이나 채팅 필터의 제품 동작을 검증한 것은 아니다.

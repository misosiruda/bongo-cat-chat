# Windows 개발판

2026-10-13 구현 기록. 첫 제품의 실사용 인수 완료와 공개 배포 승인을 의미하지 않는다.

## 구성과 선택 이유

- Python 3.13 / `ctypes`: 기존 PoC의 Steam ABI와 읽기 전용 Mono 조회 코드를 검토해 제품 모듈로 다시 작성했다. 연구 폴더를 import하거나 이전 PID·주소 파일을 읽지 않는다.
- PySide6 / Qt WebEngine / QWebChannel: Windows 창과 한국어 입력을 제공하면서 PR #3의 HTML·CSS 디자인을 이어간다. 정적 시안이 프레임워크를 결정한 것은 아니다. WPF는 FFI·UI 재작성이 크고, WebView2 기반 Python 셸은 별도 런타임 조합 검증이 필요해 이 개발판에서는 선택하지 않았다.
- Steam·메모리 조회는 별도 `multiprocessing` 작업자에 격리한다. 상속된 로컬 큐만 쓰며 제품은 HTTP 서버나 외부 수신 포트를 열지 않는다. 큐 상한을 넘기면 연결을 중단한다.
- SQLite: 계정·로비·연결 구간, 앱 UUID, 수신 순번, UTC 수신 시각, 송신 상태를 보관한다. 처음에는 최신 100개를 조회하고, 위로 스크롤하면 이전 100개를 이어 붙인다. 화면의 저장 기록은 최대 1,000개 범위로 다시 조회하며 본문 부분 문자열 검색을 제공한다. 별도 검색 인덱스의 복제 원문은 만들지 않는다.
- PyInstaller `onedir` 앱과 `onefile` 실행기: Python·Qt를 포함하며 버전 폴더를 전환해 [자동 업데이트](automatic-updates.md)를 적용한다. 업데이트 manifest 서명은 구현했지만 Windows Authenticode 서명과 공개 배포용 설치 마법사는 포함하지 않는다.

이미지 추출용 UnityPy는 texture 모듈을 열 때 오디오 변환 모듈도 import한다. 공개된 `0.1.0.dev6` 묶음은 그 간접 의존성인 FMOD를 포함했다. 이번 SignPath 준비 빌드는 오디오 변환 진입점을 명시적으로 비활성화하고 FMOD와 불필요한 Qt QML/GPL 플러그인을 제외한다. 사용자가 설치한 게임 그림은 계속 로컬에서 읽으며 오디오 기능을 제공하지 않는다. `archspec` CPU 데이터와 Widgets/WebEngine 의존성은 유지하고 다른 도구의 DLL이 섞이지 않도록 빌드 PATH를 제한한다. [라이선스 검토](license-review.md)와 [준비 검증](signpath-validation.md)을 참고한다.

버전은 `pyproject.toml`, 전체 개발 환경 의존성은 `requirements-lock.txt`에 고정했다. 라이선스 선택·일반 배포 허가를 의미하지 않는다.

## 실행

창·작업 표시줄과 앱 왼쪽 위에는 고양이와 보라색 말풍선 아이콘을 사용한다. 브라우저용 파비콘, 앱·시작 실행 파일, 설치·제거 프로그램도 같은 그림으로 맞춘다. 소스 파일과 재생성 방법은 [아이콘 문서](design/app-icon.md)를 참고한다. 기존 설치본에 반영하려면 이 변경을 포함한 새 빌드가 필요하다.

Windows x64와 Python 3.13 개발 환경:

```powershell
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements-lock.txt
.venv/Scripts/python -m pip install -e . --no-deps
powershell -NoProfile -ExecutionPolicy Bypass -File tools/prepare-compatibility.ps1
.venv/Scripts/python -m bongo_chat
```

송신을 막고 실제 상태만 읽으려면:

```powershell
.venv/Scripts/python -m bongo_chat --read-only
```

Steam 초기화·게임 메모리 접근 없이 창만 실행하려면:

```powershell
.venv/Scripts/python -m bongo_chat --offline
```

설정의 개인정보·Chromium·대응 소스 안내는 소스 실행에서도 저장소 문서를 연다. 소스 환경의 오픈소스 라이선스 버튼은 자체 MIT와 의존성 검토를 표시하며, 설치본은 빌드 시 수집한 전체 고지를 표시한다. 고지 파일 읽기나 업데이트 통신 선택 저장에 실패해도 이를 채팅 DB 장애로 처리하지 않으며 기존 통신 선택을 유지한다.

실행 중인 `BongoCat.exe`의 경로에서 설치 파일을 찾는다. `0.1.0.dev6`은 `feature-contract.json`의 채팅·숨김·로비·프로필 계약을 확인한다. `Assembly-CSharp.dll`·`Heathen.Steamworks.dll`의 전체 해시나 공개 빌드 번호가 달라도 사용하는 구조·코드가 같으면 연결한다. Auto Chest Opener에 의존하지 않는다. Mono 메모리 구조와 Steam 네이티브 호출은 아직 확인한 ABI로 제한한다. 관련 계약이 달라지면 설치판의 앱 업데이트를 확인한다. [게임 업데이트 대응](game-update-compatibility.md)에 판정 범위·검사기·실제 검증과 남은 인수를 기록한다.

## 연결과 전송

1. 실행 중인 `BongoCat.exe` 하나의 PID·생성 시각·실행 경로와 기능 계약·네이티브 파일 해시를 검사한다. 다른 Steam 게임을 함께 실행할 수 있으며 다른 프로세스의 실행 경로는 조회하지 않는다. Bongo Cat 자체가 여러 개이면 대상이 모호하므로 연결을 보류한다.
2. Steam을 Bongo Cat의 App ID로 초기화하고 계정을 확인한 뒤 게임 메모리 탐색을 시작한다. 친구 게임 정보가 Bongo Cat 로비를 보고하고 자기 참여가 확인되면 `로비 발견 · 연결 확인 중` 상태에서 방과 초안 입력을 먼저 제공한다. 다른 게임 또는 빈 정보가 보고되면 현재 로비를 확인 중이라고 표시하며 탐색은 계속한다. 아직 전송은 허용하지 않는다.
3. 별도 탐색 스레드에서 로드된 Mono 어셈블리 목록·타입 캐시·도메인별 vtable을 직접 조회해 숨김 사전 루트와 `LobbyData.Current`를 찾는다. 기존 타입·필드·관리 도메인 검증을 유지하고 주소를 저장하지 않는다. 이후 로비의 기준은 이 Bongo Cat 프로세스의 현재 값이며, 해당 로비의 Steam 자기 참여까지 확인해야 송신을 허용한다. 숨김 목록 읽기는 별도로 재시도한다. 검증 완료 상태를 알린 뒤 고양이 이미지 준비를 시작한다.
4. 로비·계정·프로세스 변경마다 새 구간을 만든다. 전환 첫 콜백 큐는 폐기하고 오래된 송신 요청은 실패 처리한다.
5. 송신은 UI에서 명시적으로 누른 요청만 처리한다. 직전에 계정·게임·현재 로비·파일 호환성을 다시 확인한다. 숨김 조회 지연만으로 송신을 막지 않는다. 큐에 2초 넘게 남은 요청과 1초 이내 반복 요청은 거부한다.
6. 종료 시 탐색을 취소하고 자체 작업자와 Steam API만 정리한다. 탐색 중인 읽기 핸들은 탐색 스레드가 닫는다. 게임 종료·`LeaveLobby`·`JoinLobby`·로비 생성·설정 변경 API를 호출하지 않는다.

탐색 중에도 Steam 콜백을 계속 비우며, 미확인·숨김 사용자의 본문은 복사하지 않는다. 로비 검증 또는 사용자별 숨김 확인 직후 첫 콜백 묶음도 비워 이전 대기를 새 수신으로 취급하지 않는다. 탐색 실패 시 Steam 연결을 유지하고 15초 후 탐색만 다시 시작한다. 숨김 목록 조회 실패는 다음 상태 조회에서 재시도한다.

직접 조회는 현재 지원하는 Mono 바이너리의 어셈블리 열거·타입 캐시·vtable 조회 구조를 읽는다. `EnumProcessModulesEx`·`GetModuleFileNameExW`로 해당 게임에 로드된 모듈을 찾고, 로드된 접근자 코드도 확인한다. 어셈블리 512개·타입 버킷/항목 각 16,384개·도메인 슬롯 64개 미만·조회 5초의 상한을 두며 순환·중복·소유 이미지·조회 전후 변경을 검사한다. 모듈 기준 RVA는 지원 ABI의 구조 상수이고 이전 게임 프로세스의 주소를 재사용하지 않는다. 게임 함수를 호출하거나 게임을 중지하지 않는다. 초기화 중인 목록 등으로 직접 조회할 수 없으면 아래 검색 경로로 대체한다. 미지원 접근자 코드·프로세스 변경·취소는 대체 검색으로 우회하지 않는다.

대용량 메모리 검색은 앱에 포함하는 `MemoryScan.exe`가 수행한다. 기존 호환성 검사기와 같은 Windows .NET Framework 빌드 도구를 사용하며 추가 Python 패키지는 없다. `OpenProcess(QUERY_INFORMATION | VM_READ)`·`ReadProcessMemory`·`VirtualQueryEx`만 사용한다. 단계별 120초·4 GiB·패턴별 4,096개 후보 상한, 청크 경계 중첩과 8바이트 포인터 정렬을 유지한다. 부모는 결과 형식·주소 범위·프로세스 수명을 재검사하고, 취소 시 자신이 실행한 검색기만 종료한다. 주소는 비공개 표준 입출력 파이프로 전달하며 파일·로그에 저장하지 않는다. 게임·Steam 바이너리는 검색기에 포함하지 않는다.

최종 확인과 게임의 로비 변경은 원자적이지 않다. 이미 API를 호출한 발언은 원래 목적지에 고정하며 새 방으로 재전송하지 않는다. 매우 빠른 A→B→A 이동과 같은 방에 재입장한 뒤 늦게 도착한 외부 이벤트의 구간을 완벽하게 구분할 수 있다는 보장은 없다. 실제 전환 시험이 필요하다.

UTF-8 JSON `Channel=3`, 문자열 `Message`만 처리한다. 반환 길이·발신자·entry type·콜백 크기·JSON 중복 키·제어 문자·패킷 상한을 검증한다. 본문은 콜백 해제 전에 복사하며 Steam 채팅 번호를 DB/작업 큐에 넘기지 않는다.

후속 소스에서는 고양이 클릭 울음(`야옹 야옹`, `Meow Meow` 등 확인된 27개 언어)을 신규 수신·저장에서 제외하고 기존 기록·검색·미저장 화면에서도 숨긴다. `야옹 야옹 해주세요`처럼 다른 내용이 붙은 문장은 유지한다. 동일한 울음 문구만 직접 입력한 경우에는 게임 패킷으로 구분할 수 없어 함께 숨긴다. 기존 DB를 삭제하거나 스키마를 바꾸지 않으며, 게임 전송 형식과 송신 기능은 유지한다. 새 게임 번역이 바뀌면 목록을 다시 확인해야 한다. 이 변경은 게시된 dev6 설치본과 구분한다. [검증 범위](product-validation.md#2026-10-14-클릭-울음-제외)

현재 계정에 대한 친구 게임 정보(`GetFriendGamePlayed`)는 초기 방 표시의 보조 정보다. 다른 Steam 게임이 보고되거나 실행 중 그 표시가 바뀌어도 검증된 Bongo Cat 로비 연결·초안을 초기화하지 않는다. 게임 메모리에서 로비 없음이 확인되거나 읽기가 실패하면 친구 게임 정보로 대체하지 않는다. Bongo Cat의 현재 로비와 Steam 자기 참여, 계정·프로세스·호환성을 다시 확인하며 로비 구성원에 이름이 있다는 조건만으로 송신을 허용하지 않는다. 이 수정은 `0.1.0.dev11`에 포함된다. [결정과 근거](decisions.md#d-024-여러-steam-게임을-실행해도-bongo-cat의-로비를-직접-확인한다)

서로 다른 네이티브 콜백에 같은 본문이 오면 보존하며, 앱이 발급한 같은 이벤트를 내부에서 재처리할 때만 중복 저장을 막는다. 외부 프로토콜의 영구 ID가 없으므로 모든 Steam 재전달을 완벽히 구분한다고 보장하지 않는다.

개발판 송신 상한은 **50 UTF-16 단위**, JSON 패킷 상한은 4,096바이트다. 50은 PoC에 기반한 보수적 개발판 제한이며 게임의 공식 입력 제한으로 확인한 수치가 아니다. 한글 IME 조합 중 Enter는 전송하지 않는다. 실제 Windows IME로 직접 입력하는 시험은 합성 이벤트 검사와 구분한다.

`전송됨`은 Steam API 접수다. 자기 수신 대응은 같은 계정·방·구간·정확한 본문·5초 범위·송신 순서에 따른 후보이며 읽음/상대 화면 확인이 아니다. 앱 UUID가 없는 게임 프로토콜 때문에 게임과 앱의 같은 본문 동시 송신은 정확한 출처 대응이 모호하다. 각각 도착한 이벤트의 수량을 보존하고, 서로 다른 콜백을 본문 해시로 제거하지 않는다. 결과 불명·앱 재시작·재연결 시 자동 재송신하지 않는다.

## 숨김·프로필·기록

사용자가 이번 구현에서 선택한 정책:

- 게임에서 숨긴 동안 새 상대 메시지를 저장하지 않는다. 기존 기록은 표시에서 숨기고 해제 후 다시 조회할 수 있다.
- 숨김 조회가 실패하면 상대 대화 표시·신규 저장을 막고, 사전에 없는 사용자만 미확인으로 감춘다. 검증된 현재 로비의 송신은 유지한다. 연결 상태가 2.5초 이상 갱신되지 않으면 상대 대화와 모든 신규 송수신을 보류한다. 게임을 종료한 상태의 전체 상대 기록 열람도 아직 지원하지 않는다. [D-021](decisions.md#d-021-로비-연결과-숨김-동기화를-분리한다)
- 대화와 초안은 이 기기에 **30일** 보관한다. 실행 시와 실행 중 주기적으로 만료 데이터를 정리하고, 조회에서도 만료된 행을 제외한다. 앱을 실행하지 않은 기간에는 정리 작업이 실행되지 않는다.
- 설정에서 선택한 로비 또는 현재 계정의 기록을 확인 후 직접 삭제한다. 내보내기는 후속 범위다.
- 숨김 메모리 어댑터는 개발판 실험 기능으로 연결한다. 일반 배포 채택은 별도 결정이다.

실시간 숨김은 주기적인 표본 조회이며 클릭과 같은 순간에 반영됨을 보장하지 않는다. 조회 실패를 빈 숨김 목록으로 바꾸지 않는다. 앱 자체 숨김 버튼·독립 목록·알림·읽지 않은 수는 만들지 않았다. 목록에는 대화 원문 미리보기를 넣지 않았다.

표시 이름은 친구 별명 우선, 없으면 persona name이며 식별은 계정 문자열로 한다. 현재 확인된 프로필은 기존 메시지에도 적용하고, 조회되지 않으면 저장 당시 이름을 사용한다. 외형은 설치된 Unity 스프라이트의 스킨 두 레이어·모자를 메모리에서 합성한다. Steam 사진이나 원격 아이콘을 가져오지 않는다.

모자와 스킨을 같은 좌표에 겹치지 않고 설치된 `LobbyMember/Cat_Multiplayer/Visuals/BobTransform`의 `Body`·`Hat`·`RightPaw` 배치와 자식 순서를 읽는다. 몸통에 대한 상대 좌표를 256픽셀 이미지 좌표로 바꾸며 게임의 위쪽 Y축을 이미지의 아래쪽 Y축으로 변환한다. 모자를 이동한 전체 영역을 정사각형으로 맞춘 뒤 256×256으로 축소하므로 위로 벗어난 부분도 PNG에 포함된다. 모자가 없고 두 스킨 레이어가 같은 위치라면 기존 크기와 픽셀을 유지한다.

확인한 256×256 원본 레이어와 동일 크기·중앙 앵커·중앙 기준점·무회전·배율 1의 게임 UI 배치만 지원한다. 프리팹·레이어의 누락이나 중복, 지원하지 않는 배치·원본 크기는 임의 좌표로 대체하지 않고 외형 확인 불가로 처리한다. 회전·반전·동작·효과·기본 스킨의 모든 조합은 미검증이다. 게임 그림을 저장소·배포물에 동봉하지 않는다. [모자 위치 수정 검증](product-validation.md#2026-10-14-모자-위치-수정)을 기존 프로필 조회 시험과 구분한다.

데이터 위치는 기본 `%LOCALAPPDATA%/BongoCatChat/history.sqlite3`다. 대화·계정 ID·로비 ID·표시 이름·초안을 로컬 평문 SQLite에 저장한다. 별도 암호화나 원격 전송은 없다. SQLite secure delete와 WAL checkpoint를 사용하지만 SSD의 물리적 복구 불가능성을 보장하지 않는다. 설정은 테마와 사이드바 접힘이며 초안은 계정·방별로 보관한다.

설정창은 제목과 닫기 버튼을 고정하고 테마·업데이트·기록 관리 내용만 스크롤한다. 작은 창에서 기록 삭제 확인까지 내려가도 닫기 버튼을 사용할 수 있다. 다시 열면 삭제 확인을 접고 내용의 처음으로 돌아가며 닫기 버튼에 키보드 초점을 둔다. 닫기 버튼과 Esc로 대화에 돌아가도 검색·초안은 유지된다.

설정·참여자 모달의 배경은 흐림 효과 없이 어둡게 처리한다. Windows Qt의 배경 합성에 따른 깜빡임 후보를 피하기 위한 처리이며 제품의 GPU 가속은 유지한다. 실제 제보 환경의 깜빡임 인수 여부는 [검증 기록](product-validation.md)의 이슈 #9 항목을 따른다.

저장 실패는 전송 실패와 별도로 표시한다. 저장하지 못한 수신은 최대 200개만 현재 창에 보관한다. 저장 실패 상태에서 새 송신을 막고, 연결 새로고침 때 저장소를 재검사한다. 저장 실패 원문을 디스크 진단 로그에 복사하지 않는다.

저장이 다시 성공하면 앞서 미저장된 메시지를 그 첫 성공 메시지 직전에 배치한다. SQLite가 커밋한 순번을 기준으로 합치므로 동일한 수신 시각이나 PC 시계 역행이 대화 순서를 바꾸지 않는다. 기준 메시지가 검색·숨김 필터로 제외되어도 순서를 유지하고, 이전 대화 조회는 첫 저장 메시지의 순번을 사용한다. 메모리의 순서 표식은 DB나 UI 응답에 저장하지 않는다.

로비 전환 응답을 기다리는 동안 입력한 문장도 이전 방에 저장한다. 대상을 바꾸는 동안 입력을 잠그고 새 방에 저장된 초안을 불러온다. 기록 삭제 확인은 확인창을 연 계정·로비에 고정한다. 대화 조회 오류가 발생하면 이전 상대 대화·참여자 표시를 지우고 전송을 막는다. 저장소 복구 시 생성에 실패했던 현재 연결 구간도 다시 만들며, 성공한 후속 수신을 미저장 목록에 중복 표시하지 않는다.

## Steam 프로필 열기

현재 로비의 참여자 목록에서 상대의 `Steam 프로필 열기`를 누르거나 메시지의 상대 이름·고양이를 선택한다. Steam 클라이언트 안에 프로필 열기를 요청하며 **친구 추가는 Steam에서 직접 진행한다.** 이름·고양이 버튼도 Tab으로 선택해 Enter 또는 Space로 실행할 수 있다.

숨김 상태가 허용되고 현재 프로필에 있는 상대만 대상으로 하며 자기 자신과 보관 로비에는 버튼을 제공하지 않는다. 일부 참여자가 미확인이어도 확인된 상대는 사용할 수 있고 읽기 전용 실행에서도 허용한다. 계정·로비·연결 구간 변경, 오래된 연결, 종료·업데이트 재시작 중의 요청은 거절한다. 참여자 갱신 시 동일 대상의 포커스를 유지한다.

`Steam에 프로필 열기를 요청했어요`는 OS에 URI를 전달했다는 안내다. Steam 화면 표시나 친구 요청 성공 확인이 아니다. 열지 못하면 Steam 실행 상태를 확인하라는 오류를 표시하며 다른 주소로 자동 재시도하지 않는다. 프로필 오류로 저장 오류를 설정하거나 채팅 송신을 막지 않으며 초안·검색·스크롤·선택 로비를 유지한다. 프로필 페이지 내용과 친구 관계는 수집하지 않는다.

이번 소스의 검사는 실제 Steam 호출을 대체한 Qt/QWebChannel 및 합성 브라우저 검사다. 작업 PC에서 Bongo Cat 실행은 사용자 요청으로 금지되어 실제 제품 버튼 → Steam의 상대 프로필 표시는 미검증이다. 설치본 반영·다른 PC·미등록 프로토콜·로그인 만료 인수도 남아 있다. [검증 기록](product-validation.md#2026-10-16-이슈-23-steam-프로필-열기)을 참고한다.

## 검사와 빌드

### 기록 스크롤

새 메시지가 와도 읽던 메시지와 화면 내 위치를 유지한다. 실제 최신 구간의 맨 아래에 있을 때만 자동으로 새 메시지를 따라간다. 위로 스크롤하면 이전 기록을 자동으로 불러오며 수동 버튼도 제공한다. 이전 기록의 존재 여부는 실제 행으로 판정하므로 정확히 100개인 마지막 구간에서 빈 페이지로 이동하지 않는다.

`맨 아래로`·`최근 대화로`·`새 메시지 보기` 버튼은 대화 영역의 오른쪽 아래에 고정된다. 수동으로 실제 최신 메시지까지 내려가면 새 메시지 표시가 사라진다. 과거 구간을 읽는 중에도 새 수신을 표시하며, 내 메시지를 보내면 최신 구간으로 이동해 전송 상태를 보여 준다. 새 메시지 표시는 앱 내부의 미확인 표시이며 상대방의 읽음 확인이 아니다.

방을 다시 선택하거나 검색을 지우면 기록 범위와 읽던 메시지 위치를 함께 복원한다. 검색 결과의 `대화에서 보기`는 대상 전후의 기록을 보여 준다. 최대 1,000개 범위의 끝에 도달하면 최근 100개를 겹쳐 다음 범위로 이어 간다. 미저장 수신의 기존 최대 200개 제한은 유지한다.

조회마다 계정·로비·30일 보관·숨김 허용 목록·Meow 제외 정책을 적용한다. 이전 화면의 대화 원문을 합쳐 보관하는 별도 캐시는 없으며, 새 메시지 판정에도 같은 표시 정책을 적용한다. 화면 위치는 실행 중에만 기억하고 DB schema·보관 기간·송신 계약은 변경하지 않는다.

```powershell
.venv/Scripts/python -m pytest -q
node --check src/bongo_chat/ui/app.js
.venv/Scripts/python tools/probe_readonly.py --seconds 15
.venv/Scripts/python tools/probe_startup.py --avatars
pwsh -NoProfile -File packaging/build.ps1 -AllowUnsigned
dist/BongoCatChat/BongoCatChat.exe --offline
```

출력 폴더의 앱이 실행 중이면 빌드를 시작하지 않는다. 창을 유지한 채 새 개발 묶음을 만들려면 `pwsh -NoProfile -File packaging/build.ps1 -OutputRoot dist/reviewed -AllowUnsigned`를 사용한다. 이 경우 결과는 `dist/reviewed/BongoCatChat`이며 출력 경로는 저장소의 `dist` 안으로 제한한다. 배포용은 `-SigningConfig`로 [Windows 코드 서명](windows-code-signing.md)을 적용한다. 서명 설정과 개발용 미서명 허용을 모두 생략하면 빌드를 중단한다.

`probe_readonly.py`는 실제 설치를 읽지만 송신·로비 변경·재시작·채팅 DB 저장은 하지 않는다. 결과에는 건수와 상태만 출력한다. 게임 재시작 호환성은 사용자가 재시작한 뒤 새 프로세스에서 다시 실행해 비교해야 한다.

`probe_startup.py`는 실제 작업자에서 로비 발견·현재 로비 검증·숨김 동기화까지 걸린 시간과 상태 갱신 간격을 출력한다. 읽기 전용이며 콜백 본문 해석과 DB 생성도 차단한다. Qt 창 시작 시간은 포함하지 않는다. 기본 제한은 150초이고 `--avatars`로 제품과 같은 이미지 작업을 함께 실행할 수 있다.

브라우저 보조 검사는 `tests/browser_check.py`다. 실제 제품 HTML에 테스트 전용 로컬 QWebChannel 대역을 연결한다. 실제 Qt·QWebChannel·SQLite 검사는 `tests/test_desktop.py`에서 따로 수행한다. 두 검사 모두 실제 게임 송신의 증거가 아니다.

스크롤 회귀 검사는 `tests/browser_scroll_check.py`, 네이티브 브리지 검사는 `tests/test_scroll_desktop.py`, 조회 범위·경계·숨김 메타데이터 검사는 `tests/test_scroll_service.py`다. Browser 플러그인이 없는 환경에서는 설치된 Playwright Chromium으로 가상 대화만 검증한다.

프로필 허용·URI·캐시 검사는 `tests/test_profiles.py`, 실제 Qt 브리지는 `tests/test_profile_desktop.py`, 키보드·포커스·스크롤·테마·최소 창 보조 검사는 `tests/browser_profile_check.py`다. 프로필 검사의 OS 실행은 대체 함수만 사용하며 실제 Steam을 열지 않는다.

```powershell
.venv/Scripts/python.exe -m pytest -q tests/test_profiles.py tests/test_profile_desktop.py
.venv/Scripts/python.exe tests/browser_profile_check.py --browser <로컬-Chromium.exe> --output <저장소-외부-검증-폴더>
```

```powershell
.venv/Scripts/python tests/browser_scroll_check.py --browser <로컬-Chromium.exe> --output <외부-검증-폴더>
```

완성된 EXE에는 오프라인 `--smoke-report <경로>`와 송신을 금지하는 `--read-only --connection-report <경로>` 진단 실행이 있다. 후자는 연결 후 일정 시간 관찰하고 건수·오류 종류만 기록한 뒤 종료한다. 계정·방 ID나 원문은 진단 JSON에 쓰지 않는다. 연결 시험의 대화 DB는 `--data-dir`로 비공개 시험 폴더를 지정한다.

```powershell
.venv/Scripts/python tests/browser_check.py --browser <로컬-Chromium.exe> --output <외부-검증-폴더>
```

현재 앱의 수신 상태·송신 요청 API·DB·렌더러를 독립 검사할 수 있다. 순정 게임과 별도 상대 PC의 왕복, 실제 IME, 빠른 로비 전환, 장시간 실행은 별도 인수 시험이다.

## 설치·삭제

일반 이용자는 [설치 안내](installation.md)에 따라 단일 `Setup.exe`를 더블클릭한다. 한국어 마법사, 현재 사용자 설치, 시작 메뉴, Windows 설치된 앱 목록과 제거 프로그램을 제공한다. Python·Git·관리자 권한이나 수동 스크립트 실행은 필요하지 않다.

개발자는 먼저 `packaging/build.ps1`로 전체 묶음을 만들고 NSIS 3.13으로 설치 파일을 빌드한다. [공식 다운로드](https://nsis.sourceforge.io/Download)의 ZIP을 개발 도구 폴더에 풀어 사용한다. NSIS를 제품 이용자에게 따로 설치하게 하지 않는다.

```powershell
./packaging/build.ps1 -OutputRoot dist/windows-setup -AllowUnsigned
./packaging/build-setup.ps1 -Bundle dist/windows-setup/BongoCatChat -NsisPath <NSIS-3.13-폴더> -AllowUnsigned
```

결과는 `dist/setup/BongoCatChat-<버전>-windows-x64-Setup.exe`와 SHA-256 파일이다. 설치 프로그램 안에 전체 Qt·Python 묶음을 넣으며 런타임을 인터넷에서 받지 않는다. 앱 묶음의 `BongoCatChat.exe`만 따로 복사하는 것은 지원하지 않는다. 빌드 단계는 게임 DLL·Unity assets가 섞이면 실패한다. `-TestIdentity`는 별도 설치 이름·등록 키를 사용하는 검사용이며 이용자에게 배포하지 않는다.

내부 설치 엔진은 기존 설치 여부·버전·재분석 지점·실행 잠금을 검사한다. 같은 버전 재설치와 이전 버전 교체를 지원하고 더 낮은 버전은 거부한다. 새 파일을 임시 폴더에 준비한 뒤 교체하며 실패하면 기존 파일을 복구한다. 실행 중인 프로세스를 종료하지 않는다. dev1의 정확한 설치 표식이 있으면 이전 구조도 전환한다. 무관한 파일이 들어 있는 폴더를 새 설치로 취급하지 않는다.

제거 프로그램은 내장된 제거 엔진으로 검증된 앱 구성원만 삭제한다. 시작 메뉴와 자기 설치의 제거 등록을 정리하며 대화 데이터·설치 폴더의 별도 파일은 보존한다. 앱 설정에서는 선택 로비 또는 현재 계정의 기록을 직접 삭제할 수 있다. 여러 계정 기록을 일괄 삭제하는 기능은 없다.

같은 PC에서의 설치 검사는 [설치 검증 기록](installer-validation.md)에 남긴다. 개발 도구가 없는 별도 PC, 코드 서명·SmartScreen·백신·전원 손실·일반 배포는 별도 인수 항목이다.

## 실제 송신 시험 절차

1. 상대방이 시험에 참여하는 현재 게임 로비를 사용자가 지정한다.
2. 앱의 연결·숨김 조회가 정상인지 읽기 전용으로 확인한다.
3. 사용자 확인을 받은 정확한 문구 **1회**만 앱 UI에서 보낸다. 제안 문구: `Bongo Cat Chat 앱 송수신 확인입니다`.
4. API 접수, 자기 수신 후보, 상대 게임 화면을 각각 기록한다. 상대 화면은 상대방 또는 사용자의 확인이 필요하다.
5. 상대가 게임에서 정한 문장을 한 번 보내 앱 표시·재실행 후 검색을 대조한다.
6. 로비 이동·게임 재시작·숨김 조작은 사용자가 수행하는 별도 시험으로 진행한다. 불명확한 결과를 이유로 다시 보내지 않는다.

개발 도구 `prepare_live_test.py`는 비공개 계획만 만들고 송신하지 않는다. `run_authorized_test.py`는 사용자가 해당 문구·대상·1회를 명시적으로 허용한 뒤에만 실행한다. 실제 Qt 화면의 보내기 버튼을 한 번 누르며, 큐에 넣기 전에 시도 표식을 기록해 같은 계획의 재실행을 거부한다. 시험용 계획·ID·DB는 `research/private/`에만 남긴다. 앱에 자동 송신·재전송 기능을 넣은 것은 아니다. 이번 승인된 두 차례의 각 1회 결과는 [제품 검증 기록](product-validation.md)에 구분한다.

# Windows 개발판

2026-10-13 구현 기록. 첫 제품의 실사용 인수 완료와 공개 배포 승인을 의미하지 않는다.

## 구성과 선택 이유

- Python 3.13 / `ctypes`: 기존 PoC의 Steam ABI와 읽기 전용 Mono 조회 코드를 검토해 제품 모듈로 다시 작성했다. 연구 폴더를 import하거나 이전 PID·주소 파일을 읽지 않는다.
- PySide6 / Qt WebEngine / QWebChannel: Windows 창과 한국어 입력을 제공하면서 PR #3의 HTML·CSS 디자인을 이어간다. 정적 시안이 프레임워크를 결정한 것은 아니다. WPF는 FFI·UI 재작성이 크고, WebView2 기반 Python 셸은 별도 런타임 조합 검증이 필요해 이 개발판에서는 선택하지 않았다.
- Steam·메모리 조회는 별도 `multiprocessing` 작업자에 격리한다. 상속된 로컬 큐만 쓰며 제품은 HTTP 서버나 외부 수신 포트를 열지 않는다. 큐 상한을 넘기면 연결을 중단한다.
- SQLite: 계정·로비·연결 구간, 앱 UUID, 수신 순번, UTC 수신 시각, 송신 상태를 보관한다. 100개 단위 페이지 조회와 본문 부분 문자열 검색을 제공한다. 별도 검색 인덱스의 복제 원문은 만들지 않는다.
- PyInstaller `onedir` 앱과 `onefile` 실행기: Python·Qt를 포함하며 버전 폴더를 전환해 [자동 업데이트](automatic-updates.md)를 적용한다. 업데이트 manifest 서명은 구현했지만 Windows Authenticode 서명과 공개 배포용 설치 마법사는 포함하지 않는다.

이미지 추출용 UnityPy는 texture 모듈을 열 때 오디오 변환 모듈도 import한다. 그래서 개발 묶음에는 PyPI의 `fmod_toolkit`에 포함된 네이티브 의존성도 들어간다. 게임 설치에서 복사한 DLL이 아니며 앱은 오디오 기능을 제공하거나 실행하지 않는다. 이 간접 의존성까지 포함한 일반 배포 이용 조건·고지는 별도 확인 대상이다. 패키징은 `archspec` CPU 데이터도 포함하며 다른 도구의 DLL이 섞이지 않도록 빌드 PATH를 제한한다.

버전은 `pyproject.toml`, 전체 개발 환경 의존성은 `requirements-lock.txt`에 고정했다. 라이선스 선택·일반 배포 허가를 의미하지 않는다.

## 실행

Windows x64와 Python 3.13 개발 환경:

```powershell
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements-lock.txt
.venv/Scripts/python -m pip install -e . --no-deps
.venv/Scripts/python -m bongo_chat
```

송신을 막고 실제 상태만 읽으려면:

```powershell
.venv/Scripts/python -m bongo_chat --read-only
```

Steam 초기화·게임 메모리 접근 없이 창만 실행하려면:

```powershell
.venv/Scripts/python -m bongo_chat --offline
```

실행 중인 `BongoCat.exe`의 경로에서 설치 파일을 찾는다. 현재 개발판은 `supported-build.json`의 네 파일 SHA-256과 일치하는 설치만 허용한다. 이 목록은 기존 Auto Chest Opener 패치가 있던 개발 PC 기준이며, 순정 환경 지원 목록이 아니다. 다른 빌드는 추측해 호출하지 않고 미지원으로 표시한다.

## 연결과 전송

1. 단일 게임 프로세스의 PID·생성 시각·실행 경로를 확인하고 파일 해시를 검사한다.
2. 타입·필드·관리 도메인을 확인해 숨김 사전과 `LobbyData.Current`를 매 프로세스 수명마다 새로 찾는다. 저장된 주소는 없다.
3. Steam 계정, 게임의 현재 로비, 그 로비의 자기 구성원 여부를 대조한다. 콜백에서 본 방 번호만으로 송신 대상을 정하지 않는다.
4. 로비·계정·프로세스 변경마다 새 구간을 만든다. 전환 첫 콜백 큐는 폐기하고 오래된 송신 요청은 실패 처리한다.
5. 송신은 UI에서 명시적으로 누른 요청만 처리한다. 직전에 계정·게임·로비·숨김 상태를 다시 확인한다. 큐에 2초 넘게 남은 요청과 1초 이내 반복 요청은 거부한다.
6. 종료 시 자체 작업자와 Steam API만 정리한다. 게임 종료·`LeaveLobby`·`JoinLobby`·로비 생성·설정 변경 API를 호출하지 않는다.

최종 확인과 게임의 로비 변경은 원자적이지 않다. 이미 API를 호출한 발언은 원래 목적지에 고정하며 새 방으로 재전송하지 않는다. 매우 빠른 A→B→A 이동과 같은 방에 재입장한 뒤 늦게 도착한 외부 이벤트의 구간을 완벽하게 구분할 수 있다는 보장은 없다. 실제 전환 시험이 필요하다.

UTF-8 JSON `Channel=3`, 문자열 `Message`만 처리한다. 반환 길이·발신자·entry type·콜백 크기·JSON 중복 키·제어 문자·패킷 상한을 검증한다. 본문은 콜백 해제 전에 복사하며 Steam 채팅 번호를 DB/작업 큐에 넘기지 않는다.

현재 계정의 Steam 게임 정보(`GetFriendGamePlayed`)에 보고된 App ID·로비도 게임 메모리와 대조한다. 로비 구성원에 이름이 있다는 조건만으로 송신을 허용하지 않는다. 서로 다른 네이티브 콜백에 같은 본문이 오면 보존하며, 앱이 발급한 같은 이벤트를 내부에서 재처리할 때만 중복 저장을 막는다. 외부 프로토콜의 영구 ID가 없으므로 모든 Steam 재전달을 완벽히 구분한다고 보장하지 않는다.

개발판 송신 상한은 **50 UTF-16 단위**, JSON 패킷 상한은 4,096바이트다. 50은 PoC에 기반한 보수적 개발판 제한이며 게임의 공식 입력 제한으로 확인한 수치가 아니다. 한글 IME 조합 중 Enter는 전송하지 않는다. 실제 Windows IME로 직접 입력하는 시험은 합성 이벤트 검사와 구분한다.

`전송됨`은 Steam API 접수다. 자기 수신 대응은 같은 계정·방·구간·정확한 본문·5초 범위·송신 순서에 따른 후보이며 읽음/상대 화면 확인이 아니다. 앱 UUID가 없는 게임 프로토콜 때문에 게임과 앱의 같은 본문 동시 송신은 정확한 출처 대응이 모호하다. 각각 도착한 이벤트의 수량을 보존하고, 서로 다른 콜백을 본문 해시로 제거하지 않는다. 결과 불명·앱 재시작·재연결 시 자동 재송신하지 않는다.

## 숨김·프로필·기록

사용자가 이번 구현에서 선택한 정책:

- 게임에서 숨긴 동안 새 상대 메시지를 저장하지 않는다. 기존 기록은 표시에서 숨기고 해제 후 다시 조회할 수 있다.
- 숨김 조회가 실패하거나 2.5초 이상 갱신되지 않으면 상대 대화 표시·신규 저장과 송신을 막는다. 사전에 없는 사용자는 미확인으로 취급한다. 게임을 종료한 상태의 전체 상대 기록 열람도 아직 지원하지 않는다.
- 대화와 초안은 이 기기에 **30일** 보관한다. 실행 시와 실행 중 주기적으로 만료 데이터를 정리하고, 조회에서도 만료된 행을 제외한다. 앱을 실행하지 않은 기간에는 정리 작업이 실행되지 않는다.
- 설정에서 선택한 로비 또는 현재 계정의 기록을 확인 후 직접 삭제한다. 내보내기는 후속 범위다.
- 숨김 메모리 어댑터는 개발판 실험 기능으로 연결한다. 일반 배포 채택은 별도 결정이다.

실시간 숨김은 주기적인 표본 조회이며 클릭과 같은 순간에 반영됨을 보장하지 않는다. 조회 실패를 빈 숨김 목록으로 바꾸지 않는다. 앱 자체 숨김 버튼·독립 목록·알림·읽지 않은 수는 만들지 않았다. 목록에는 대화 원문 미리보기를 넣지 않았다.

표시 이름은 친구 별명 우선, 없으면 persona name이며 식별은 계정 문자열로 한다. 현재 확인된 프로필은 기존 메시지에도 적용하고, 조회되지 않으면 저장 당시 이름을 사용한다. 외형은 설치된 Unity 스프라이트의 스킨 두 레이어·모자를 메모리에서 합성한다. Steam 사진이나 원격 아이콘을 가져오지 않는다. 확인한 256×256 레이어 규격만 지원하고 누락·중복·다른 크기는 외형 확인 불가로 표시한다. 회전·동작·효과·기본 스킨의 모든 조합은 미검증이다. 게임 그림을 저장소·배포물에 동봉하지 않는다.

데이터 위치는 기본 `%LOCALAPPDATA%/BongoCatChat/history.sqlite3`다. 대화·계정 ID·로비 ID·표시 이름·초안을 로컬 평문 SQLite에 저장한다. 별도 암호화나 원격 전송은 없다. SQLite secure delete와 WAL checkpoint를 사용하지만 SSD의 물리적 복구 불가능성을 보장하지 않는다. 설정은 테마와 사이드바 접힘이며 초안은 계정·방별로 보관한다.

저장 실패는 전송 실패와 별도로 표시한다. 저장하지 못한 수신은 최대 200개만 현재 창에 보관한다. 저장 실패 상태에서 새 송신을 막고, 연결 새로고침 때 저장소를 재검사한다. 저장 실패 원문을 디스크 진단 로그에 복사하지 않는다.

저장이 다시 성공하면 앞서 미저장된 메시지를 그 첫 성공 메시지 직전에 배치한다. SQLite가 커밋한 순번을 기준으로 합치므로 동일한 수신 시각이나 PC 시계 역행이 대화 순서를 바꾸지 않는다. 기준 메시지가 검색·숨김 필터로 제외되어도 순서를 유지하고, 이전 대화 조회는 첫 저장 메시지의 순번을 사용한다. 메모리의 순서 표식은 DB나 UI 응답에 저장하지 않는다.

로비 전환 응답을 기다리는 동안 입력한 문장도 이전 방에 저장한다. 대상을 바꾸는 동안 입력을 잠그고 새 방에 저장된 초안을 불러온다. 기록 삭제 확인은 확인창을 연 계정·로비에 고정한다. 대화 조회 오류가 발생하면 이전 상대 대화·참여자 표시를 지우고 전송을 막는다. 저장소 복구 시 생성에 실패했던 현재 연결 구간도 다시 만들며, 성공한 후속 수신을 미저장 목록에 중복 표시하지 않는다.

## 검사와 빌드

```powershell
.venv/Scripts/python -m pytest -q
node --check src/bongo_chat/ui/app.js
.venv/Scripts/python tools/probe_readonly.py --seconds 15
pwsh -NoProfile -File packaging/build.ps1
dist/BongoCatChat/BongoCatChat.exe --offline
```

출력 폴더의 앱이 실행 중이면 빌드를 시작하지 않는다. 창을 유지한 채 새 묶음을 만들려면 `pwsh -NoProfile -File packaging/build.ps1 -OutputRoot dist/reviewed`를 사용한다. 이 경우 결과는 `dist/reviewed/BongoCatChat`이며 출력 경로는 저장소의 `dist` 안으로 제한한다.

`probe_readonly.py`는 실제 설치를 읽지만 송신·로비 변경·재시작·채팅 DB 저장은 하지 않는다. 결과에는 건수와 상태만 출력한다. 게임 재시작 호환성은 사용자가 재시작한 뒤 새 프로세스에서 다시 실행해 비교해야 한다.

브라우저 보조 검사는 `tests/browser_check.py`다. 실제 제품 HTML에 테스트 전용 로컬 QWebChannel 대역을 연결한다. 실제 Qt·QWebChannel·SQLite 검사는 `tests/test_desktop.py`에서 따로 수행한다. 두 검사 모두 실제 게임 송신의 증거가 아니다.

완성된 EXE에는 오프라인 `--smoke-report <경로>`와 송신을 금지하는 `--read-only --connection-report <경로>` 진단 실행이 있다. 후자는 연결 후 일정 시간 관찰하고 건수·오류 종류만 기록한 뒤 종료한다. 계정·방 ID나 원문은 진단 JSON에 쓰지 않는다. 연결 시험의 대화 DB는 `--data-dir`로 비공개 시험 폴더를 지정한다.

```powershell
.venv/Scripts/python tests/browser_check.py --browser <로컬-Chromium.exe> --output <외부-검증-폴더>
```

현재 앱의 수신 상태·송신 요청 API·DB·렌더러를 독립 검사할 수 있다. 순정 게임과 별도 상대 PC의 왕복, 실제 IME, 빠른 로비 전환, 장시간 실행은 별도 인수 시험이다.

## 설치·삭제

로컬 빌드 후 `dist/BongoCatChat` 전체를 사용한다. EXE 하나만 복사하면 Qt·Python 파일이 없어 실행되지 않는다. 빌드 단계는 게임 DLL·Unity assets가 섞이면 실패한다.

```powershell
# 빌드 묶음 안에서 Windows 기본 PowerShell로 실행. 관리자 권한 불필요.
powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1
# 종료 후 설치 폴더의 제거 스크립트 실행
powershell -NoProfile -ExecutionPolicy Bypass -File .\uninstall.ps1
```

설치 스크립트는 사용자 프로그램 폴더로 복사하고 시작 메뉴 바로가기를 만든다. 기존 설치/바로가기를 덮어쓰지 않는다. 제거는 표식이 있는 설치의 알려진 구성원만 삭제한다. 게임 폴더와 대화 데이터는 건드리지 않는다. `uninstall.ps1`과 빈 설치 폴더는 남으므로 필요하면 직접 지운다. 대화까지 지우려면 제거 전 앱 설정에서 현재 계정 기록을 삭제한다. 데이터 폴더의 여러 계정 기록을 일괄 삭제하는 기능은 없다.

개발 도구가 없는 별도 Windows PC, 시작 메뉴 바로가기, 코드 서명·설치 UI·일반 배포는 미검증 또는 후속 작업이다. 로컬 복사·실행·제거 시험은 해당 인수를 대신하지 않는다.

## 실제 송신 시험 절차

1. 상대방이 시험에 참여하는 현재 게임 로비를 사용자가 지정한다.
2. 앱의 연결·숨김 조회가 정상인지 읽기 전용으로 확인한다.
3. 사용자 확인을 받은 정확한 문구 **1회**만 앱 UI에서 보낸다. 제안 문구: `Bongo Cat Chat 앱 송수신 확인입니다`.
4. API 접수, 자기 수신 후보, 상대 게임 화면을 각각 기록한다. 상대 화면은 상대방 또는 사용자의 확인이 필요하다.
5. 상대가 게임에서 정한 문장을 한 번 보내 앱 표시·재실행 후 검색을 대조한다.
6. 로비 이동·게임 재시작·숨김 조작은 사용자가 수행하는 별도 시험으로 진행한다. 불명확한 결과를 이유로 다시 보내지 않는다.

개발 도구 `prepare_live_test.py`는 비공개 계획만 만들고 송신하지 않는다. `run_authorized_test.py`는 사용자가 해당 문구·대상·1회를 명시적으로 허용한 뒤에만 실행한다. 실제 Qt 화면의 보내기 버튼을 한 번 누르며, 큐에 넣기 전에 시도 표식을 기록해 같은 계획의 재실행을 거부한다. 시험용 계획·ID·DB는 `research/private/`에만 남긴다. 앱에 자동 송신·재전송 기능을 넣은 것은 아니다. 이번 승인된 두 차례의 각 1회 결과는 [제품 검증 기록](product-validation.md)에 구분한다.

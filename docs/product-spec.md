# 제품 요구사항

상태: 2026-10-12 합의 내용과 설계 제안. 2026-10-13 로비 변경·사용자 숨김 검토를 추가했다. 문서에서 요구사항으로 적은 UI·저장 기능은 아직 구현하지 않았다.

## 1. 해결할 문제

Bongo Cat의 로비 채팅은 게임 화면에 잠시 나타난 뒤 사라진다. 사용자는 지나간 대화를 다시 확인하기 어렵고, 게임 안에서 문장을 입력하는 방식도 불편하다고 설명했다.

사용자가 원하는 것은 게임의 기존 대화에 참여하면서 메신저나 Discord처럼 목록 형태로 읽고 입력할 수 있는 별도 프로그램이다. 여기서 Discord는 UI와 사용성의 참고 대상이다. Discord 서버·봇·계정과의 연동을 요청한 것은 아니다.

## 2. 사용자와 사용 조건

- 1차 대상: Windows에서 Steam Bongo Cat을 실행하고 기존 로비에 참여한 이용자.
- 상대방: 원래 게임 채팅만 사용해도 된다. 별도 프로그램 설치를 요구하지 않는다.
- 배포 목표: 불특정 Bongo Cat 이용자에게 무료로 배포하고 개발자에게 안내한다.
- 현재 검증 조건: Steam 로그인, 게임 실행, 현재 계정의 로비 참여가 모두 있는 상태.
- 게임을 종료한 채 메신저만 사용하는 방식은 별도 연구 대상으로 남긴다.

## 3. 주요 사용자 흐름

### 연결

1. 앱을 실행하면 Steam과 게임의 연결 가능 여부를 확인한다.
2. 현재 참여한 로비를 확인해 채팅 화면 상단에 표시한다.
3. 로비가 없거나 대상이 확인되지 않으면 송신을 비활성화한다.
4. 로비가 바뀌면 새 로비의 대화 화면으로 전환하고, 이전 기록은 별도 기록으로 유지한다.

앱이 사용자 대신 임의의 로비를 만들거나 참여하는 동작은 첫 제품 범위가 아니다. 자동 접속 감지는 아직 구현·검증하지 않았다.

기본 목표는 게임의 로비 변경을 자동으로 따라가는 것이다. 새로고침은 상태 재확인을 위한 보조 동작으로 둔다. 전환 중에는 보내기를 제한하고, 이전 방의 초안·늦게 도착한 메시지가 새 방에 섞이지 않게 한다. 이미 API를 호출한 메시지는 원래 대상의 결과로 남기며 새 방으로 자동 재전송하지 않는다.

### 읽기

1. 다른 이용자가 원래 게임에서 메시지를 보낸다.
2. 앱이 해당 로비의 채팅 이벤트와 본문을 수신한다.
3. 발신자, 본문, 앱의 수신 시각을 목록에 표시한다.
4. 저장된 기록은 로비별로 다시 읽고 검색할 수 있다.

발신자의 Steam 식별자 수신은 확인했다. 닉네임·프로필 이미지 조회와 화면 표시는 구현 후 별도 검증이 필요하다. 발신 시각이 원래 데이터에 들어 있지 않으므로 수신 시각을 발신 시각처럼 표시하지 않는다.

게임에서 특정 사용자를 숨긴 경우 앱에서도 같은 의도를 반영하는 것이 추가 검토 대상이다. 현재 PoC에는 게임의 숨김 상태를 읽는 처리가 없고, 정적 분석에서 확인한 상태는 게임 내부 캐시에 있다. 자동 연동 방법을 확보하기 전에는 숨김이 반영된다고 안내하지 않는다. 목록·검색·알림과 기존 기록·숨김 중 저장의 정책은 [엣지 케이스 문서](edge-cases.md)에서 구분한다.

### 보내기

1. 사용자가 프로그램의 입력창에 문장을 입력한다.
2. 앱은 내 메시지를 즉시 목록에 표시하고 `전송 중` 상태를 붙인다.
3. 현재 계정과 대상 로비를 다시 확인한 뒤 한 번 송신한다.
4. API 결과에 따라 전송 상태를 갱신한다.
5. 자기 메시지가 수신 이벤트로 돌아오면 기존 행에 반영한다. 새 행을 중복 생성하지 않는다.

`전송됨`은 송신 API의 수락을 의미한다. 상대방의 화면 표시나 읽음 확인을 의미하지 않는다. 결과가 불명확한 상황에서는 자동 재전송하지 않는다.

## 4. 화면 구성안

화면 디자인과 UI 프레임워크는 미정이다. 아래는 기능 배치 제안이다.

| 영역 | 내용 | 필요한 동작 |
| --- | --- | --- |
| 연결 상태 | Steam·게임·현재 로비 상태 | 연결 끊김 안내, 송신 가능 여부 표시 |
| 대화 목록 | 현재 로비와 기록이 있는 로비 | 현재 대화·보관 기록 구분, 로비별 전환 |
| 메시지 영역 | 발신자, 본문, 수신 시각, 내 메시지 상태 | 스크롤, 복사, 날짜 구분, 새 메시지 표시 |
| 입력 영역 | 텍스트 입력과 보내기 | 한글 IME, 길이 안내, 전송 중·실패 피드백 |
| 검색 | 저장된 대화의 본문 검색 | 결과 시각과 로비 확인, 해당 메시지로 이동 |
| 기록 설정 | 저장 위치와 보관 상태 | 저장 활성 상태 안내, 내보내기·삭제 정책 제공 |

사용자가 과거 메시지를 읽는 중에는 새 메시지가 와도 화면을 강제로 맨 아래로 이동하지 않는 동작을 제안한다. 기본 단축키, 알림, 보관 기간, 자동 실행은 추가 결정이 필요하다.

## 5. 첫 제품에 포함할 요구사항

| ID | 요구사항 | 인수 기준 |
| --- | --- | --- |
| FR-01 | 현재 로비에 대한 수신 | 다른 계정이 게임에서 보낸 문장이 앱에 정확히 나타남 |
| FR-02 | 기존 게임으로 송신 | 앱에서 보낸 문장이 별도 프로그램을 설치하지 않은 상대방 게임에 나타남 |
| FR-03 | 프로그램 내부 자기 메시지 표시 | 입력한 문장이 즉시 나타나고 자기 수신 이벤트로 중복되지 않음 |
| FR-04 | 로컬 대화 저장 | 앱 재실행 후 이전에 저장한 기록을 조회할 수 있음 |
| FR-05 | 기록 조회와 검색 | 기록이 있는 로비와 수집 기간이 명확하며 검색 결과로 이동할 수 있음 |
| FR-06 | 로비 자동 추적과 경계 유지 | 변경을 감지해 대상을 갱신하고 미호출 송신을 중지함. 이전 요청·초안·수신을 새 방으로 자동 재지정하지 않음 |
| FR-07 | 실패 상태 설명 | Steam 종료·권한 문제·전송 결과 불명·저장 실패를 구분함 |
| FR-08 | 게임 파일 무수정 | 설치·실행·종료 후 게임 파일이 바뀌지 않고 기존 게임 동작이 유지됨 |
| FR-09 | 게임의 개별 사용자 숨김 검토·반영 | 상태 조회 경로와 실제 반영을 검증하고 목록·검색·알림에 일관되게 적용함. 경로 미확보 시 미지원 사실과 범위 재결정을 명시함 |

FR-01·02의 통신 경로는 PoC로 일부 확인했지만, 제품 UI를 포함한 전체 인수 기준을 통과한 것은 아니다.

FR-09는 연동 가능성부터 확인해야 한다. 앱 자체 수동 숨김을 추가한 것만으로 게임 숨김 자동 반영 기준을 통과했다고 기록하지 않는다. 게임의 전체 채팅 끄기·자동 고양이 숨김·언어 필터는 개별 숨김과 별도로 적용 정책을 결정한다.

## 6. 제외한 기능

- 게임 안의 내 캐릭터 위에 별도 말풍선을 표시하는 기능.
- 게임 DLL 수정, 게임 내부 플러그인 설치, 게임 프로세스에 코드 주입.
- 별도 메시지 서버, 클라우드 백업, 여러 기기 동기화.
- 프로그램 실행 전·오프라인 동안의 대화를 복구한다고 보장하는 기능.
- 읽음 표시, 상대방 화면 표시 완료를 자동 판정하는 기능.
- 이미지·첨부파일·음성·Discord 봇 연동.
- 게임에 없는 메시지 수정·삭제 기능을 상대방에게도 적용하는 기능.
- 상자 열기, 탭 수, 보상, 아이템 등 채팅 이외의 게임 동작.

이모지의 데이터 왕복은 시험했으나 게임 화면 지원은 확인하지 않았다. 첫 제품은 일반 텍스트를 기준으로 검증하며 이모지·이모티콘 호환을 홍보하지 않는다.

## 7. 기록의 의미

대화 기록은 이 앱이 실제 수신한 시점부터 수집한 로컬 기록이다. 앱을 종료하거나 수신이 끊어진 구간은 완전한 대화 기록으로 취급하지 않는다. 누락 가능한 구간을 사용자에게 표시하는 방안을 설계한다.

게임에서 말풍선이 사라지더라도 이미 저장한 기록을 다시 볼 수 있는 것이 핵심 가치다. Steam이나 게임이 모든 과거 메시지를 영구 보관한다는 가정에 의존하지 않는다.

## 8. 완료 판정

첫 제품 완료는 화면 시안이나 자체 루프백 성공으로 판정하지 않는다. 순정 게임 환경의 실제 다른 계정과 송수신하고, 재실행 후 기록 복구, 한글 입력, 로비 변경, 오류 상태, 자기 메시지 중복 방지까지 확인해야 한다. 세부 시험은 [개발·검증 계획](roadmap.md)을 따른다.

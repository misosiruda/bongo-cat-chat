# 게임 파일 무수정 프로필·숨김 연동 검증

검증일: 2026-10-13 / Windows / Bongo Cat 빌드 `25723683`.

후속 개발판은 이 PoC를 대조해 새 주소 탐색·구조 검증·숨김 필터·로컬 스프라이트 합성을 구현했다. 사용자 승인은 개발판 실험 연결에 한정한다. [제품 실행 증거](product-validation.md)의 새 탐색·프로필 합성과 이 문서의 과거 수동 숨김 조작 시험은 별개이며 게임 재시작 호환성은 여전히 미검증이다.

## 결론과 증거 구분

**이름과 고양이 외형의 조회 경로를 실제 실행으로 확보했고, 사용자가 게임에서 조작한 같은 이용자의 숨김→해제도 외부 프로그램에서 감지했다.** 게임 파일 수정, DLL 주입, 게임 메모리 쓰기는 하지 않았다. 다만 숨김 경로는 실행 중인 게임의 내부 메모리 구조에 의존하는 실험이며 제품 채택·배포 호환성 검증은 별개다.

표의 이름 조회는 실제 데이터를 읽었다는 뜻이다. 현재 이름을 화면 캡처와 대조했거나 메신저 제품이 완성됐다는 뜻은 아니다. [최초 조회·관찰 요약](evidence/2026-10-13-profile-sync-validation.json)과 [사용자 조작 대조 요약](evidence/2026-10-13-manual-sync-validation.json)을 분리해 보관한다.

최초 약 10분 관찰에서는 다른 이용자의 모자·스킨 갱신만 수신했다. 이후 사용자가 다시 요청한 관찰에서 내 스킨 복원과 같은 이용자의 숨김·해제를 확인했다. 최초 기록의 숨김 전환 미관찰 결과는 이력으로 보존하며, 후속 결과와 혼합하지 않는다.

## 1. 시험 조건과 변경 범위

- 기존 Auto Chest Opener 패치가 설치된 사용자의 현재 게임을 그대로 사용했다. 순정 설치 검증은 아니다.
- 별도 Python 프로세스에서 설치된 `steam_api64.dll`을 로드했다. 로비 생성·가입·이동과 채팅 송신을 하지 않았다.
- 초기 API 시험은 25초씩 두 번 수행했다. 두 번째 시험에서 실제 로비 데이터를 확보했다.
- 프로필 조회 중 수신한 로비 채팅 콜백의 헤더만 처리했으며 채팅 본문은 가져오지 않았다.
- 게임 설정은 외부 프로그램에서 변경하지 않는다. 수동 조작 시험은 사용자가 게임 안에서 수행한 경우에만 그 사실을 기록한다.
- 메모리 접근 권한은 `PROCESS_QUERY_INFORMATION | PROCESS_VM_READ`다. 쓰기·프로세스 중단·원격 스레드·함수 호출·DLL 주입을 사용하지 않았다. 현재 Windows 토큰은 관리자 권한으로 상승하지 않은 상태였다.
- 실행 전·후 `Assembly-CSharp.dll` SHA-256은 `daa0c573859bb42e5f9a45eabf22f9e913fe3a2fe01371579a812b3f96790d07`로 일치했다. 모든 게임 파일의 전후 해시를 비교한 시험은 아니다.
- 원본 스크립트·주소·식별자를 가명 처리한 관찰 기록·추출 이미지는 로컬 `research/private/2026-10-13-profile-validation/`에만 보관한다. 원시 메모리 덤프와 채팅 본문은 저장하지 않았다.

## 2. 이름은 친구 별명까지 같은 규칙으로 읽어야 한다

정적 분석에서 `PlayerNameTag.Start`와 이름 변경 처리기는 `UserData.Nickname`을 사용한다. 이 값은 `GetPlayerNickname`이 비어 있지 않으면 그 값을 쓰고, 없으면 `GetFriendPersonaName`을 쓴다.

```text
같은 Steam 계정 식별자
  → 내가 지정한 Steam 친구 별명 조회
  → 별명이 없으면 해당 이용자의 persona name 조회
  → 게임과 같은 표시 이름
```

로비의 13명 전원에게서 비어 있지 않은 이름을 읽었으며, 이번 표본에서는 별명이 설정된 사람이 없었다. 따라서 별명 우선순위는 실제 게임 코드로 확인했고, 별명 지정 환경의 실행 비교는 아직 하지 않았다.

이름을 사용자 식별 키로 사용하지 않는다. 정보가 아직 도착하지 않으면 임시 표시를 하고 갱신해야 한다. Steam 문서도 로비 진입 직후 이름 정보가 비동기로 도착할 수 있음을 설명한다. [이름 API](https://partner.steamgames.com/doc/api/ISteamFriends#GetFriendPersonaName), [친구 별명 API](https://partner.steamgames.com/doc/api/ISteamFriends#GetPlayerNickname)

## 3. 외형 데이터와 그림을 구분한다

게임의 `CatCosmeticsMultiplayer.OnLobbyDataUpdate`는 멤버의 `hat`·`skin` 값을 읽는다. `LobbyMemberData`는 이 문자열을 정수로 해석하며, 값이 없거나 해석할 수 없으면 `-1`을 사용한다. 외형 변경은 같은 로비 멤버 데이터의 갱신으로 전달된다.

외부 프로세스에서 다음 경로를 확인했다.

1. 현재 로비 구성원을 열거한다.
2. 각 구성원의 `hat`·`skin`을 조회한다.
3. `LoadItemDefinitions` 후 아이템 정의의 이름·슬롯·이미지 주소를 읽는다.
4. 설치된 리소스에서 게임과 같은 이름 규칙으로 실제 스프라이트를 찾는다.

초기 13명은 두 슬롯이 모두 설정돼 있었다. 중복을 제외한 아이템은 25종이었고, 필요한 스킨 4개 프레임과 모자 이미지를 합친 64개 스프라이트를 모두 찾았다. 원본 슬롯값과 조회 실패는 구분해야 하며, 이 표본 성공을 모든 아이템의 보장으로 확대하지 않는다.

Steam의 `icon_url`은 아이템 아이콘이다. 게임 안의 완성된 고양이 프로필을 그대로 반환하는 API는 이번 조사에서 확보하지 않았다. 정지 프로필은 게임이 쓰는 스킨의 두 레이어와 모자를 합성해 구성할 수 있다. 실제로 초기 내 외형에 해당하는 로컬 PNG 샘플을 생성했다. 게임 화면을 캡처한 이미지나 최종 렌더러의 시각 일치 증거는 아니다.

이미지는 설치된 리소스에서 읽기만 했다. 원본 리소스·추출 이미지를 Git 또는 배포물에 포함하지 않았다. 배포 시 이미지 이용·공급 방식은 별도 검토 대상이다. [로비 멤버 데이터](https://partner.steamgames.com/doc/api/ISteamMatchmaking#GetLobbyMemberData), [아이템 정의 조회](https://partner.steamgames.com/doc/api/ISteamInventory#GetItemDefinitionProperty)

## 4. 숨김은 실행 중인 게임의 상태를 직접 읽는다

현재 확인한 코드에서 사용자 숨김은 `PlayerDataCache._playerDataCache`의 `PlayerData.IsHidden` 값이다. 게임의 숨김 UI는 이 값을 변경하고 해당 고양이 오브젝트의 활성 상태를 갱신한다. 이 경로에서 Steam 멤버 데이터 또는 설정 파일로 값을 내보내는 호출은 찾지 못했다.

게임의 별도 IPC도 조사했다. 확인한 IPC는 다른 게임과 탭·버프를 교환하는 용도였으며 사용자별 숨김 목록 조회 기능을 확인하지 못했다. 임의로 IPC에 연결하거나 메시지를 보내지는 않았다. 레지스트리의 `AutoHideCats` 같은 전체 설정이나 인벤토리 아이템 숨김은 사용자별 숨김 목록의 대체값이 아니다.

이번에 확보한 실험 경로:

1. 설치된 Mono 런타임의 메타데이터 접근 코드에서 현재 구조를 확인한다.
2. 외부 프로세스가 읽기 권한만으로 게임 프로세스를 연다.
3. 클래스 이름·정적 필드·런타임 타입을 검증해 실제 정적 사전을 찾는다.
4. 사전의 필드 배치를 메타데이터에서 읽고, 사용자 ID별 `IsHidden`만 가져온다.
5. 읽은 사용자 ID를 현재 Steam 로비 구성원과 대조한다.

첫 조회에서 캐시 12개 항목 모두가 로비의 다른 이용자와 일치했다. 최초 값은 전부 false였다. 주소나 임의 바이트가 일치한다는 이유만으로 성공 처리한 것이 아니라 클래스·필드·키·값 타입과 로비 구성원까지 확인했다. [Windows 읽기 전용 API](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-readprocessmemory)

이 경로는 Steam이 제공하는 공개 숨김 API가 아니다. 현재 빌드에 대한 별도 어댑터가 필요하다. 첫 탐색 세 단계는 약 58초가 걸렸으며, 주소를 찾은 뒤 12개 항목을 읽는 100회 측정의 평균 간격은 약 3.29ms였다. 초기 탐색 비용과 반복 조회 비용을 구분해야 한다. 숫자는 이 PC의 짧은 측정이며 성능 보장이 아니다.

게임 재시작 후 기존 주소를 재사용해서는 안 된다. 빌드·프로세스·타입·필드·사전 구조가 맞지 않거나 읽기에 실패하면 상태를 확인 불가로 처리해야 한다. 조회 실패를 “아무도 숨기지 않음”으로 바꾸면 안 된다. 실험 파서는 잘못된 구조에서 예외로 중단하지만 제품의 알림·검색·기존 기록에 대한 처리 정책과 검증은 아직 남아 있다.

**파일 무수정 조건에서의 기술적 후보는 확보했지만, 이 메모리 읽기 방식을 제품에 채택하기로 확정한 것은 아니다.** 게임 파일 수정·프로세스 주입·메모리 쓰기를 전제로 삼지 않는다.

## 5. 로비 탐색에서 추가로 발견한 제한

첫 실행에서는 `GetFriendGamePlayed(내 계정)`이 Bongo Cat과 다른 App ID를 반환해 기존 탐색기가 로비를 찾지 못했다. 게임 프로세스는 실행 중이었고 Bongo Cat 로비 콜백도 수신됐다.

두 번째 실행에서는 Bongo Cat App ID로 받은 콜백의 로비 번호를 후보로 삼고, 후보가 하나이며 내 계정이 구성원에 포함된 경우에만 읽기 대상으로 삼았다. 이 경로로 13명의 데이터를 읽었다. 로비 가입·이동 호출은 하지 않았다.

이 결과는 현재 로비에서의 읽기 성공이다. 방 이동, 다중 후보, 늦은 콜백, 콜백이 전혀 오지 않는 방에서의 자동 탐색은 미검증이다. 이 휴리스틱을 검증 없이 송신 대상 선택에 사용해서는 안 된다. 제품 로비 추적은 독립 과제로 유지한다.

## 6. 사용자 조작과 후속 관찰 대조

사용자는 새로 10분간 기록하도록 요청한 뒤 외형 변경·복원과 사용자 숨김·해제를 수행했다. 관찰기는 12:24:43 KST에 시작했고 초기화 후 첫 유효 표본은 12:24:45 KST에 기록됐다. 첫 숨김·해제는 기록에 없으므로 성공으로 산입하지 않았다. 관찰 중 같은 이용자의 숨김을 유지하도록 다시 요청했고, 사용자의 숨김 유지·해제 완료 답변과 아래 기록을 대조했다.

요청한 관찰은 **12:34:45 KST에 정상 종료**했다. 초기화 포함 실행 시간은 602.5초였고 초기화 후 600초 관찰을 마쳤다. 변경 시 저장한 프로필 표본 42개와 숨김 표본 3개를 보관했으며 최종 `observer_completed` 값은 true다. 종료 후에도 같은 게임 프로세스가 계속 실행 중임을 확인했고 대상 DLL 해시는 시작 시와 일치했다.

| 외부에서 관찰한 시각 (KST) | 대상과 관찰값 | 판단 |
| --- | --- | --- |
| 12:24:45.439 | 내 스킨 `1155`, 모자 `921` | 앞선 관찰의 스킨 `914`와 다른 상태로 시작. 최초 변경 순간은 미포착 |
| 12:24:48.885 | 내 스킨 `1155 → 914`, 모자 `921` 유지 | 앞선 관찰의 외형으로 복원되는 변경 수신 |
| 12:27:06.558 | 현재 로비의 다른 이용자 한 명, `IsHidden: false → true` | 사용자의 숨김 유지 답변과 일치 |
| 12:27:45.226 | 같은 이용자, `IsHidden: true → false` | 사용자의 같은 이용자 숨김 해제 완료 답변과 일치 |

두 숨김 전환은 동일한 계정 식별자로 연결됐으며 각 전환 당시 현재 로비의 다른 이용자와 일치했다. 공개 요약에는 보고서 내 임시 별칭만 남긴다. 시각은 외부 관찰 시각이며 사용자가 클릭한 시각이 아니므로 실제 동기화 지연을 측정한 결과로 사용하지 않는다.

외형의 변경된 상태와 복원 수신은 확인했지만, 변경 때마다 고양이 이미지를 다시 만들거나 게임 화면과 비교하지 않았다. 숨김도 상태 감지까지 검증했으며 채팅 본문 수신·기록·검색·알림 필터와 결합한 제품 시험은 아니다. 게임 설정 조작은 사용자가 직접 했고 외부 프로그램은 조회만 했다.

관찰 도중 로비 인원은 달라졌지만 캐시는 퇴장한 이용자의 항목을 보유할 수 있었다. 캐시 항목 수를 현재 참여 인원으로 사용하지 않으며, 계정과 현재 로비를 대조해야 한다. 로비 이동·재시작 후 캐시 수명은 여전히 미검증이다.

## 7. 다음 인수 조건

- 감지한 게임의 숨김·해제를 앱의 기존·새 대화, 검색·미리보기·알림·읽지 않은 수에 적용하고 전체 흐름을 시험한다.
- 게임 화면과 이름·고양이 샘플을 비교하고, 지원할 정지·동작·효과 범위를 결정한다.
- 순정 설치, 다른 PC, 재시작·업데이트·접근 거부에서 조회 또는 명시적인 미지원 처리를 확인한다.
- 현재 게임 프로세스와 계정·로비의 대응을 검증하고, 전환 중 이전 데이터를 적용하지 않는다.
- 메모리 읽기 어댑터 채택 여부를 결정한다. 공식 상태 조회 기능이 제공된다면 그 경로를 우선 검토한다.

이름·외형·숨김 조회 실험과 제품 UI·저장·검색 완성은 별도 단계다. 이번 검증으로 T-22·T-26·T-27 전체를 통과한 것으로 표시하지 않는다.
